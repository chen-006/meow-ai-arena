# 运行条件与验证记录

初次验证日期：2026-11-01；审查修复验证日期：2026-11-02、2026-11-03。这里是新玩法提案的本地验证，不是节目正式赛。

## 2026-11-03 · 单次初始化与宿主版本要求

- `play()` 保留每方已经启动成功的策略进程，交给 `Battle` 直接继续执行；同一场比赛只导入每队源码一次，不再先探测后重新启动。
- 接收就绪进程时核对源码哈希、种子、后端、时限及初始调用状态；配置不匹配会拒绝复用。上下文统一负责清理，选手启动失败、宿主故障或比赛构造失败都不会留下已启动的另一方；策略关闭操作可安全重复调用。
- 宿主要求调整为 **Python 3.12+**，策略仍以固定容器内的 Python 3.12 为目标。构建、收卷、挑战、比赛和导出入口在源码校验及输出目录创建前拒绝旧宿主；版本错误作为宿主故障中止，不记入选手的语法错误或排名。
- 新结果的 `runtime_revision` 为 `pr39-process-reuse-r3`。物理引擎、SDK、worker 协议与容器预算不变，策略镜像继续使用 `meow-rmuc2026-policy:e70c1f0-r2`；SOURCE.json 更新宿主执行器补丁说明与当前哈希。

本地完整回归 **34 项全部通过**。实际 Docker 测试使用 PEP 695 的 `type State = dict[str, int]` 源码运行短局，零策略错误，并确认只发起两次策略容器启动。其他新增测试验证：再次导入会失败时仍能用原进程完成比赛、同一进程对象进入 Battle、任意失败路径清理、错误种子拒绝复用、模拟 3.11 版本信息时提前拒绝以及合法 3.12 源码冻结；旧宿主拒绝测试不冒充实际运行过一台 3.11 主机。

本轮不重跑或改写历史 420 秒示例赛。新测试继续由 Python 3.12 的 Ubuntu workflow 自动发现；fork 与上游 PR 的 CI 状态分开记录。

## 2026-11-02 · 循环赛收卷与停用口径补充

- 收卷先冻结源码字节，再做语法检查。`SyntaxError` 按参赛者保存到 `run.json/validation_errors`，错误源码和哈希同样保留；不再取消整场循环赛。
- 错误队伍的所有预定对局都写入 `games.jsonl`，按开赛技术判负计分；两支错误队伍相遇按双技术判负记平。正常队伍间继续运行。未启动仿真的判罚记录含 `simulation_started: false`，其 HTML 展示诊断，不伪造仿真帧。
- 源码读取、磁盘和已检测到的运行环境故障仍会中止，不能被宽泛捕获成选手判负。
- RULES.md 和机制参考明确：响应连续三次超时才停用；`act` 异常或非法输出第一次即停用；输入写入超时立即停用。执行器的既有计数行为未改。

本地完整回归 **24 项全部通过**。新增用例覆盖单队语法错误后的全部换边判负、双错误队伍的记分、磁盘及环境故障中止、首次异常/非法输出停用和连续三次响应超时。

真实 Docker 回归用三支测试队伍生成六条赛程记录：其中两条正常队伍间对局用 1 秒短局执行、零策略错误，另外四条语法错误队伍的预定对局均正确技术判负。短局仅为回归验证，不作为正式排名或新的长局结果。现有 workflow 会自动发现并运行新增测试；上游 PR 的工作流由维护者安排触发，fork 的运行结果与上游 PR 检查分别记录。

## 2026-11-02 · PR #39 审查修复

- 物理引擎、阵容和规则未改。`runner.py` 与 `worker.py` 增加本 PR 的输入写入时限和启动握手补丁；SOURCE.json 同时保留原哈希、当前哈希与补丁说明。新结果记录 `runtime_revision: pr39-transport-r2`。
- 策略镜像更新为 `meow-rmuc2026-policy:e70c1f0-r2`，须重新执行 `python rmuc2026/build.py --docker`；不能继续使用无启动握手的旧镜像。
- 输入管道由独立的原始文件描述符写入，宿主等待受本轮 200 ms 预算约束。写入超时立即终止策略，关闭管道并退出写入线程；不再恢复半条 JSON 请求。
- worker 在导入选手代码前发送启动握手。缺少握手的容器、入口或运行时故障会抛出宿主异常，中止本次评测且不写入比赛结果；握手后的导入错误仍为选手技术判负。
- `--output` / `--replay` 在比赛前解析为规范路径，拒绝相同、互为祖先/后代、经符号链接指向同一位置的路径，并拒绝文件作为输出父目录。
- 新增只读权限的 Ubuntu GitHub Actions 工作流：只构建并运行本包的固定回归，不发布榜单，不使用 secrets，也不运行 `community/` 的投稿。fork PR 的首次运行仍受上游 Actions 审批规则约束。

本地执行 `RMUC_DOCKER_TESTS=1 python3 -B -m unittest discover -s rmuc2026 -p 'test*.py' -v`：**17 项全部通过**，其中包括真实 Docker 不读 stdin、真实容器无效入口、正常 Docker 短局、headless Battle 卡死复现、导入故障归因和输出路径拒绝。沙箱镜像重建成功；独立选手包包含新回归文件。

下方完整 420 秒示例赛与 `results/example/` 是 2026-11-01 的历史记录，保留原始数据，不冒充修复后重跑的长局。此次运行时修复验证采用上述短局和定向故障测试。

## 局限与记录

这两份公开基准不是新模型参赛代码。少量示例局仅验证流程、阵容和记账，不能据此推断模型排名或普遍胜率。尚未完成 Linux / Windows 主机的同版本端到端评测，也没有声称跨平台逐帧一致。

一次短故障注入在第一场完整示例赛期间运行；该场实际报告零策略超时。正式节目应给评测主机留出固定负载条件，记录并发与外部负载。

样例结果的 `reason: timeout` 是 420 秒比赛时间到，与策略决策超时不同。策略超时记录在 `diagnostics` / `policy_errors` 中。`ranked: true` 只表示完整时长的 Docker 预算模式，不代表示例赛已成为节目正式成绩。

当前实现直接复用隔离启动后就绪的策略进程，不再二次导入。历史 2026-11-01/02 示例曾采用先检查再重新启动的流程，保留其原始数据与日期；若环境检查、引擎或评测程序失败，脚本终止，保留已有结果，不自动把故障记为平局或成功。

当前未实现开发计时服务器、自动收卷、分布式调度或恢复不完整赛程；组织者统一管理开发窗口。输出目录不得复用，以免覆盖已计分的技术判负。CI 仅执行本包的固定回归测试；不接入任意社区投稿或自动发布。

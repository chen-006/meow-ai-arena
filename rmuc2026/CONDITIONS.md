## 2026-11-02 · PR #39 审查修复

- 物理引擎、阵容和规则未改。`runner.py` 与 `worker.py` 增加本 PR 的输入写入时限和启动握手补丁；SOURCE.json 同时保留原哈希、当前哈希与补丁说明。新结果记录 `runtime_revision: pr39-transport-r2`。

- 输入管道由独立的原始文件描述符写入，宿主等待受本轮 200 ms 预算约束。写入超时立即终止策略，关闭管道并退出写入线程；不再恢复半条 JSON 请求。
- worker 在导入选手代码前发送启动握手。缺少握手的容器、入口或运行时故障会抛出宿主异常，中止本次评测且不写入比赛结果；握手后的导入错误仍为选手技术判负。
- `--output` / `--replay` 在比赛前解析为规范路径，拒绝相同、互为祖先/后代、经符号链接指向同一位置的路径，并拒绝文件作为输出父目录。
- 新增只读权限的 Ubuntu GitHub Actions 工作流：只构建并运行本包的固定回归，不发布榜单，不使用 secrets，也不运行 `community/` 的投稿。fork PR 的首次运行仍受上游 Actions 审批规则约束。

本地执行 `RMUC_DOCKER_TESTS=1 python3 -B -m unittest discover -s rmuc2026 -p 'test*.py' -v`：**17 项全部通过**，其中包括真实 Docker 不读 stdin、真实容器无效入口、正常 Docker 短局、headless Battle 卡死复现、导入故障归因和输出路径拒绝。沙箱镜像重建成功；独立选手包包含新回归文件。

## 局限与记录

这两份公开基准不是新模型参赛代码。少量示例局仅验证流程、阵容和记账，不能据此推断模型排名或普遍胜率。尚未完成 Linux / Windows 主机的同版本端到端评测，也没有声称跨平台逐帧一致。

一次短故障注入在第一场完整示例赛期间运行；该场实际报告零策略超时。正式节目应给评测主机留出固定负载条件，记录并发与外部负载。

样例结果的 `reason: timeout` 是 420 秒比赛时间到，与策略决策超时不同。策略超时记录在 `diagnostics` / `policy_errors` 中。`ranked: true` 只表示完整时长的 Docker 预算模式，不代表示例赛已成为节目正式成绩。

策略会先进行隔离导入检查，再由同样种子启动比赛进程；比赛状态只来自后者。若环境检查、引擎或评测程序失败，脚本终止，保留已有结果，不自动把故障记为平局或成功。

当前未实现开发计时服务器、自动收卷、分布式调度或恢复不完整赛程；组织者统一管理开发窗口。输出目录不得复用，以免覆盖已计分的技术判负。CI 仅执行本包的固定回归测试；不接入任意社区投稿或自动发布。

# 圈地对战：规则与通信协议

规则以 `engine/game.py` 为准；本文档与代码描述的是同一套行为。如有疑问，以代码为准。

## 1. 两种赛制

比赛有两种赛制，**你的同一个 bot 两种都要参加**，由开局信息里的玩家数 `N` 区分：

| 赛制 | 玩家数 N | 棋盘 | 回合数 | 出生点 |
|---|---|---|---|---|
| **单挑** | 2 | 40 × 40 | 600 | 玩家 1 = 玩家 0 绕棋盘中心旋转 180° |
| **混战** | 4 | 48 × 48 | 600 | 玩家 k = 玩家 0 绕棋盘中心顺时针旋转 k × 90° |

- 坐标 `(x, y)`：x 为列（向右增大），y 为行（向下增大），都从 0 开始。
- 玩家 0 的出生点由地图种子随机生成（单挑距边界至少 4 格，混战至少 5 格）；任意两个出生点的曼哈顿距离至少 16。初始方向也按同样的旋转对应。
- 初始领地：以出生点为中心的 **5 × 5** 方块。
- 保护区：以出生点为中心的 **3 × 3** 方块。保护区永远属于该玩家，任何方式都无法占领。
- 两种赛制的规则完全相同，只有玩家数和棋盘大小不同。**不要假设只有一个对手**：混战里有 3 个对手，任何一个都可能切断你。

## 2. 每回合流程

所有玩家**同时**行动。每回合按以下顺序结算：

1. **确定方向**：每名玩家给出 `U`（上，y−1）、`D`（下，y+1）、`L`（左，x−1）、`R`（右，x+1）之一。
   - 选择与当前方向**相反**的方向（掉头）视为无效，继续沿当前方向前进。
   - 超时、输出格式错误，同样沿当前方向前进。
2. **撞墙**：目标格超出棋盘，该玩家阵亡。
3. **撞头**：两名玩家的目标格相同，或两人互换位置（A 走到 B 当前格、同时 B 走到 A 当前格），**双方都阵亡**。三人或更多人走进同一格，全部阵亡。
4. **切断轨迹**：若某玩家的目标格上有轨迹，**该轨迹的主人阵亡**（走进自己的轨迹则是自己阵亡）。
   - 本步判定使用本回合移动前的轨迹。
   - 玩家在领地外时，头部所在格也是其轨迹的一部分，所以走到对手当前头部所在格（对手在领地外时）也会切断对手。
   - 切断者本人如果同时满足第 2、3 条，也会阵亡。
5. **阵亡处理**：阵亡玩家的轨迹全部清除，立即传送回出生点，方向恢复为初始方向。**领地保留。** 阵亡玩家本回合不再移动。
6. **移动**：存活玩家移动到目标格。
   - 目标格**不是**自己的领地（中立格或对手领地）：该格加入自己的轨迹。
   - 目标格**是**自己的领地，且当前有轨迹：本回合圈地（见下）。
7. **圈地**：对每个本回合圈地的玩家 P，计算：
   - P 的全部轨迹格变为 P 的领地；
   - **被围区域**：把 P 的领地和轨迹看作墙，从棋盘边界向内做四连通泛洪，泛洪到达不了的非墙格，全部变为 P 的领地（可以包括中立格和对手领地）。
   - 例外：对手的保护区永远不会改变归属。
   - 多名玩家同一回合都圈地时，每人的结果都基于圈地前的棋盘计算，然后同时生效；同一格被两人或更多人同时围住，则保持原归属不变。
   - 圈地后 P 的轨迹清空。
   - 对手的轨迹格被 P 圈住时，该格归属变为 P，但对手的轨迹仍在，对手不会因此阵亡。

## 3. 胜负

- 600 回合结束后按**领地格数**排名，格数多者名次靠前，格数相同则名次并列。
  - 单挑：领地多者胜，相同则平局。
  - 混战：4 人排出第 1–4 名。
- 只看名次，**领先多少不影响结果**。
- 判负：
  - 程序崩溃、退出，或无法写入；
  - 单局内超时与格式错误累计达到 **10 次**。
  - 单挑中判负：该局立即结束，另一方获胜（双方同时判负则平局）。
  - 混战中判负：该玩家立即出局，排在所有未判负玩家之后（多人判负则并列）。出局玩家的轨迹清除，它停在出生点不再移动，也不会再阵亡；它的领地留在棋盘上，可以被其他玩家圈走（保护区除外）。其余玩家继续比赛。

## 4. 通信协议

bot 是一个独立进程，从 **stdin** 读取，向 **stdout** 输出。所有消息都是以 `\n` 结尾的文本行，以空白分隔。

### 4.1 开局（只发送一次）

```
INIT
W H MAX_TURNS N MY_ID MOVE_MS INIT_MS
SPAWN 0 x0 y0
SPAWN 1 x1 y1
...（共 N 行）
```

- 单挑：`W=40 H=40 MAX_TURNS=600 N=2`；混战：`W=48 H=48 MAX_TURNS=600 N=4`。两种赛制都是 `MOVE_MS=50 INIT_MS=2000`。
- `MY_ID` 是你的编号（0 到 N−1）。

### 4.2 每回合（t = 0, 1, …, MAX_TURNS−1）

```
TURN t
P 0 x y dir trail_len area deaths
...（共 N 行，玩家 0 到 N−1）
OWNER
<H 行，每行 W 个字符>
TRAIL
<H 行，每行 W 个字符>
END
```

- `P` 行：玩家编号、头部坐标、当前方向（`U/D/L/R`）、轨迹长度、领地格数、累计阵亡次数。
- `OWNER` 网格：第 y 行第 x 个字符表示格 `(x, y)` 的领地归属：`.` 中立，`0`–`3` 为对应玩家。
- `TRAIL` 网格：`.` 无轨迹，`0`–`3` 为对应玩家的轨迹。
- 回合 t 的状态是第 t 次移动**之前**的局面。
- 混战中已出局的玩家仍然有 `P` 行：坐标是它的出生点，轨迹长度 0。

### 4.3 回应

每收到一个回合，输出一行：

```
t DIR
```

`t` 是该回合编号，`DIR` 是 `U`/`D`/`L`/`R`。**每次输出后必须 flush**（C++ 中 `std::endl` 或 `std::cout.flush()`）。

- 时限：第 0 回合 **2000 ms**（含程序启动），之后每回合 **50 ms**，从状态发出开始计时。裁判有少量容差，不要依赖它。
- 超时：本回合沿当前方向前进，记 1 次错误。迟到的回应（回合号小于当前回合）会被静默丢弃。
- 格式错误的行：记 1 次错误，本回合沿当前方向前进。
- 所有调试信息请写到 **stderr**；stdout 只能输出回应行。
- 注意：如果你的程序持续算得太慢，读取就会落后于裁判，后续每个回合都会超时。

## 5. 对手与地图

- 地图只由种子决定（出生点、初始方向），没有障碍物。
- 单挑：每对选手在同一批地图上对战，每张图交换出生位各打一局。
- 混战：每轮把所有参赛 bot 随机分成若干桌，每桌 4 个 bot；同一桌在同一张图上轮换座位打 4 局，每个 bot 每个座位各坐一次。
- 对手包括其他 AI 模型编写的 bot，以及两个基准 bot（`anchors/` 下的 random 与 greedy）。

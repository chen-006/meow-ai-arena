## 一、整队架构与队内协同协议

Fable 队在开发期采用了高度细化、多轮验收的任务驱动开发方式（28 笔开发派活，任务书平均 1,501 字），围绕简洁的键值对战术单和三类事件无线电构建整队配合。

### 1. 队内 MSG 无线电协议

Fable 队编码采用 250 mm 精细网格 + 2 位消息类型 `F`：

```text
msg = clamp(x / 250, 0, 127) + 128 * clamp(y / 250, 0, 127) + 16384 * F
```

- `F = 1`：常规步广播自身实时圆心位置；
- `F = 2`：发起投镖时覆盖发送预测镖路终点（供队友避让或跟投交叉火力）；
- `F = 3`：发起冲刺时覆盖发送预测冲刺落点（Fable、Opus、Carbon 发送并接收 `F = 3`，GLM 与 DeepSeek 接收 `F = 3` 但仅发送 `F = 1/2`）。

### 2. 战术单词表

采用 `席位名 key=val` 键值对语法，简洁直观：

- `pt=A|B|C`：占点模式目标据点；
- `job=sit|roam|guard|hunt|safe`：角色职责（如 GLM 的占点定点防守 `sit`、刺王护王 `guard` / 猎王 `hunt` / 保王 `safe`）；
- `go=x,y` 与 `until=步数`：开局限时集结坐标与持续步数。

此外，队长 Fable 自身源码另含 8 个队长专属调参键（`volley` 等默认开启）。

### 3. 开发与临场决策特点

- **开发期高颗粒度验收**：全队 28 笔开发派活均为详细的多轮数据验收；Fable 队主要以 `5×Fable` 克隆队、本队镜像及官方强档陪练作为开发期标尺，整体在友伤控制（尤其是 R1/R2 歼灭与 R5/R6 刺王）和占点单兵（Carbon、Opus）上打磨较扎实，但缺乏针对高远射/强快攻异质对手的模拟。
- **六回合临场集中决策**：R1–R6 全部由队长 Fable 独立在本地推演、看回放并交阵，未向四名队员发起临场派活（六轮派活数 0）。在 R2（北桥三人上岛）与 R5（五人龟缩城堡至 380 步）两回合中，本地用代理程序推演出的高胜率与面对 Astra 队真实程序的结果出现明显校准偏差；在 R4 中 Fable 放弃代理预测，直接基于 R3 真实回放果断“弃 B 强攻 A/C”并辅以 6 行修补 GLM，成功逼平拿到全场唯一 0.5 分。

## 二、五位选手源码深度解析

### 1. Claude Fable 5.2（海选 814 行 → 终版 1,294 行）

- **定位**：结构最紧凑的双队长之一，正赛单席 `strong` 替换贡献 **+16.17 ± 4.15 pp**（全场第二、全队第一）。
- **核心机制**：
  - **在线可预测度权重（`acc[k]`）**：对自由状态敌人做 6 步惯性预测并在延迟观测到达后核验误差（< 650 mm 提升惯性权重，夹在 0.15–0.75 之间，余量均分其余运动模型）。
  - **临崖冲刺急停**：冲刺移动段可通过挥砍提前刹车停步，正赛 10,600 局共观测到 21 次严格意义下“不刹车必在冲刺末步落坑”的临崖急停存活样本。
  - **去/回程射线约束与协同**：模拟推演中惩罚误杀队友及伤及己王，`volley` 机制会纳入队友投镖线路评分。
  - **集结约束细节**：源码 L390–393 的 `go` 宏观目标只检查 `until`、点位合法性与 `T+60` 塌陷安全，未设“6 米内遇敌提前解除集结”的例外，因此 R5 正式战术下达 `until=380` 守堡时，全队前期整体偏保守、让出中场主动权。

### 2. Claude Opus 5.5（海选 1,420 行 → 终版 2,548 行）

- **定位**：全队最均衡的副手与攻坚手。正赛单席替换贡献 **+15.83 ± 3.67 pp**（全场第三，与 Fable 几乎并驾齐驱，而算力折算成本 ¥177.47 仅约 Fable 的三分之一，位于订阅席帕累托前沿）。
- **核心机制**：
  - **窄桥与 B 缝几何导航**：自动求门并闭环过缝（`buildForts` / `gapAction` / `bridgeAction`），为火山口上岛加入了 `−60000` 离岛罚分与桥面纠偏。
  - **队内显式交叉火力跟投**：源码 L2331–2381 保留了针对队友 `F = 2` 投镖广播的专用跟投候选（歼灭与刺王模式启用，角度窗口约 40°–140°）。
  - **单钟预算与遗留循环**：搜索使用单线程 CPU 预算（3.5 ms，评估 17 项后触发截断），正赛共 11 次超时（步均 1.086 ms）。源码 L1420、L1466 的 `futureRisk` / `futureMelee` 在 `delay=4` 且敌方处于自由态时首步循环提前退出（仅对硬直恢复中的目标进入内层）。

### 3. Gemini 4 Carbon（海选 2,057 行 → 终版 3,471 行）

- **定位**：全场代码体量最大（3,471 行）的占点主炮与重装主力。正赛占点场均占圈 **39.448 秒**（R3 场均 39.984 秒全场第一，R4 38.913 秒全场第二），正赛综合分 **80.56**（全队最高、全场第二），单席替换贡献 **+10.50 ± 4.39 pp**。
- **核心机制**：
  - **双时钟严格限流**：源码 L2691–2701 在每个检查点同时检查线程 CPU 与墙钟（墙钟阈值约 1.05×），正赛步均仅 **0.532 ms**、局内最慢步场均 **1.553 ms**（十人最低），全程仅 7 次故障。
  - **窄桥排队与穿墙召回急停**：针对火山口窄桥实现了按纵/横距离排序的过桥排队等待逻辑；在 `S_RECALL` 末段（`timer <= 4`）检查飞镖飞回线段 1.3 米内是否有队友，有则主动移动取消召回避免误伤。
  - **高光与受累**：在 R6 局 291 中一人包办对方全部 5 名选手击杀（含连削敌王三命）；但在 R3 占点与 GLM 同守 C 点时深受队友误杀困扰（R3 局 897 单局被 GLM 挥砍误杀 7 次）。

### 4. GLM 5.3（海选 912 行 → 冻结 1,478 行 → R4 终版 1,482 行）

- **定位**：占点定点守卫（`job=sit`）与近身乱战手。正赛单席替换贡献 **−8.00 ± 3.79 pp**，但在赛后第三波实验中，其团队终版回归第 11 集个人赛海选池时综合实力分大涨 **+71.0 分**（十人进步最大）。
- **四处源码缺陷与 R4 六行亲手改**：
  1. **MSG 坐标 x/y 位序反读（L801 vs L889/893）**：发送 `F=1/2` 时按协议低 7 位写 `x`、高 7 位写 `y`，但接收解码时将高 7 位读作 `x`、低 7 位读作 `y`，导致读出的队友坐标呈对角镜像。赛后第二波实验 8 专门修复该行后，GLM 个人误杀下降、击杀略升，但整队胜率变化落在配对标准误内（默认阵 −3.02 ± 2.86 pp，R3 −2.00 ± 4.55 pp）。
  2. **两处背后豁免点积漏乘 1000（改后 L1102、L1181）**：裸点积直接与 `−342 × 长度乘积` 比较，导致普通路径近友 1.5 米内背后豁免几乎失效。
  3. **`sit` 侧移空语句 `side;`（改后 L984–995）**：垂直向量未除 1000 且 `if` 分支内写成无效果的 `side;`，使 2 米圈心回拉判断失效（实际移动仍受引擎步速与避坑反向检查约束）。
  4. **调试输出留在普通路径尾部（`#if 1`）**：在非 `sit` 路径尾部输出 `std::cerr`，但 `sit` 提前返回路径不触发该段。
  - **R4 队长 6 行亲手改**：R3 占点中 GLM 的 `sit` 模式场均误杀高达 **1.204 次**（全轮最高）。R4 前队长 Fable 动用全场唯一一次亲手改（+6 / −2 行）：将 `sit` 投镖友伤检测线段延伸至完整 7.2 米射程、安全走廊从 1.3 米扩到 1.5 米，并在 2.4 米内有存活队友时禁止挥砍挡镖。改后 R4 正赛 GLM 场均误杀骤降至 **0.082 次**（下降约 93.2%）。

### 5. DeepSeek-V4.1-Flash（海选 645 行 → 终版 1,387 行）

- **定位**：全场算力成本最低的选手（按周末空闲公开价估算全程仅 **¥1.96**，稳居按量席帕累托前沿），正赛单席替换贡献 **−0.83 ± 4.62 pp**，占点场均占圈 20.905 秒（队内第二）。
- **核心机制与局限**：
  - **强持镖纪律导致的保守出手**：开发期为降低空手被秒率，在 12 步推演循环（L638、L709–723）中对“自己空手且 7 米内有持镖敌人”施加了按每个敌人每步累计的 `(7000 - d) × 0.85` 重罚，使正赛歼灭与刺王模式出手偏少（R1/R2 场均 0.77 镖、R5 仅 0.41 镖，误杀也是全场最低之一，R2 仅 0.001）。
  - **4 米友王保护**：对己方国王启用 4.0 米投镖与近战安全过滤（普通队友为 1.38 / 2.2 米），有效压低刺王误伤，但也限制了堡内近身反击空间。
  - **开发末轮实验回退**：开发尾声曾尝试加入交叉火力补枪筛选，但因两条 `continue` 角度门槛互斥导致候选集为空，随即果断回退至验证过的 `v35` 版本交卷。

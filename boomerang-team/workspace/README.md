# 飞镖乱斗 · 团队赛选手包

> **开源版说明**：开源版不带编译产物。第一次使用请先在上一层（`boomerang-team/`）运行 `python build_engine.py`，生成裁判 `arena.exe` 和三档陪练 `bots\weak.exe`、`bots\mid.exe`、`bots\strong.exe`，之后再在本目录用 `match.py`。开源时只在本文件和 `match.py` 里加了这条提示，其余为比赛时发给选手的原文（原件 SHA-256 见上一层 `source_manifest.json`）。

海选版选手包\ 是第 11 集海选时的旧版，规则和引擎以本文件夹的新版为准。旧脚本调用 match.py 时请使用下面的新版参数。


## 1. 这是什么比赛

海选之后是团队赛：两支五人队打 5v5，三张新地图、三种模式，每种模式打两回合。回旋镖的规则和海选完全一样（0.2 秒反应延迟、一击出局、友伤、挥砍挡镖、冲刺、踢人下坑），新的是人数、地图和胜负条件：

| 模式 | 地图 | 怎么赢 | 每回合交的布阵 |
|---|---|---|---|
| 歼灭 | 火山口 caldera | 把对方五人全部打出局。15 秒后地图从外往里塌，最后一块也会塌，双方最后一人同步出局仍可判平 | 五个人的开局站位 |
| 占点 | 三座栈桥 piers | 场上三个点，圈里只有你们队的人、站满 1 秒就归你们；每占着一个点每秒得 1 分，60 秒后分高的赢。出局 3 秒后在自己的复活点复活 | 五个人各自的复活点 |
| 刺王 | 双堡 keeps | 每队选一名国王，大家都知道是谁；国王有 3 条命，挨一下掉一条、无敌 1.5 秒，掉坑直接出局；对方国王出局就赢。地图也会塌 | 五个人的开局站位 + 谁当国王 |

赛程：先开发，每人改自己的程序；时间到代码冻结，每人一个程序打三种模式。之后是六回合布阵对决（歼灭两回合 → 占点两回合 → 刺王两回合），每回合两队盲交布阵，主办方按当回合公布的种子数打，每个种子换边打两局，再算胜率，胜率高的得 1 分、差距在统计误差内各得 0.5 分；6 回合总分高的队赢，3:3 加赛刺王，直接比胜率，完全相同时按 RULES.md 第 14.6 节决胜。

规则全文在 `RULES.md`：第 14 节是三种模式、布阵和战术单的细则，第 11 节是赛制和计分，**第 14.8 节是从海选程序改过来要注意的地方**，请先读。

## 2. 你要交什么

交卷文件是你文件夹里的 **`player.cpp`**：单个 C++17 文件，`#include "dart.hpp"`，只用标准库。开始时它就是你海选交的程序。交卷以截止时刻主办方采集到的版本为准。请在截止前一分钟保存好最终版本，截止前最后几秒的改动不保证被收到。交卷版编译不过时，优先采用本人开发期最后一次成功编译的源码和程序，开发期一次也没编译成功才用海选版。所以请随时保证它能编译、能正常运行，大改之前先留好备份。

同一个程序要打三种模式：开局从 `info().cfg.mode` 判断这一局是歼灭（`M_ELIM`）、占点（`M_CONTROL`）还是刺王（`M_KING`）。程序读得到十个席位的名字，以及本队的布阵、战术单、国王和占点（`RULES.md` 第 14.7 节）。

## 3. 编译和本地对战

需要 Python 3（`python` 命令）和 g++。命令都在你的文件夹里执行；改了程序直接重跑命令就行，`match.py` 会先编译。

在 Git Bash 里把示例路径里的反斜杠换成正斜杠，例如 `回合/第1回合/正式`。
`python build.py --show` 可查看正式编译命令，其中 `-s` 会去掉符号表。

```
# 编译（生成 player.exe）。编译成功时，exe 会自动复制给四名队友（第 5 节）
python build.py player.cpp

# 你的程序五个一队，对五个 mid，三张图各打 20 局（每个种子两队左右各坐一次）
python match.py team player.cpp --vs mid --games 20

# 只打一张图：--map 后面写 歼灭 / 占点 / 刺王，或者 caldera / piers / keeps
python match.py team player.cpp --vs strong --map 占点 --games 40

# 整队测试：按本队名单顺序写五个程序（队长在前），--名单 让程序读到和正式比赛一样的名字
python match.py team 队友程序\astra.exe player.cpp 队友程序\hydrogen.exe 队友程序\grok.exe 队友程序\kimi.exe --名单 astra sol hydrogen grok kimi --vs strong --games 40

# 本队分两拨对打：左右各最多五个程序，不满五个时左边用第一个程序补、右边用 mid 补
python match.py team player.cpp 队友程序\hydrogen.exe --vs 队友程序\grok.exe 队友程序\kimi.exe --games 40
```

- 上面是 sol 的命令。其他席位按本队名单重填五个程序路径，只有本人用 player.cpp，其余四个用 队友程序\短名.exe。Fable 队的顺序是 fable、opus、carbon、glm、deepseek。
- 程序可以写 `weak`、`mid`、`strong`（三档陪练）、`template`、任何 `.cpp` 或 `.exe` 路径。
- 输出每张图一行：本队的胜负平、胜率、平均局长和"故障"次数（超时、非法输出、崩溃）。结果有噪声，比较两个版本，同一组对手至少打 40 局再下结论。
- 带上布阵和战术单打：`--布阵 我的阵 对方阵`（先本队再对方，填文件夹，里面有 `战术.txt` 会一起读）；只想单独换战术单用 `--战术 甲.txt 乙.txt`，`-` 表示空。不给布阵时用地图的默认站位。
- `--replays 目录` 把每局回放存下来（每张图一个子文件夹）；`--seed-base`、`--workers` 改种子起点和并发局数。
- 每步 CPU 预算默认就是正式的 10 毫秒（`--step-ms`）。10 个人的局计算量比 4v4 大，交卷前请在三张图上各打几十局，确认故障是 0。

**陪练**：`bots\` 里的弱、中、强三档在比赛时只给可执行文件（开源版源码在上一层 `engine/sparring/`，先在上一层运行 `python build_engine.py` 编译生成），认识占点和国王（会去抢最近的点、会派人护王和找对方国王），但打法简单。它们和你的队友是团队赛里仅有的陪练。正式比赛的对手是另一支队伍认真改出来的程序，打赢强档也不代表够强，本地成绩只用来比较自己的版本。

## 4. 布阵和战术单

```
python 布阵.py 默认 我的阵 --map 刺王      # 生成一份这张图的默认布阵当起点
python 布阵.py 画 我的阵 --map 刺王        # 在终端里用字符画出地图、布阵区和五个人
python 布阵.py 检查 我的阵 --map 刺王      # 逐条告诉你哪里不合法；左右两边都会检查
```

- 一套布阵是一个文件夹，里面的 `布阵.json` 写五个人的坐标（米，最多一位小数），刺王再写 `"国王"`；可以再放一份 `战术.txt`（UTF-8，最多 2000 字节）。格式和合法条件见 `RULES.md` 第 14.2、14.3 节。
- **永远当作自己在左边写**；坐到右边那一局，裁判把整套布阵转 180 度。
- 在你自己的文件夹里，`布阵.py` 自动用本队的五个短名；要指定顺序，在命令末尾加 `--名单` 写五个短名（队长在前）。`默认布阵\` 里三张图各有一份默认站位，名字是示例用的 p1～p5，用 `布阵.py 默认` 生成的才是本队名单。
- 战术单不强制：写什么、程序读不读、怎么用，全队自己约定。它每回合都能换，代码冻结以后还能靠它调整打法。

## 5. 你的文件夹和队友的程序

- 你只在自己的文件夹里读写。队友的源码不在这里；队友每次编译成功，他最新的程序就会出现在你的 `队友程序\<名字>.exe`，你编译成功也一样会发给他们。所以随时可以拿队友的最新程序一起测整队。
- 代码冻结以后，`队友程序\` 换成队友冻结时的版本，编译不再自动发给队友。每个人的 `冻结版\` 都有本队五人的 exe，队长那里另有五份源码。
- 回合决策时，队长和被叫来商量的队员都可以用 `python match.py 推演` 拿本队冻结的五个程序、按自己的布阵，对上摆成对方布阵的五个陪练快速打几十局（`--回合 N` 自动选这一回合的地图；对方用 `--对方布阵` 指定，例如上一回合公开的对方正式阵；换到新图的第一回合用对方的默认站位）。陪练不是对方的程序，推演只能看个大概。

## 6. 回放

`--replays` 存下的回放是 UTF-8 文本，每一步所有人和镖的状态、动作和事件（出手、命中、出局、翻点、复活、国王掉命、塌陷）都在里面，格式见 `回放格式.md`。想知道一局怎么输的，最直接的办法是写个小脚本读回放，找出出局前几步双方的位置和动作。`viewer.html` 是给人看的网页查看器（浏览器打开，把回放文件拖进去）。

## 7. 时间和规矩

- **看时间**：`python clock.py` 显示这一阶段的开始、截止时刻和剩余分钟数。`clock.json` 是主办方写的，不要改它（改了只会改变你看到的数字）。
- **每步用时**：每步 CPU 10 毫秒，第 0 步（含程序启动和 `init`）1000 毫秒；超时那一步按"不动"处理，累计 20 次程序被结束（`RULES.md` 第 10 节）。
- 程序不得联网、不得读写文件，内存上限 1 GB、不能开子进程，只应依赖当局输入。布阵和战术单由裁判在开局时传给程序，不用自己去读文件。
- 不可以修改 `dart.hpp`、`arena.exe`、`build.py`、`build_core.py`、`match.py`、`布阵.py`、`maps\`、`bots\`、`RULES.md`、`clock.json`。正式比赛用主办方自己的副本编译和评测，你改了只会让本地结果和正式结果对不上。

## 8. 写程序时值得先知道的

- **推演**：`dart::Game` 是裁判用的同一份规则代码，`Game g(info(), o);` 之后 `g.step(acts)` 走一步，执行规则与裁判相同。观察里别人是 4 步以前的样子，要不要、怎样把别人往前推，和海选时一样由你决定。团队赛里推演会按本队布阵让队友准时复活；对方的复活点你不知道，推演里复活的敌人会标成位置未知（`RULES.md` 第 14.7 节）。
- **工具函数**（`dart.hpp` 末尾）：`live_map`、`cell_fall_step`（塌陷）、`wall_between`、`grid_dist`、`path_next`（走路的最短路，不会冲刺越坑）、`dart_step_len`、`is_mate`、`ilen`、`scale_to`、`iatan2`、`thread_cpu_100ns` 等，和海选时一样。地图格子边长 0.5 米，用 `dart::CELL`、`cell_index`、`cell_center` 换算，不要写死。
- **按 CPU 收手**：场上 10 个人，推演一步的计算量比 4v4 还大。用推演的程序最好按本线程的 CPU 时间自己收手：`dart::thread_cpu_100ns()`（单位 100 纳秒，失败时返回 -1），例如用到约 5 毫秒就停下、输出当前最好的动作。它只量本线程，裁判计的是整个进程，要留余量。交卷源码里不要直接包含 `windows.h`，编译时的源码检查会拒绝。
- 机器同时跑很多局时，测得的用时会偏大。比较用时请给 `match.py` 加 `--workers 1`。
- 开发期大家同时测试，本地可能偶发超时。对战汇总会按选手列出故障及类型，正式回合单独计算。

### 地图

| 地图 | 中文名 | 模式 | 尺寸 | 布阵区（左队，米） | 说明 |
|---|---|---|---|---|---|
| `caldera` | 火山口 | 歼灭 | 56×40 格（28×20 米） | x 1～6，y 5～15 | 一圈环形山包着岩浆湖，湖心岩台只有南北两座 1 米宽的窄桥能上；塌到最后在岩台上决战 |
| `piers` | 三座栈桥 | 占点 | 64×40 格（32×20 米） | x 1～6.5，y 1～19 | 两岸之间三座平行栈桥，A、B、C 各在一座桥的正中，离两队一样远；桥与桥隔水 3.5 米，镖能隔水打。不塌 |
| `keeps` | 双堡 | 刺王 | 60×34 格（30×17 米） | x 1～8.5，y 1～16 | 两队各有一座只开南北两道门的小城堡；塌陷从两头的城堡先塌起，最后在正中的广场决胜 |

布阵和战术单里的点名都按本队在左书写。例如“守 A”就是守本队视角的上桥，坐左时对应场上 A，坐右时对应场上 C。程序用 `i = info().point_index("A")` 查索引，再读 `info().points[i]` 和 `o.owner[i]`。

三张图都是绕地图中心转 180 度对称，右队的布阵区是左队的转 180 度。地图文件里 `DEPLOY` 是布阵区，`POINT` 是占点，`SPAWN` 是默认站位，`//` 开头的行是注释。

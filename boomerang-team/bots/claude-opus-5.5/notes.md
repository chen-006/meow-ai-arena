# 飞镖乱斗 · opus 的程序说明

> 计时说明：比赛开始时本目录没有 `clock.json`（`python clock.py` 提示"没有找到计时信息"），我先按提示词的 75 分钟自己掌握时间；
> 后来主办方放入了 `clock.json`（07:55:15 开始，09:10:15 截止），之后以它为准。
> **交卷版是开发中的第 20 版**（`old/v20.cpp` 与 `player.cpp` 相同）：在第 8 版基础上只改了一个常数——
> 位置评估里"离自己地上的镖的距离"权重从 0.12 提高到 0.20（每米 200 分），让程序更积极地走过去捡镖、少站着召回。

## 1. 整体思路

程序是一个"**每步重新规划的推演搜索**"：每一步先把观察补偿到"现在"，生成几十个候选方案，用裁判同款引擎 `dart::Game`
把每个方案推演 16 步，再叠加几种"看不见的威胁"的风险扣分和进攻的命中概率，选分数最高的方案，只执行它的第一步动作。
下一步再从头算。整个程序是单个 `player.cpp`（约 1400 行），只用 `dart.hpp` 和标准库。

### 1.1 延迟补偿（`reconstruct`）
- 观察里别人是 4 步前的样子，自己是现在的。我记下自己每一步的状态和动作（`hp/hd/ha` 环形历史），
  拼出"第 t-4 步开始时的完整局面"（别人用观察，自己用历史），再用引擎推到现在：
  自己用当时真实给出的动作，别人按当时的速度方向继续走、不出手。
- 推完后把自己的状态和自己的镖换回真实的当前值（自己的东西是精确的）。
- 推演里对手被"打死"不当真（现实里他可能躲开了），保持存活。
- 这样已经在飞的镖、互推、撞墙、接镖在"现在"的局面里都和裁判一致，只有对手这 4 步的意图是猜的。

### 1.2 候选方案（`plans`）
- 移动：16 个方向 × 两种持续时间（3 步 / 9 步，之后站住），外加站着不动。
- 冲刺：8 个方向（冷却好、自由状态时），带一点固定代价。
- 扔镖：对每个可见对手，在多个瞄准方向里（情景"继续走/停"在镖到达时的位置、补偿后位置、观察位置，各再加 ±4.6°、±9.2° 偏移）
  选命中概率最高的一个，再配 4 种蓄势中的移动（左右横移、后退、站）。
- 挥砍 / 踢：贴近对手时朝他判定时刻的预测位置出手。
- 冲刺接近战：冲刺方向指向对手预测位置，在第 3/4/5 步接近战。要求"单纯冲刺本身也安全"——因为下一步重新规划时不一定会接近战，
  早期版本曾因此冲进 S 形深沟。
- 冲刺移动中：随时可以接近战（也当"刹车"用，避免冲刺终点落进坑）。
- 挡镖：对 4 米内飞来的镖朝它挥砍（引擎推演判断挡没挡到）。
- 召回：镖在地上时。

### 1.3 每个方案的打分
`分数 = 进攻收益 + 终点位置分 − 推演里死亡（−30000，越晚越轻）− 各种风险扣分`

1. **引擎推演**（`simPlan`）：H=16 步，对手按速度继续走。负责精确规则：自己会不会走进坑、撞上已知的镖、被推、冲刺越坑是否落地、挡镖是否成功、塌陷。
2. **真实飞镖的多情景风险**（`buildRealDarts` + `realRisk`）：观察里在飞的别人的镖、以及观察里正在蓄势（方向已知）的镖，
   用轻量模拟在**主人 10 种走位情景**下各推一遍（回程的镖追主人当前位置，主人走位不同路线就不同），按情景权重算被打中的概率，×20000 扣分。
   专门修好了"跑进对手回程镖路线"的死法（第一版对 strong 的主要死因）。挥砍方案会判断哪把镖落在格挡扇形里、之后不再算它。
   同时算出每个对手"按继续走的情景什么时候接住镖"（`armT`），给后面两项用：对手回程中途冲刺、接镖后接挥砍，是早期常见死法。
3. **假想来镖**（`buildThreats` + `threatRisk`）：对手手里有镖（或很快接住镖），假设他在我看不见的第 t-4..t+3 步任一步出手，
   瞄准"他那时看到的我"（我第 τ-4 步的位置），分不带提前量 / 全提前量 / 半提前量三种，算方案被打中的加权次数，×7000 扣分。
   **权重按对手的实际出手频率自适应**：统计每个对手"自由、有镖、在 7.5 米内"的步数和其中开始扔镖的次数，
   频率高的对手（例如见人就扔的 weak）威胁权重最多放大到 3 倍，最少 0.7 倍。
4. **假想近战**（`buildMelee` + `meleeRisk`）：对手可能在这几步直接挥砍/踢，或冲刺后在第 3/4/5 步接近战，
   按"他看到的我 + 提前量"瞄准，判定时我在不在扇形里。踢的话再模拟我被踢滑 12 步后停在哪：停在坑里就和被砍一样重，否则只扣一点。
   我在判定那一步处于锁定状态（硬直、召回、冲刺）时权重 ×3（对手能精确预判锁定中的我）。
5. **终点位置分**（`evalEnd`）：快塌的格子、坑边（被踢下去的风险）、离最终安全区的距离（越到后期越重）、手里有没有镖（空手 −250）、离自己地上的镖多远（每米 −200）、
   和对手的距离（双方有镖时不进 3.8 米，太远（>6 米）要靠近目标；我空手而他有镖时离 7.5 米以上；他空手我有镖时贴到 3.2 米左右压迫）；
   中间有墙时距离惩罚减轻。
6. **4v4 友伤**：推演里队友被我打死扣 25000；扔镖方向（含队友按速度外推的位置）1.5 米内有队友就不扔。

### 1.4 进攻：命中概率（`buildScen` / `throwProb` / `meleeProb`）
- 对每个对手，从 **4 步前的观察**出发（不是从补偿后的位置），生成 20 条行为情景：继续原速度、停、8 个方向各走；
  每种又分"不反应"和"看到我出手后（第 t+5 步起）横向躲开"两个版本。情景模拟考虑他当前的蓄势/硬直/冲刺/被踢滑行（锁定时动不了），也不会自己走进坑。
- 镖的去程是确定的（速度表 900、850、…，整条线只查一次墙），按相对运动判命中（含最远点停留 3 步），算加权命中率。
- 扔镖收益 = p × 9000 − (1−p) × 2600。挥砍同理；踢的收益主要来自"踢下坑"的概率（模拟滑行终点在不在坑里），
  并检查对方是否处于免踢状态（被踢硬直中、及硬直后一步）——早期版本会去踢正在硬直的人，必然踢空然后被扔中。

### 1.5 其他细节
- 所有数值从 `info().cfg` 读；出生点、地图、塌陷全从 `info()` 读，没有写死座位或地图。
- 安全区：开局 BFS 出"最后塌（或永不塌）的格子"的距离场，后期把人往里拉。
- CPU：1v1 单步最多约 2 ms，四人局约 2.5–2.8 ms，4v4 约 3.7 ms（预算 10 ms）。另有 6.5 ms 的 CPU 保险丝（`thread_cpu_100ns`），超过就停止评估剩下的方案。
- 平手用一个按座位播种的小随机数打破（xorshift），避免完全可预测。

## 2. 强项与弱项

**强项**
- 规则层面精确：所有动作的后果交给裁判同款引擎推演，不会自己冲进坑、冲刺不会落在坑里、挡镖时机由引擎判断。
- 躲镖：已知的镖（含回程镖在主人不同走位下的路线）基本不会再撞上；对看不见的出手按"他看到的我"建模。
- 自适应：针对"出手频繁"的对手提高警惕（对 weak 从 31:9 提升到 55:4）。
- 四人局表现好：对 3 个 strong 平均名次约 1.75、平均得分约 3.3（strong 们 1.9–2.3）。

**弱项**
- 冲刺斩（对手冲刺途中接挥砍）仍是主要死因之一：从对手按冲刺到判定只有 5～7 步，我看到时已来不及，只能靠风险模型提前保持距离。
- 自己处于硬直/召回/冲刺收势时被抓。
- 在更大、墙更多的图（我把两张 4v4 图改成 1v1 自测）上对 strong 只有五五开，召回次数偏多。正式的 1v1/四人图是 18×12 米，影响应小一些。
- 对手的 4 步隐藏期只用"继续原速度"外推来补偿推演局面；对急转弯的对手，补偿后的位置不准（命中率估计里用了多情景弥补）。

**试过但没用上的**（都在 160 局 1v1 + 80 局四人局上和基准比较过）
- `futureRisk/futureMelee`（第 t+4 步以后对手瞄准"方案里的我"出手，只在我锁定时计入）：开发中发现循环有 bug（第一次迭代就 break，实际从未生效）；
  修好后整体启用反而从 100:59 掉到 75:80；单独只开近战部分 95:61、只开飞镖部分 92:67，都不比不开好，所以保留了不生效的行为
  （代码还在，实际不起作用）。我猜原因是它让程序在任何会锁定的动作（扔、召回、冲刺）上都过于保守。
- 召回引导中的镖（RISE）建模为即将起飞的召回飞镖：83:77，比不加差。
- 整个冲刺都算"锁定"、冲刺代价 −350/−700、召回代价 −400：都在噪声范围内或更差。
- 冲刺中刹车代价 −3000（只在必死时刹车）：96:63，更差（刹车踢有时能救命/踢人下坑）。
- 风险权重 RISKW 4500 / 10000（现用 7000）、击杀价值 KILLV 7000 / 12000（现用 9000）、LOCKF 2 / 5（现用 3）：都不更好。
- 与对手保持距离的阈值整体放大或缩小：都更差。
- 踢的最低命中率 0.35 + 召回惯性（v9）：1v1 104:55 略好（噪声内），但四人局得分从 3.26 掉到 2.99；拆开测是"踢的门槛"伤害四人局
  （多人局里踢人下坑、打断别人很有价值），所以没采用。
- 草丛隐身奖励（终点在草丛且未暴露加 200/500 分）：1v1 和四人局都更差。
- 对手近战频率自适应（仿照出手频率）：1v1 持平，四人局 2.99，更差。

## 4. 规则疑问 / 可能的问题

- 没有发现引擎和规则文本不一致的地方。读代码确认了几处细节：
  - 冲刺移动最后一步 `dashing = 0`，照常判落坑；冲刺接近战后恢复落坑判定（所以"冲刺斩"方案里要求单纯冲刺也安全）。
  - 被踢免疫按"这一步开始时"的状态判断（`kick_protected`），硬直结束后那一步 free 且 timer=1 时也免踢。
  - 召回引导中给 ACT=4 不会重新计时，给任何移动立刻中断。
  - 出镖那一步镖不动、不判命中，也不参与镖撞镖；回程镖朝主人"这一步移动后"的位置飞。
- `Game(info(), obs)` 里看不见的对手是 `unknown`，推演中不移动也不会被打中；我只在假想威胁里用他最后出现的位置。
- 比赛开始时没有 `clock.json`，`clock.py` 无法显示时间（见开头）。
- 过失说明：开发中途我曾把几个对局结果的临时文本（以及一个调试用 .cpp）写到 Git Bash 的 `/tmp`（工作目录之外），
  发现后已删除我写的那些文件（没有动别的文件），之后只写本目录下的 `tmp/`。

# 团队赛（5v5，Fable 队，队长 fable）

## 第一轮（队长任务：适配 5v5、友伤、队内消息、战术单、三种模式的目标）

备份：改之前的海选版在 `old/v20_pre_team.cpp`，第一轮完成版在 `old/t1.cpp`。

### 改了什么
1. **适配 5v5**
   - 历史环形数组从 1100 开到 2048，`reconstruct` 里原来 `hv[t0]`、`hp[t0]`、`hd[t0]` 没取模（1200 步的占点会越界），已改成 `% HIST`。
   - `thrScale[MAXP] = {1,1,1,1,1,1,1,1}` 只初始化了 8 个，第 9、10 号是 0；改成在 init 里按 MAXP 循环初始化。
   - 队友一律用 `is_mate`，模式用 `M_ELIM / M_CONTROL / M_KING`；原来"扔前查队友"只在 `mode == M_TEAM` 时生效，已改成所有模式都查。
   - 占点出局期间 decide 直接返回空动作（不发消息）；复活后历史照常用（推演会按 base 复活，之后用当前观察覆盖自己），没有卡死和崩溃。
   - CPU：离我 12 米外、镖也不在附近的人，在推演里标成 unknown（不参与模拟）；方案按"站住、长移动、进攻、冲刺、短移动、召回"排序，超过 4.2 毫秒就砍后面的。
2. **友伤**
   - 扔：队友（消息位置和推到现在的位置都查）到"我 → 出手方向 7.2 米（撞墙截断）"线段距离 < 1.3 米就不扔；挑瞄准方向时直接跳过被挡的方向。
   - 挥砍 / 踢 / 挡镖 / 冲刺斩 / 冲刺中刹车砍：1.7 米内、出手方向 ±70° 内有队友就不出手。
   - 队友的镖（含正在蓄势的）用和敌镖一样的多情景路线：撞上按真实风险扣分（×20000），另外进到镖 1.2 米内、或站在回程镖与主人连线 1 米内扣分（×2500）。
   - 队友 F=2 报的镖路线段：16 步内走到 1.2 米内扣分（×2500）。
   - 位置评估：离任一队友 < 2 米扣 (2000-d)×0.3。
3. **队内消息**：每步发 `qx + 128*qy + 16384*F`；发出扔镖指令那一步 F=2，终点沿出手方向 7.2 米并截在地图内留 300 毫米。收到 F=1 用作队友位置（推演里把队友挪到消息位置 + 一步速度），F=2 记成危险线段；先看 alive，F=0/3 忽略。回放核对：存活的每一步 F=1 解码都等于自己所在格，每次扔镖都发了 F=2。
4. **战术单**：按行解析，第一个词是自己短名或 all，后面"键=值"；自己那行优先。认 pt、job、go、until；pt 用 `point_index` 换场上索引，没写就取离自己复活点最近的点；go 的米数坐右时换成 (W−x, H−y)。行尾 \r、中文行、不认识的键和非法值都跳过（专门测过）。
5. **三种模式的目标**（在位置评估里加一项"到目标点的路程"，路程用 `grid_dist` 算，绕开水和坑）
   - 占点 hold：目标是 pt 圆心，1.2 米外扣 800 + 0.8/毫米；圈里按离圆心距离轻微扣分。roam：去最近的"不是我们的、或圈里有敌人"的点，都是我们的就去找最近的敌人。选目标时优先打进了我圈（3.5 米内）的敌人。
   - 刺王：guard 目标 = 本方国王往最近敌人方向 2 米处；hunt 目标 = 对方国王（看不见就用最后看到的位置）；对方国王无敌时不朝他扔、不砍（踢照样，踢下坑价值 ×4）；打中对方国王价值 ×1.6。我是国王时：推演里每掉一条命扣 14000，离敌人 6 米内扣分（safe），坑边、快塌的格子加重扣分，离最近队友 3.5 米外扣分。
   - 歼灭：沿用海选的"往最后塌的区域走"；离最近队友 5 米外扣分（别落单），选目标时加上"队友离他多远"（和队友打同一个）。
   - go/until：步数没到、集结点 3 秒内不塌、6 米内没有敌人时，目标就是集结点。
6. 召回已经开始时，"站着不动"方案 +900（团队赛里原来会反复开始又取消召回，空手时间太长）。

## 第二轮（队长任务：F=3 冲刺预告；对照队长踩过的坑 A–E；占点空手；歼灭）

备份：`old/t2a.cpp`（第二轮主体），`old/t2b.cpp`（占点圈内减轻坑边 / 队友间距扣分的变体）。

### 改了什么
1. **F=3 冲刺预告**：发出冲刺指令那一步发 F=3，落点 = 起点沿冲刺方向 DASH_V×DASH_T（3 米），截在地图内留 300 毫米。
   收到队友的 F=3：记成"上一条位置 → 落点"的线段，6 步有效；扔镖 / 近战的友伤检查把线段上 5 个点都当成"队友可能在的地方"；
   推演里把这个队友设成冲刺状态（指令后第 e 步：timer = 8−e，已冲 clamp(e−2,0,4) 步），让他在推演里真的冲过去。
2. **A1 被挤下坑**：位置评估里离坑（含 45 步内要塌的格子、地图外）1.75 米内扣 (1750−d)×0.8，0.9 米内再加 (900−d)×1.5；离队友 1.7 米内再扣 (1700−d)×0.8（原来 2 米内 ×0.3 保留）。
3. **A2 墙坑之间的一格缝**：自己写了寻路（Dijkstra 10/14，不切角），"一边是墙、另一边是坑或地图外"的格子当成不能走；目标路程场和塌陷出发时刻都用它。
4. **A3 冲刺**：冲刺方案本来就用引擎推演到冲刺结束，落点是坑会被判死；现在自己掉坑（不是被踢）的方案扣 90000（一票否决）。冲刺途中前后两个方向的"刹车砍"如果都被友伤检查挡掉，就换别的方向砍一下停住。
5. **A4 塌陷按最晚出发时刻**：开局算一遍 ldep[c] = min(本格塌的步数, max(邻格 ldep − 走过去的步数))，从决战区往外推（最大堆）；
   位置评估里离最晚出发不到 35 步扣 (35−slack)×220（最多 7700，压过所有目标）；我现在这格不到 35 步时不要目标点（只管逃）；不到 50 步时不召回。
6. **B 目标拉力**：目标项改成"这个方案结束时的目标代价 − 现在的目标代价"（相对值）；自己掉坑的方案一票否决。
7. **C**：友伤检查只看观察里的 alive，位置用消息（F=1，冲刺中用 F=3 线段）+ 推演位置；推演里队友不会被假想镖打死（我的推演里没有假想镖）。
8. **D**：挡镖的挥砍、冲刺斩、冲刺中刹车砍全部过友伤检查（第一轮已经做了）。
9. **E**：队友回程 / 召回的镖到主人连线 1 米内扣分（第一轮已有）；新加：我自己的镖在回程 / 召回时，推演里有队友夹在"镖 → 我"线段 1 米内就扣分（×1500），让我挪位置。
10. **占点空手**：镖落在 3 米内（走 12 步以内）就把目标临时换成镖（拉力 1/毫米），走过去捡；召回坚持站完的加分降到 600，而且只在最晚出发还有 50 步以上时给。
11. **召回反复（查回放才找到的真原因）**：一局占点里我五个座位开始召回 210 次、被打断 195 次、真正飞回来只有 14 次；镖在地上的时间占 38.6%。
    调试输出显示站着不动的方案假想镖风险经常 3000–5000，程序躲开是对的，错在一开始就不该召回。改法：
    - 已在召回中、站着不动风险 < 1500、不会误伤队友时，直接选"站住"（不再和移动方案比）；
    - 站 12 步风险 > 800 时召回方案再扣 3000（别开始）；
    - 占点里镖在 6 米内（其他模式 3 米）就走过去捡，不召回。
    同一局（种子 77）改后：手里有镖 18.5% → 26.9%，镖在地上 38.6% → 30.7%，召回站着 12.8% → 2.3%；扔镖 55 → 82 次，捡镖 8 → 22 次。

## 第三轮（队长任务：占点 B 进不去；A/C 在圈时间；刺王 hunt / 国王防踢）

备份：`old/t3a.cpp`（B 点过缝），`old/t3b.cpp`（+ 国王防踢，交卷版）。

### 改了什么
1. **B 点过缝**：第二轮"一边墙一边坑的格子不能走"把 B 堡垒封死了（我当 B 位时一直贴在墙外）。现在：
   - 开局对每个点从圆心按 walkCell BFS：区域 < 300 格的就是"堡垒"（只有 B），找出区域边上所有"上下一墙一水"的缝格，
     算出外口 / 内口和方向：例如左侧北缝外口 (12.4, 8.58)、内口 (13.9, 8.58)，安全线 y = 水边 + 80 毫米（和队长给的数一致，按地图算出来，四个缝都有）。
   - 目标在堡垒里而我在外面：离最近的外口 > 2.5 米（或直线不全在地面上）时交给规划器、目标换成外口，坑边扣分放到 1/4；
     2.5 米内直线走过去（最后一步按比例慢走），离口子 ≤ 30 毫米且速度 ≤ 60 时开始沿缝的方向直线走，过了内口才交还规划器。
     过缝时不冲刺、不斜走、不停。出堡垒对称处理。
   - 回放量（整队 vs 五个 strong，6 局，我当 B 位）：第一次进圈 34–38 步；在圈里 45%、81%、68%、68%、75%、86%（平均 70.5%）；
     每局阵亡 2.0，落坑 0.5（3 次，回放里多数是被踢下水，state=8；有 1 次过缝时被推下水）。整队 6-0，平均分差 +107.7（第二轮同类测试 +38.9）。
     改之前（第一版过缝，1.2 米内才直走）：在圈里 37–69%，曾两局停在东墙外 (19.4, 10.0) 不动被打死——口子离水太近、坑边扣分大于目标拉力，进不了 1.2 米，所以改成 2.5 米 + 放轻坑边扣分。
2. **占点捡镖**：只捡离自己圈心 ≤ 半径 + 1.2 米、且和我在同一个区域（都在堡垒里或都在外面）的镖；否则在圈里召回。
3. **国王防踢**：我是国王时，空手（会踢）的敌人 4 米内扣 (4000−d)×0.6；离我 6 米内的敌人，沿"敌人 → 我"方向往后 0.8/1.5/2.2/2.8 米有坑（或 12 步内塌）就扣 (6000−d)×0.4。

## 第四轮（队长任务：管好自己的镖；陪练换成队长的程序）

备份：`old/t4a.cpp`（四条规则），`old/t4b.cpp`（t4a + 占点清圈 / 圈内斥力减轻）。统计脚本 `tools/armstat.py`（持镖比例、阵亡分类、被镖打死时是否空手、在圈内比例）。

### 改了什么（只在团队赛模式生效，1v1 / 四人局不变）
1. **出手门槛**（throwOK）：只在 对手 4.5 米内且处在蓄势 / 出镖硬直 / 挥砍踢起手与硬直 / 冲刺前摇与收势 / 召回 / 被踢 时，或 3 米内，或对手空手且 5 米内 才扔；
   隔墙不扔；对手持镖、站着、正对着我（朝向差 < 25°）、离我 1.8 米以上时不扔（他一刀就能挡）。
2. **空手时**：空手扣分 250 → 1200（推演里早接到回程镖的方案更好，等于"站在镖 → 自己的线上等它"）；持镖敌人 7.5 米内的斥力 0.12 → 0.35/毫米（隔墙仍是 0.05）。
   镖落地：只在 3 米内、镖附近 6 米内没有持镖敌人看得到时走过去捡；6 米内有持镖敌人看得到我时不召回。
3. **敌人空手时进攻**：选目标时空手的敌人优先（距离按减 2.5 米算）；对空手的目标保持 3.2 米的权重 0.05 → 0.12。
4. 隔墙、对方正对着我持镖时不扔（见 1）。
5. CPU：团队赛规划预算 4.2 → 3.5 毫秒（刺王对 fable 时单步最大到过 8.54 毫秒，改后 5.62）。交卷版 `old/t4c.cpp` = t4a + 预算 3.5 毫秒。

## 我的程序在三种模式里怎么打

## 队长的指导：最有用的和没说清的

**最有用的**
1. **第二轮的"踩坑清单 A–E"**：被挤下坑、一格缝、冲刺落点、塌陷要按最晚出发时刻算、目标拉力要用相对值。每一条都给了机制和对策，直接对应到我评分里的具体项；改完落坑和误伤都明显下降。

# 飞镖乱斗 · 参赛笔记（deepseek_dsh）

## 1. 程序是怎么打的

整体思路一句话：**不把 0.2 秒前的观察当成现在，而是先用裁判同款规则把局面推回现在，再对一组候选动作做 16 步前向推演，按"活着 > 击杀 > 抢到好位置/留住镖"打分，走分数最高的一步。**

### 1.1 延迟补偿：重建当前局面

观察里别人和别人的镖是 `DELAY = 4` 步以前的样子，自己是现在的。程序每步把自己真实的 `Player`/`Dart` 状态和这一步要发出的 `Action` 记进历史数组（`myP/myD/myA`）。决策时：

1. 用 `Game(info(), obs)` 建一个以"4 步前"为初始局面的对局（观察里别人正好是那一刻的状态）；
2. 把自己的座位换成历史里第 `t-4` 步的真实状态和自己的镖；
3. 对这 4 个隐藏步，自机用记录的真实动作回放，对手用"按当前速度继续走"的推断动作，调用 `Game::step` 推 4 步；
4. 推演结束后再把自机状态/镖强制对齐到当前观察（保证自己一定是准的）。

这样得到的对手位置、镖的位置（包括这 4 步里刚出手的镖、撞墙落地、镖撞镖）、倒计时和状态，都比"把旧位置直接当现在用"准确得多。重建时如果自机被推断动作害死（说明推断和真实冲突），就退回不重建的保守版本。

### 1.2 候选动作

每步枚举：

- **16 个方向的移动**（22.5° 一个）+ 停止；再补上朝最近对手/背对最近对手、朝自己地上的镖、朝地图中心、以及垂直于每把敌方飞镖运动方向的两个方向；
- **扔镖**：对每个对手，先用一个轻量推演估计"镖飞到他需要几步"，在到达步数附近 ±2 步的未来位置上取瞄准点（相当于提前量），再用完整推演验证；1v1 和四人局用不同的瞄准搜索（四人局更偏向打空手/硬直中的目标）；
- **近战**：朝对手未来 0/1/2 步的位置，以及左右各偏约 22° 的方向挥砍/踢；另有朝敌方飞镖现在/下一步位置起手，用来**格挡**；
- **冲刺**：朝最近对手、地图中心、8 个罗盘方向；
- **召回**：镖在地上且自由时。

### 1.3 推演和评分

每个候选都用 `Game` 从重建局面往后走 16 步：

- 自机第 1 步用候选动作，之后假设一直朝同一方向移动（冲刺/硬直/召回等状态由引擎自己处理）；
- 对手继续按当前速度走；**如果自由、有镖、能看见我且在 5000 内，就朝我扔镖；很近就挥砍/踢**。这是一个偏悲观的对手模型，目的是逼自机真的去躲镖，而不是站着挨打；
- 中途自机出局 → 巨大负分（越晚出局略好一点）；击杀对手 → 大额正分；
- 推演结束后再加位置分：脚下格子离塌陷还有多久、离边界、离最近对手的距离（有镖时保持约 2.5 米、没镖时退开）、对手空手/硬直时压上去、四人局里不要被两个人夹住、草丛隐蔽等。

最终选总分最高的候选。若所有候选都会死，就选死得最晚/带一个垫背的。

### 1.4 其他细节

- 看不见的草丛对手：用最后一次看见的位置和速度外推，放进推演里当威胁（但不作为主动瞄准目标），避免被草里出来的人白打。
- CPU 预算：实测单步最多约 4.8 毫秒（预算 10 毫秒），4v4 的 check 里约 2 毫秒，第 0 步约 55 毫秒（预算 1000 毫秒）；因此没有加时间预算收手，保证同样的局面总是选同样的动作。每步的候选数有限（约 50 个），最坏情况也在预算内。
- 决策里有一个由座位号播种的小随机数，只用于打破完全相同的分数（避免固定偏向某个方向/座位），不影响主逻辑。

## 2. 强项和弱项

**强项**

- 延迟重建：比"把观察当现在"的版本强很多（早期版本的直接对照很明显）。
- 镖的威胁处理：对手模型会主动朝我扔镖，逼着自机在 4 步盲区里也做规避；实测这是提升最大的一块（把对手扔镖模型关掉后，同一批 1v1 从 15 胜 25 负掉到 8 胜 32 负）。
- 防守位置：会算脚下格子的塌陷时间、离坑和边界的距离，很少自己掉坑（正式测试里落坑出局比例很低）。
- 四人局的"不要被夹击 + 躲开有镖的人 + 抓空手/硬直"这一组打分，把四人局平均得分从约 1.65 提到 2.69。

**弱项**

- 对真正会预判的对手，远距离扔镖命中率仍不高；模拟里对手"继续走"，现实中对手会横向躲，很多镖被躲掉。
- 近战使用率低（每局约 0.1～0.2 次挥砍），远低于 strong 的约 1.2 次；近身缠斗主要靠躲而不是抢刀。
- 决策对极小的分数差敏感：同一份逻辑改一点无关代码，胜负可能摆动几个百分点；60 局的对比经常不可靠，下面的结论尽量用 120 局。
- 没有真正的多步计划（冲刺接近战只作为一次性推演，不会跨步执行），复杂连招做不出来。

**试过但没有用上的想法**

- 冲刺后接挥砍的"计划"候选：推演里很赚，但下一步重新决策时不会继续执行，实际变成白白冲刺，40 局从 23 胜掉到 16 胜，放弃。
- 真正跨步执行的冲刺斩（记住计划、到冲刺移动段强制接挥砍）：无约束时 60 局 21:37、四人局 1.52，明显变差；只对"硬直中、且硬直覆盖判定步"的目标用，120 局 65:53、四人局 2.60，和不用时（64:54、2.69）在误差内，最终不用——预测的必杀在现实里经常被对手在最后 4 步改动作躲掉，承诺冲刺反而把自己送进危险距离。
- 把移动方向从 16 个加密到 32 个（11.25°）：120 局 59:60、四人局 2.02，明显变差——候选太密时很多分数几乎相同，反而选不出有意图的走位。
- 让对手模型"追着我走"：对手太强，自机变得过度保守，1v1 和四人局都明显变差。
- 让对手模型"预判我的速度"再瞄准：自机过度躲镖，胜率下降。
- 故意朝敌方飞镖扔镖去空中相撞：没有稳定收益，还带来过单步 CPU 尖峰，去掉。
- 把推演深度加到 18/20 步：16 步最好；更深时"一直朝一个方向走"的假设太失真。
- 召回保护/惩罚：各种阈值试下来和 16 步推演自带的效果差不多，最终保留让推演自己决定。
- 1v1 里给召回/冲刺加固定惩罚：120 局 60:60，没有收益，去掉。
- 出镖时站定（让出手点和瞄准方向完全一致）：120 局 47:73，明显变差——扔镖那 4 步里的移动本身就是在躲对手的镖，站定等于挨打，去掉。
- 对手扔镖威胁半径的参数扫描：4000 → 51:68，4500 → 61:57，**5000 → 64:54**，5500 → 58:62（各 120 局）；400 局复核：4800 → 163:232、四人局 2.71，5000 → 194:204、四人局 2.80，5000 还让四人局从 2.32 提到 2.80。这个参数比大多数结构改动都值，最终取 5000。
- 四人局扔镖距离上限：不设上限（400 局 2.56）→ 4200（400 局 2.80）→ 3800（400 局 2.70）；只在四人局加 4200 上限（远处目标在混战里很容易躲镖，扔了反而空手），1v1 不受影响，仍为 64:54。
- 1v1 没镖时的退避半径/强度：3000/0.08（原值）→ 64:54，3400/0.10 → 56:63，2800/0.06 → 62:57；保留原值。
- 起手 1～3 步也做延迟重建（从第 0 步回放）：和原来的逐局结果完全一致（那几步对手速度是 0，外推不动），保留更一致的写法。
- 用 `thread_cpu_100ns()` 做 CPU 预算保护：实测本程序单步最多约 4.8 ms（预算 10 ms），预算保护几乎不会触发，却会让同一份程序在不同运行中因为计时抖动而选出不同动作（同样 60 局重跑胜负会摆动）。最终**去掉预算保护**，让搜索完整、结果确定；4v4 的 check 里单步最多约 2 ms。源码里只保留一个开局前 40 步写到 stderr 的小调试输出（不影响协议，正式比赛可以直接关掉/忽略）。

## 4. 规则里没看懂/有歧义的地方

1. **同一步"出镖"与"挥砍判定"的先后**：5.4 说被踢/被砍时正在蓄势的镖在同一结算步仍会出手，6 的结算顺序里又先处理出镖、再处理挥砍判定。我按 `Game::step` 的实现来理解（出镖的镖这一步不动、不判伤害；挥砍判定用出镖前的位置），没有发现和文字冲突，但这块文字读起来容易误解。
2. **"被踢硬直最后一步"的落坑判定**：5.4 说第 4 步计时已经转回 free，所以照常判落坑并记给踢的人。我依赖引擎实现，自己没有另写判定；建议文字里补一句"最后一步在计时轮转后判"。
3. **草丛可见性与延迟**：7.2 说"按 DELAY 步以前那一刻判断，包括你自己那时的位置"，但又说队友消息不延迟。我的理解是：观察里的 `vis` 已经是按 4 步前算好的，直接信它；重建时不能拿现在的草丛/位置重新算可见性。实际实现里 `Obs.vis` 确实就是那一刻的结果，和文字一致。
4. **`Game(info(), obs)` 的 `unknown`**：文档说看不见的人不移动、不出手、不会被打中；我实测确认了。但它也意味着直接拿观察推演会低估草丛里的威胁，需要自己补——这点 README 有提示，不算歧义。
5. **时间/CPU 计量**：第 10 节说 CPU 计量按进程累计周期差、取数边界在收到动作行时。用墙上时钟或 CPU 时间收手都会受调度影响，这一点文档自己也承认；我没有发现裁判/引擎的确定性有问题（同样的动作序列结果逐位一致），只是带时间预算的搜索在不同机器负载下可能选出不同动作。
6. **小局平局**：1v1 打满 40 秒都活着算平局，四人局并列名次分平分。我的程序没有专门"拖平"的逻辑（推演里也没有把"活到时间结束"当成一个明确目标），如果正式比赛里出现大量僵局，这可能是一个可改进点。

## 团队赛 第四轮（管镖 / 空手生存）
- 改动：扔镖门槛改为全模式（4.5m 内且对手非自由 / 3m 内 / 对手空手且 5m 内），不朝正对持镖的敌人和墙后扔；空手时远离持镖敌人 7m（有墙加成），3.2m 内且没人盯着才去捡，召回要求 6m 内没有持镖敌人且有视线；对手空手 5m 内可打。

## 赛后复盘（Fable队 deepseek）

### 一、三种模式里我的程序怎么打
通用骨架：每步先用裁判同款 Game 从 4 步前的观察重建当前局面（自机用记录的真实历史回放，别人按观察到的速度外推，队友有 MSG 就用新位置），再枚举移动、扔镖、挥砍/踢、冲刺、召回等候选，每个候选往后推演 12 步。推演里敌人会朝最近的本队队员扔镖/挥砍，队友按当前速度继续走。评分顺序是：自己活着 > 团队击杀/占点/护王 > 地形安全、队形、手里的镖。所有选目标都排除队友，扔、砍、踢、格挡都过友伤检查，CPU 到 4.8ms 自动收手。战术单认 pt、job、go、until；MSG 每步发 F=1，扔镖那步发 F=2，收到 F=2/F=3 只当危险线段、不当位置。
歼灭：默认先守本方岸边，按队伍平均 y 选北桥或南桥，380 步后进湖心岩台，岛上按座位散开；有 go 就先到集结点；离坑和快塌格子越近扣分越多；不主动追出队形。提前上岛的特殊过桥逻辑试过但没做成，最终版仍是这套默认打法。
占点：默认守离自己复活点最近的点；战术单给了 pt 就守 pt，job=roam 就去最近的非我方/圈里有敌人的点。进圈后优先站住，敌人进圈就按出手门槛打，尽量不追出圈；死了复活直接回点；空手时收着打、能安全捡镖就捡，否则等镖回来或找机会召回。实际圈内时间约 25~35%，是最大短板。
刺王：自己不是国王时默认 guard，站在国王和最近敌人之间、离国王 3.5 米内；job=hunt 就直奔对方国王。自己是国王时默认 safe，贴队友、躲敌人、不靠坑，第 330 步后如果还困在城堡里就先从最近的门出去再去中间；job=fight 就按普通队员打。我的国王明显弱于队长。

### 二、队长的指导：哪些最有用、哪些没说清
最有用的是这五条：
1. 用队友程序 fable.exe 当陪练。strong 太弱，五个我打五个 strong 基本全胜，说明不了任何问题；换成 fable 之后才看见真实差距。
2. 用回放量化。圈内时间、每局阵亡、死因分布、持镖时间、被镖打死时空手的比例——没有这些数，调参就是瞎猜。
3. 「47% 的镖死发生在冲刺里」。禁掉近敌冲刺后，占点阵亡 8.1 降到 7.0，砍死 2.0 降到 0.5，这是单条最有效的修复。
4. 「管好自己的镖」四条。提高出手门槛、空手拉开、敌人空手才是机会、别朝正对持镖的敌人扔。改完持镖时间 83% 到 89%，被镖打死时空手 41% 到 25%。
5. 先备份、改不好就退回。第五、六、八轮三次试验都变差，都是靠回退保住了好版本；最终交的 v35 是验证过最稳的一版。

没说清或我理解偏的地方：
1. 第四轮说空手要拉开 7 米，第五轮又说占点守点时不要退到 7 米外、就在圈里等镖。两条相反，占点里照前者执行等于把点让出去；我后来才明白 7 米只适用于歼灭/刺王。
2. 第五轮给的评分量级（目标区 80 分/米、被打中 600~1000 分）和我的评分体系（击杀、占点、死亡都是几千）不是一个尺度。直接照搬后程序变成冲圈送死：圈内 0~3.8%、掉坑 5.4 次/局。这里需要的是各项权重的比例，不是绝对数字。
3. B 点窄缝给到了 0.1 米宽的可走线和精确坐标，但没说清怎么让 0.1 米的线在格子中心寻路和整数毫米移动下稳定保持；我做了特殊路线，仍然只成功一半。
4. 提前上岛只给了 go=13,9 和 130 步目标，没说路上遇到敌人时「赶路」和「打架」谁优先。我的程序一路打架，440 步才到桥头，过桥逻辑根本没触发。
5. 消息协议没确认到每个人程序的实际实现。队友并不都发 F=1/F=2，所以「队友位置用消息里的新位置」在我这里退化成 4 步前观察加外推；最后的交叉火力 4 局 0 触发，也和这个有关。

### 三、最满意和最遗憾
最满意：
- 5v5 适配做得干净：10 人、1200 步、三种模式、左右换边都不崩，最终三图测试故障 0；单步 CPU 平均约 1ms、最大约 3ms，离 10ms 预算很远，这在 10 人推演里不容易。
- 友伤从早期每几局一次，降到最终测试 0 次；占点挥砍误伤 carbon 的问题用「2.2 米/80 度/目标身边 1.2 米/队友 2 步预判」修掉了。
- 用数据驱动改进：冲刺死亡、持镖率、空手镖死这几个数是真的动了（阵亡 8.1→7.0→6.1，持镖 83→89%，镖死空手 41→25%）。
- 知道什么时候停手：三次试验做坏都老老实实回退，没有为了「用了新功能」而把好版本弄坏。

最遗憾：
- 占点圈内时间始终只有 25~35%，离队长的 55~77% 差一大截。这是 0.5:5.5 里我贡献的一部分，我没找到「既站住圈又不送死」的评分平衡；第五轮照搬队长的量级反而更差，说明我对自己的死亡惩罚和占点收益的相对关系还没吃透。
- 刺王当国王明显弱于 fable：同样四个队友、同样阵型，我的国王胜率只有三成多。safe 太保守，fight 才有五成多，但最终默认还是 safe。
- B 点进圈、提前上岛两个具体战术都没做成，交叉火力一次没触发。练了很多，但没转化成比赛里的实际收益。
- 对团队协同估计不足。我的程序更像一个独立强个体，交叉火力、同点分工、消息协议这些真正靠配合的东西做得不够；下一版应该更早和队长对齐协议，把「队友会怎么做」当成一等公民，而不是只优化自己那一步。

如果再来一次：我会把占点评分里「目标拉力 / 敌人威胁 / 死亡惩罚」做成三四个可调比例，用回放脚本自动扫参，而不是每次手调一个绝对值；也会在开发早期就和队长确认每个人的消息协议和战术单执行情况，先把团队协同跑通，再抠个人走位。

# 成绩和判定结果

除这份说明外，都是比赛时裁判脚本的输出或裁判模型写的文件，原样复制。文件里的"队A"～"队F"见 `抽签结果.md`；"第 5 期"就是第 5 集；提到的 `赛事/…`、`裁判/…` 是主办方本地的目录，对应关系见 `../referee/README.md`。

这些文件用的是改名前的旧称："攻手"就是"测试手"，"击穿""攻击"就是"找到反例""找反例"，"守住"就是没找到反例，"抗击穿"就是"抗反例"，"拿下"是指在几份代码上找到了反例。

| 文件 | 内容 |
|---|---|
| `最终成绩.md` | 全部成绩表：三张榜、终版在 9 组隐藏负载上的用时、相对基线的倍数、初测和精确重测的对比、盲评、7 个缺陷点、终版复测、终版体检。**数字以它为准** |
| `团队成绩.md`、`团队成绩.json` | 三张榜和每个分项的明细，`团队计分.py` 的输出 |
| `results1.jsonl`、`第1轮_速度成绩.md` | 第 1 轮 6 份主程代码在 8 组隐藏负载上的逐组结果（每行一组：状态、每次运行的 CPU 秒、墙钟、内存）和汇总表 |
| `results2.jsonl` | 第 3 轮 6 份终版在 9 组隐藏负载上的逐组结果（精确计时，`precise` 字段是连跑的遍数和累计 CPU 时间） |
| `主程基准.jsonl` | 算增值用：主程原版在第 3 轮负载的旧格式版本上的用时。没有队E，原因见 `../CONDITIONS.md` |
| `修复.json` | 每份终版修好了本队几个回归用例 |
| `results2_初测.jsonl`、`主程基准_初测.jsonl`、`团队成绩_初测.md`、`团队成绩_初测.json` | 精确重测之前的初测结果。**初测是重赛的第一遍计时，不是作废的第一次比赛。**前三名在轻负载上只用 0.03～0.05 秒，是 2～3 个计时刻度，好几组完全并列，所以重测了一次。名次没有变 |
| `抽签结果.md`、`抽签结果.json` | 分队 |
| `历代战绩.json` | 12 个模型前 4 集的成绩，填提示词用的。里面的"说明"一栏是主办方本地的数据来源（主办方电脑上的相对路径，仓库里没有这些文件；这份文件是填提示词用的原件，没有改） |
| `round2/矩阵.json`、`矩阵.md` | 第 2 轮 28 个用例的正式判定：成立与否、原因、基线和被测代码的用时。`✖` 表示这位测试手在这份代码上至少有一个用例成立 |
| `round2/缺陷点归类.md`、`缺陷点归类.json` | 成立的用例归成 7 个缺陷点，以及每位测试手的得分。归类是人工做的 |
| `blind-review/汇总.md`、`汇总.json` | 盲评的最终分数和每位裁判的一句话点评 |
| `blind-review/<裁判>/` | 每位裁判写的文件：12 份 `代码XXX.json`（5 个维度的分数和证据）、`总览.md`、`草稿.md`、追问得到的 `百分制.json` |
| `blind-review/对照表.json` | 匿名编号对应哪一队的哪份代码。比赛时裁判看不到 |
| `retest/判定.md`、`判定.json` | 终版复测的正式判定 |
| `retest/<裁判>/cases/finalN/` | 两位裁判交的反例和检查记录 `说明.txt`。没有 `.in` 的目录表示没找到反例，说明里写了检查过什么 |
| `retest/对照表.json` | `finalN` 对应哪一队的终版 |
| `final-check/性能探针.md`、`性能探针.json` | 终版体检的性能部分 |
| `final-check/赛后流水线.log` | 赛后一连串评测的日志：复测判定、精确重测、计分、两轮随机对拍（每份终版"不一致 0 个"的记录在这里）、性能探针。产生它的批处理 `赛后流水线.sh` 没有放进仓库 |

两处要留意的地方：

- `round2/缺陷点归类.md` 开头一度误写成"28 个用例，21 个成立，7 个不成立"，整理开源材料时已更正为 20 个成立、8 个不成立（和它自己的表、`矩阵.json` 一致），文件里留了更正说明。缺陷点和得分不受影响。
- 盲评的评分文件引用的是匿名副本里的代码，模型名和队名在那份副本里被换成了"某某"，所以个别引文和 `../submissions/` 里的原文差这几个词。

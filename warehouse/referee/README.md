# 复现正式评测

这里是比赛用的裁判程序、参考实现和隐藏负载。除 `评测.py` 的两处开源修复（续评版本校验、精确计时补跑内存检查）和 `进度.py` 里去掉的一处本机目录名外，放出来的脚本和比赛时逐字节相同。历史成绩保持原样。它们按比赛时的中文目录找文件，所以要先用 `还原目录.py` 把仓库里的材料复制成比赛时的结构，再在那里运行。

## 需要什么

- Python 3。比赛时和开源前的核对都是在 Windows 11 上用 Python 3.12 做的，没有装任何第三方包。
- g++，要支持 `-std=c++20`。比赛电脑上是 w64devkit 里的 GCC 16.2.0。脚本直接调用 `g++`，也可以用环境变量 `CXX` 指定（PowerShell：`$env:CXX = "C:\path\to\w64devkit\bin\g++.exe"`，请换成实际绝对路径）。仅把编译器放进仓库 `tools/` 不会让第五期脚本自动找到它。
- 运行 `.sh` 脚本需要 bash（Windows 上用 Git Bash）。只做评测和计分用不到它们。
- 计时用的是进程的 CPU 时间。`workspace/tools/measure.py` 里有非 Windows 的分支，但整套流程只在 Windows 上验证过。
- 系统路径和编译器的坑：比赛电脑的系统代码页被改成 UTF-8 之后，w64devkit 的链接器打不开含中文的路径（经过见 `../CONDITIONS.md`）。还原出来的目录带中文名，如果编译时报 `cannot open output file … Invalid argument`，就是这个问题。

## 步骤

```bash
python referee/还原目录.py ~/warehouse-rerun      # 在 warehouse/ 下运行；目标文件夹随意，必须不存在或是空的，不要放在仓库里
cd ~/warehouse-rerun
```

还原出来的文件夹里已经带着比赛的全部结果。**只想验证计分**，直接重算，不需要编译：

```bash
python 裁判/盲评汇总.py          # 重写 赛事/盲评/汇总.md、汇总.json
python 裁判/团队计分.py          # 重写 赛事/结果/团队成绩.md、团队成绩.json
python 裁判/第1轮速度表.py       # 重写 赛事/结果/第1轮_速度成绩.md
python 裁判/成绩汇总.py          # 重写 赛事/结果/最终成绩.md
```

开源前核对过：这四步的输出和 `../results/` 里的文件逐字节相同。

**重新评测**（要编译，机器要空闲，不要并行）。请使用新的 `--out` 路径，或在还原副本中删除旧结果后重跑。`评测.py` 现在校验源码、负载、基准清单、评测工具及参数摘要；只有摘要相同才跳过已完成条目，摘要缺失或不一致会退出，不会静默复用历史结果：

```bash
rm 赛事/结果/results1.jsonl 赛事/结果/results2.jsonl 赛事/结果/主程基准.jsonl
python 裁判/评测.py --phase 1 --entries 赛事/主程提交 --out 赛事/结果/results1.jsonl
python 裁判/评测.py --phase 2 --entries 赛事/接手提交 --out 赛事/结果/results2.jsonl --min-total 2
python 裁判/主程基准.py --min-total 2 --skip 队E     # 增值用：主程原版在第二阶段负载的旧格式上的用时
python 裁判/修复判定.py                              # 终版有没有修好本队的回归用例
python 裁判/团队计分.py
python 裁判/成绩汇总.py
```

- 加速比是拿你测到的用时去除 `manifest.json` 里的基准用时，而基准是在比赛电脑上测的。换一台电脑，输出对不对可以完全复现，**加速比和分数不能直接比**。想在自己的电脑上重测基准，运行 `python 裁判/准备隐藏负载.py --phase 2 --repeat 1`（参考实现 9 组合计约 17 分钟）和 `--phase 1 --repeat 1`（基线很慢）。注意 `--phase 1` 现在会多生成 3 组 `hid_heavy_*`，那是重赛时为第二阶段加的配置，第 1 轮的评测没有用它们。
- 隐藏负载可以从种子重新生成：`gen.py`、`gen2.py` 用种子 20261006 生成的内容和这里的 `.in` 文件逐字节相同（开源前核对过）。
- `--min-total 2` 就是"精确计时"：每组连跑到累计 CPU 2 秒、最多 80 遍、取平均。不加就是初测的口径。
- 开源前在还原出来的目录里试跑过第二阶段评测和修复判定：五份终版 9 组全部正确，队E 全部异常退出，修复结果和 `../results/修复.json` 相同。

**其他判定**：

```bash
python 裁判/击穿判定.py          # 第 2 轮：重判 28 个用例，重写 赛事/击穿结果/矩阵.*。超时类用例每个要等一两分钟
python 裁判/终版复测判定.py      # 赛后终版复测的判定
python 裁判/终版体检_性能.py     # 性能探针
python 裁判/可行性验证/边界对拍.py 标准程序 被测程序 1500 --p2      # 随机对拍，用法见脚本开头
```

上述第 2 轮和终版复测脚本内部并行 3 个用例，并使用墙钟时间判断超时；这里的“不要并行”指不要同时启动其他评测任务。并行竞争和机器速度都可能影响超时结论，压线反例尚无新增串行复核记录。历史边界对拍中存在非法输入，详见 [审计补充](../CONDITIONS.md#开源审计补充)。缺陷点归类（`赛事/击穿结果/缺陷点归类.json`）是人工写的，脚本不会生成它。

## 写死了本机路径的地方

- 比赛根目录 `C:\arena5`：`赛事工具.py` 里的 `ARENA`，`终版复测计时.sh` 里的 `/c/arena5`。建选手文件夹、计时、封存、拼赛后评审包（`生成赛后评审包.py` 会往那里写）都用它。只做评测和计分不涉及。
- `巡检.py`、`进度.py` 读的是用户目录下 Claude Code、Codex 的会话记录，以及 `赛事/运行记录/` 里的原始输出，这些都没有放进仓库。
- 编译产物默认放在 `裁判/build/`。比赛电脑上有安全软件会拦截别处新编译的程序，所以脚本里有不少相关的注释，别的电脑不用管。
- 环境变量 `A02_EVENT` 可以把"赛事"目录指到别处，彩排时用的。

## 和比赛时的差别

- `评测.py` 增加开源修复：新结果逐条保存 `fingerprint`；续评时检查源码、负载、基准清单、评测脚本、计时工具及参数是否相同，旧结果没有摘要时拒绝续评。精确计时补跑现在也检查 1 GB 内存上限，并记录所有补跑的峰值内存 `peak_mem_mb`。这些修复不改计分公式，也没有重写历史成绩。`进度.py` 的越界检查里原来有一处本机出题目录的名字，开源时去掉了，只保留按内部编号匹配的那一个条件。其余比赛脚本未改；这份 `README.md` 和 `还原目录.py` 是开源时新增的文件。
- 没有放 `开跑.py`（命令行席位的启动脚本）、`查用量.py`（查接口额度）和 `隔离测试.py`（检查各工具的工作目录），因为里面是本机各工具的安装位置、密钥文件的位置和账号池的模型名。受影响的地方：`收卷.py` 在文件开头就导入 `开跑`，直接运行会报错；`开局.py <队> 准备`（只在第 1 轮）和 `复盘.py --run` 也会在导入 `开跑` 时报错；评测、判定、计分、拼包都不受影响。各工具的启动参数写在 `../CONDITIONS.md` 里。
- `复盘.py` 还要读 `赛事/运行记录/` 里第 1 轮的元数据，这些没有放，所以它不能直接重跑；它生成的提示词模板见 `../prompt.md`。
- 拿掉了 5 个比赛当时的内部脚本：`赛后流水线.sh`、`夜间评测.sh`、`夜间审计.sh`、`夜间彩排.py` 是把评测步骤串起来的批处理和彩排脚本，引用 `裁判/build/` 下已经编译好的程序和计时日志，单独拿出来跑不通；`计分_个人赛版.py` 是早先个人赛赛制的计分，这一集没有用。没有别的脚本调用它们，按上面的步骤逐条运行即可。`成绩汇总.py` 开头的注释和成绩文件里提到的 `赛后流水线.sh`、`赛后流水线.log`，指的是那个批处理和它的日志，日志在 `../results/final-check/`。
- `提示词/` 只放了脚本要读的 4 个模板（赛前狠话和三轮的提示词）。
- 没有放编译产物，也没有放隐藏负载清单的几份旧备份。
- `还原目录.py` 会按 `矩阵.json` 把成立的反例复制成 `赛事/击穿结果/被击穿用例/`，比赛时这个目录是 `击穿判定.py` 生成的，内容相同。

# HANDOFF.md —— 给接手队友的交接文档

> 本文档是与队友唯一的沟通渠道。**动手前先通读一遍**，尤其是"怪行为清单"和"要改逻辑动哪里"。
> 现状：`src/` 是对 `baseline/` 的性能重写版，输出与基线逐字节一致（公开负载 + 大量对拍用例已验证），
> 公开负载加速 16x ~ 147x。基线代码仍是行为的唯一标准答案：**任何行为疑问，去 `baseline/` 里读代码，不要信 SPEC.md**。

## 1. 代码结构（编译：`g++ -O2 -std=c++20 src/*.cpp`，只用标准库）

| 文件 | 职责 |
|---|---|
| `common.h` | 数据结构（`Robot`/`Order`/`Evt`）、全局状态、各模块接口 |
| `input.cpp` | 一次性读入 + 事件解析，事件按 tick 分桶（`AllEvents()[t]`） |
| `dist.cpp` | 地图查询（`OK`/`INMAP`/`ISWALL`）、**距离表缓存**（`DistTable`/`DIST`/`CHG_DIST`/`ALL_CHG`） |
| `sim.cpp` | 主循环 `RunSim()` 与 7 个阶段：事件 → 救援 → 充电 → 派单 → 去充电 → 移动 → 报表；`Finish()` 收尾 |
| `output.cpp` | 输出缓冲（拼一个大字符串最后 `fwrite`）+ 送达/丢失/拒绝/取消/延迟统计 |
| `main.cpp` | 入口与全局变量定义 |

主循环在 `sim.cpp` 顶部 `RunSim()`，每个 tick 的阶段顺序和基线一致，日志顺序就是输出顺序，别动。

## 2. 性能是怎么来的（改动逻辑时别把这些弄坏）

1. **事件按 tick 分桶**（`input.cpp`）：基线每 tick 扫描全部事件并 `SPLIT`，是 O(T×E) 的天坑。
2. **距离表缓存**（`dist.cpp`）：BFS 距离只取决于"墙 + 封锁"，所以按 (出发点, 封锁版本) 缓存，
   LRU 上限约 256MB。`BLOCK_VERSION` 在每次 BLOCK/UNBLOCK 真正改变状态时 +1（`DistInvalidate()`），
   缓存自动整体失效。**如果你的改动引入了新的距离查询，直接用 `DIST()` / `DistTable()`，不要自己写 BFS**。
   - `distSrc(tab, a, b)`：tab 是"从 a 出发"的表，直接查 b。
   - `distRev(tab, a, b)`：tab 是"从 b 出发"的表，用对称性反查 a（a 被封锁时有专门处理，见注释）。
3. **派单按取货点批量算**：每个订单只跑一次 BFS（取货点），再对候选机器人 O(1) 查表；
   b、c（送货点到最近充电桩）按 (订单, 封锁版本) 缓存在 `OCACHE`。
4. **占据格计数**（`OCCN`）：基线 `OCC()` 每次 O(R) 扫描，现在 O(1)。移动/停机/救援时同步维护，**改移动逻辑要记得维护 OCCN**。
5. **热点报表用旋转坐标差分**：`u=x+y, v=x-y`，曼哈顿距离 ≤ R 等价于 |du|≤R 且 |dv|≤R，
   二维差分 + 前缀和把 O(W·H·R) 降成 O(W·H+R)。
6. **待派订单用 `std::set` 按 (优先级↓, 到达↑, 编号↑) 排序**：订单号互不相同 → 全序 → 与基线 `std::sort` 结果一致。

## 3. ⚠️ 怪行为清单（基线行为 = 规格，必须保留！SPEC.md 在这些地方是错的）

1. **派单平局取"编号大"的机器人**：基线是 `if (a <= best)`，后面的覆盖前面的。
   SPEC 说"相同取编号小的"，**错**。（`sim.cpp` dispatch，注释有标）
2. **CHARGED 阈值是 90% 不是充满**：基线 `RB*10 >= PRM[0]*9` 就变 IDLE。
3. **RESCUE 只给半血**：基线 `RB = PRM[0]/2`。SPEC 说"电量充满"，**错**。
4. **LATENCY avg 是四舍五入**：`(sum + delivered/2) / delivered`，SPEC 说整数除法，**错**。
5. **取消计数含失败的取消**：CANCEL 指向"存在的订单"就 `cancelled++`，哪怕订单已送达/已取消最后输出 CANCEL_FAIL。
   （`handleEvents` 里 CNT_CANCELLED++ 的位置别挪）
6. **DIST(a,a) == 0**，哪怕 a 是墙或被封锁（基线先判相等再判可通行）。派单时"机器人站在取货点上"的 a 就是 0。
7. **取货/送货点只在下单时校验**：不是墙就在地图内就收单；**之后被 BLOCK 也不退单**，
   机器人会原地等（目标不可通行 → 累计等待 +1）。反过来：机器人站在被封锁的格子上仍可作为 BFS 起点（`distRev` 里有处理）。
8. **移动按机器人编号顺序**，后面的机器人看到前面机器人本 tick 挪完的位置；SIDESTEP 也是。
9. **让路（SIDESTEP）条件**：连续等待 ≥ 4 且"下一步格子"不是目标格；按方向顺序（上右下左）找第一个空邻格。
   让路后仍会做到达判定（让路格子可能是目标格）。
10. **停机的机器人不占格子**；救援成功后重新占据。RESCUE 的条件还包括"所在格没有别的机器人"。
11. **热点统计对所有非墙格**（含被封锁的格子、充电桩），统计所有非 DEAD 机器人。
    全是墙的地图会输出 `hot=-1,-1,-1`（合法输入里机器人至少占一格非墙，但防守时别假设）。
12. **重复订单号**（非法输入）在基线下会把 ORD[id] 覆盖、PEND 里留两份，行为很离谱；
    `check_input.py` 保证订单号互不相同，我们按唯一处理。同理机器人名就是 `R<下标>`。
13. **报表行里 pending= 是待派订单数**，`SUMMARY open=` 是 PENDING/ASSIGNED/PICKED 三种状态的订单数。
14. **事件行首的 tick 用 atoi 解析**；合法输入是标准十进制整数，无需操心，但自测脚本别喂奇怪格式。

## 4. 要改某类逻辑，动哪里

- **派单/分配规则**（需求变更八成会碰）：`sim.cpp` 的 `dispatch()`。
  排序键在 `PendCmp`（`sim.cpp` 上部）；候选条件 = `R_IDLE && battery >= PRM[2]`；
  合格条件 = `a、b、c 都 < INF && battery >= a+b+c+PRM[3]`；选择 = a 最小、平局编号大。
  b、c 的缓存 `OCACHE` 在封锁变化时失效；如果你要引入随时间变化的因素，注意让缓存失效条件跟上。
- **电量/充电**：`RunSim()` 里的充电阶段（90% 阈值）、`goCharge()`（选桩两步走：先挑没被占且够电量的，再退而求最近）、
  `die()`（没电趴窝）。电量是 `Robot::battery`，全整数运算，没有浮点。
- **报表**：`report()`。计数在函数前半段，热点在后半段（差分数组）。
  若改成别的距离度量（比如欧氏），差分公式要跟着换。
- **订单状态机**：`Order::st`；状态流转点分散在 `handleEvents`（下单/取消）、`dispatch`（分配）、
  `arrive`（取货/送达）、`die`（REQUEUE/LOST）。第二阶段的 aging/carryCost（`check_input.py --p2`）
  大概要在这里加钩子：老化可以在 `RunSim()` 每 tick 开头加个阶段，成本规则在 `arrive`/`Finish` 里加。
- **输出格式**：`output.cpp`。注意 `OutLine()` 里的统计分支是按行首关键字匹配的（DELIVER/LOST/REJECT），
  新增会影响 SUMMARY 的日志要记得改统计。

## 5. 风险与防守

- 攻手能看到全部 `src/`（包括本文档），会针对"我以为的边界"构造输入。已知他们最可能打的点：
  1. 被封锁格子上的机器人 / 取货点被封锁（`distRev`、`distSrc` 的边界）；
  2. 反复 BLOCK/UNBLOCK 同一格（缓存失效：只在真实变化时失效，行为正确，但如果你改了封锁逻辑要复测）；
  3. 订单号大小混排（排序按整数，不是字符串）；
  4. 取消各种状态的订单（含重复取消、取消不存在的）；
  5. 全部充电桩被封锁（c = INF，所有派单都失败；去充电两步都找不到桩就不动）；
  6. 反复趴窝-救援（RESCUE 半血 + 格子被占时不能救）、窄通道让路；
  7. reportEvery=1、hotRadius=0/400、lowThreshold=0、chargeRate=batteryMax 这类参数边界。
- 自测工具都在 `work/`：`gen_edge.py` 生成 25 个边界用例，`difftest.py` 与基线逐字节对拍。
  **每次改完代码**：`python tools/bench.py`（5 组公开负载全对）+ `python work/difftest.py work/edge/*.in`。
  有余力再 `python tools/gen.py <配置> <种子>` 换种子多对拍几组。
- 距离缓存的内存上限是 ~256MB（`dist.cpp` 里 `cacheReset`），总体远低于 1GB 上限；
  输出是整块字符串缓冲，最大负载下约几百 MB 以内，安全。
- **不要开多线程**：计时是所有线程 CPU 时间之和，没好处。

## 6. 已知技术债（可接受，但别再欠新的）

- `Evt` 的字段 `a,b,c,d` 含义随类型变化（见 `common.h` 注释），没做成 union 是为了简单。
- 派单里对每个候选机器人做 O(1) 查表，理论最坏 O(待派 × 机器人数) 一 tick；
  实测公开负载和大负载（200×200、300 机器人、20000 tick、20 万事件）都很快。真要再压，可以按电量给候选机器人分桶。
- `Finish()` 里状态转字符串用了三元表达式，订单多时 `open` 要扫全部订单（只在收尾一次，无所谓）。

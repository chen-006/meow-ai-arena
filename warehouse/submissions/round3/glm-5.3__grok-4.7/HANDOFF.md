# HANDOFF —— 给接手的队友

我把仿真重写成等价的快速版（输出与基线逐字节一致已验证：5 组公开负载 + gen.py 换 10 个种子 × 5 配置对拍 + 11 个手工边界用例，全部一致）。主循环七阶段的**语义、日志格式、所有怪行为一律没动**，动的只有"怎么算"。下面是你接手前必须知道的东西。

## 1. 文件结构

| 文件 | 职责 |
|---|---|
| `common.h` | 全部全局变量/枚举/函数声明。**先读它**，每个加速结构都有注释说明维护规则 |
| `main.cpp` | 全局变量定义 + `main()`。变量名与旧版完全相同（RX/RY/RB/RST/ORD/PEND…） |
| `sim.cpp` | `ReadAll` / `RunSim`（主循环）/ `Finish`，七阶段结构与基线一一对应 |
| `util.cpp` | `FIELD` 距离场缓存、`DIST`/`CHG_DIST`/`CHG_NEAR`、`setRST`/`occMove`、`OCC`、日志输出 |

删掉了 `old_stuff.cpp`（旧派单 + 有 bug 的 `bfs_fast_cached`，全是死代码；`USE_NEW_DISPATCH`/`FLAG_FAST_BFS` 开关一并移除）。

## 2. 我做的优化（都不改变输出）

1. **事件分桶**：`ReadAll` 里把事件 SPLIT 一次、按 tick 存进 `EVB[t]`，主循环只看本 tick 的。基线是每 tick 全量扫 EVT 并重新 SPLIT，O(T×E)。事件必须按 `atoi(tick)` 匹配当前 tick，tick<0 或 ≥T 的永远不触发，bucket 逻辑与这个语义完全一致。
2. **统一距离场 `FIELD(sx,sy)`**：基线的 BFS / BFS2 / bfs_fast_cached / CHG_DIST 内部 BFS 四份代码算的是**同一个东西**（起点恒为 0、其余格须 OK 可走）。现在合并成一个按 (起点, 封锁版本) 缓存的距离场；BLOCK/UNBLOCK 真正改动封锁集合时由 `blkAdd/blkRemove` 自动失效。缓存满会整体清空（上限约 160MB，`fieldSetup` 里按地图面积换算）。
3. **派单**：只有 `PEND` 变动（`PEND_DIRTY` 置位）才重建有序快照；排序键预解析成整数（prio 降、arrival 升、订单号数值升）。订单号唯一（check_input 保证），所以是严格全序，任何正确排序结果都和基线一致。订单坐标整数缓存在 `OINT`（`ORD` 仍是规范字符串存储，两者在 ORDER 事件处一起写入）。
4. **状态整数化**：`RSTI`（枚举）是热路径比较用的，`RST`（字符串）只用于输出。**改状态必须走 `setRST(i, ST_*)`**，它会同步两者并维护占格计数 `OCCG`（DEAD 车不占格）。改位置必须走 `occMove`。OCC 由 O(NR) 线性扫变成查网格。
5. **报表热点**：`|dx|+|dy|≤r ⟺ |du|≤r 且 |dv|≤r`（du=x+y, dv=x−y），在旋转坐标系建二维前缀和，每个非墙格 O(1) 查询，代替基线 O(W·H·NR)。**平局规则保持基线原样**：行优先扫描、严格大于才更新（`n > hc`，hc 初值 −1，所以全空地图的热点是第一个非墙格）。若要改热点定义，重写 sim.cpp 第 7 阶段那段即可。
6. **日志**：`writeLog` 不再对每条日志做 SPLIT（前缀判断代替），`I2S` 用 `to_string`，`dumpLog` 攒 1MB 块 fwrite（基线的 `endl` 逐行 flush 是大头）。统计（DELIVER/LOST/REJECT 计数）在 `writeLog` 里，**新增日志类型时记得检查它的前缀统计逻辑**。

## 3. 必须知道的"怪行为"（都是基线原样保留的，别"修"）

- **派单选车用 `a <= best`**：距离并列时取**编号大**的机器人（注释写着"选编号小的"，代码是反的！）。sim.cpp 派单段原样保留。
- **BFS 距离不对称**：起点可以不可走（比如机器人正站在被 BLOCK 的格子上，或死车复活到封锁格上），`dist(a,b) ≠ dist(b,a)`。所以 `DIST` 只有在**两端都可走**时才用对称性查缓存（`FIELD(b)` 处取 `[a]`），否则按基线方向 `FIELD(a)` 算。**这段逻辑测试手一定会测**，改派单时千万别顺手简化。
- 充电"充满了"判据是 `RB*10 >= PRM[0]*9`（九成电就走）；救援在停机 100 tick 后、格子没被别的活车占着时复活，电量给 `PRM[0]/2`。
- `CNT[3]`（取消计数）：只要订单存在就 +1，**即使随后 CANCEL_FAIL**。
- 事件 token 不足我加了防御性 `continue`（基线是越界 UB）；合法输入到不了这些分支。
- `CHG_NEAR` 距离并列取行优先扫描里靠前的桩；派单的 `b`、`c` 被我提出机器人循环（基线惰性计算，但它们是纯函数，等价）。

## 4. 风险点 / 测试手可能测哪里

- **封锁抖动**：BLOCK/UNBLOCK 每次真实变动都清空整个 FIELD 缓存。pub_dynamic 型负载（block=0.25）加速比最低（~3.7x），瓶颈就在这。若要再快，方向是"只失效受影响的场"或增量 BFS，但**先证明等价再动手**。
- **派单 O(P×NR)**：大积压 × 多机器人时每 tick 仍是 P×NR 次数组查（基线是同样次数的 BFS，我们相对仍快）。缓存上限按 200×200 地图设计，隐藏负载上限（W,H≤200, R≤300, T≤20000, E≤200000）内存峰值估算 <300MB。
- 我验证过的对拍脚本在 `work/`（`gen_edge.py` 生成边界用例；gen.py 换种子对拍的 shell 循环见 HANDOFF 外的会话记录），`work/` 不在 src/ 里，交卷不受影响但可参考。

## 5. 第二阶段（p2）提示

`tools/check_input.py --p2` 显示 PARAMS 行末尾会多 `agingEvery carryCost` 两个参数。改法：`ReadAll` 里现在固定读 6 个 `PRM[i]`（token 序列与基线逐个对应，含怪异输入行为）——扩展成读 8 个即可，建议把 `PRM` 扩到 `PRM[8]` 并在 `common.h` 更新注释；派单/电量/报表逻辑都在 sim.cpp 对应阶段里，热点报表是独立代码块，改动互不牵连。新状态直接加进 `STNAME`/枚举尾部即可，`setRST` 会自动处理占格计数。

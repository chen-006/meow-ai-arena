# HANDOFF.md — 给接手的队友

## 这是什么

仓储机器人调度仿真。从 stdin 读场景，把日志写 stdout。本版是我（主程）从混乱基线重写的，
**输出与基线逐字节一致**（已在 5 组公开负载 + 12 组 gen.py 换种子 + 13 组手工边界用例上和基线对拍通过）。
编译：`g++ -O2 -std=c++20 src/*.cpp`（评测机会加 `-static`）。只有 C++ 标准库。

## 文件结构

- `main.cpp`：全部全局变量定义 + main（ReadAll → RunSim → Finish → dumpLog）。
- `common.h`：全局声明、订单/事件结构体、状态枚举。机器人状态和订单状态从基线的字符串改成了枚举
  （`RST`/`Order.status`），输出时经 `RSTATE_NAME` 转回字符串。
- `util.cpp`：BFS 距离场缓存、充电桩查询、占用网格（OCC）、日志写出。
- `sim.cpp`：读输入 + 主循环（7 个阶段，顺序和基线完全一致）+ 收尾统计。
- 基线的 `old_stuff.cpp` 已删除：里面的旧派单和 BFS 缓存都没被线上使用（`USE_NEW_DISPATCH=1`、
  `FLAG_FAST_BFS=0`），是死代码。

## 主循环每个 tick 的顺序（不能换）

1. 事件（ORDER/CANCEL/BLOCK/UNBLOCK）→ 2. 救援 → 3. 充电 → 4. 派单 → 5. 低电量去充电 →
6. 移动 → 7. 报表。阶段之间有隐含依赖（比如派单看到的电量是充完电之后的），改逻辑时别调顺序。

## 优化思路（看懂这些再改代码）

- **事件按 tick 分桶**（`EVTAT`）：基线每 tick 全扫事件表，O(T·E)。
- **BFS 距离场缓存**（`getFieldPtr`，util.cpp）：键是 (x,y)，`BLKVER`（封锁版本号）变了就失效。
  派单、移动寻路、找充电桩全都查它。缓存满 512 项整体清空（只影响速度不影响结果）。
  机器人还有一层 per-robot memo（sim.cpp 里的 `memoF*`），位置不动且 BLKVER 不变就一直复用。
- **充电桩距离场**（`chgField`）：多源 BFS 一次算出"每格到最近可用充电桩"，替代基线每问一次一次 BFS。
- **OCC 占用网格**：`occCnt/occIdx` 数组，O(1)。**机器人每次移动/死亡/救援都要维护它**
  （`occAdd/occRemove`），在 sim.cpp 里搜这两个函数能看到所有维护点，改移动逻辑时必须同步。
- **热点统计**：Manhattan 距离 ≤ r 等价于 (u=x+y, v=x−y) 坐标下的正方形（max(|du|,|dv|) ≤ r），
  用二维差分 + 前缀和，O(NR + (W+H)²)，替代基线 O(W·H·NR)。注意差分数组开了 (S+2)²，
  右边界 u1+1 会到 S+1，别"优化"回 (S+1)²。

## 基线的怪行为（都是特性，别当 bug 修！）

1. **派单机器人并列取编号大的**：`if (a <= best)`（不是 `<`），代码注释说"一样近选编号小的"，是假的。
2. **派单排序第三关键字是 `atoi(订单号)`**：不是字典序（输入保证订单号是 1..1e9 标准整数，所以等价数值序）。
3. **`DIST` 同点直接返回 0**，哪怕目标格被墙/被封；起点不可走时 BFS 照样从起点向外扩（d[start]=0）。
4. **`CHG_DIST` 起点不可走时**：等价于"OK 邻居的距离场值 +1"（基线从起点 0 向外扩的必然结果）。
5. **充电到 90% 就走**（`RB*10 >= PRM[0]*9`），不是充满；救援恢复 `PRM[0]/2`（整数除法）。
6. **CANCEL 计数**：订单存在就先 `CNT[3]++`，哪怕随后因为状态不对输出 `CANCEL_FAIL`。
7. **只有行进状态（TO_PICKUP/DELIVERING/TO_CHARGER）且不在目标上才会因电量 0 趴窝**；
   IDLE/CHARGING 电量 0 不死。TO_CHARGER 趴窝不影响订单。
8. **死人不占格子**（OCC 跳过 DEAD），活人可以踩死人格子；救援要求格子没活人且停机满 100 tick。
9. **让路（SIDESTEP）**：连续等待 ≥4 且最优格被占且最优格不是目标时，挪到第一个"能走且没车"的邻居
   （方向序：上右下左），不管远近；让路也可能正好走到目标上，会触发到达逻辑。
10. **派单在每 tick 开头对 PEND 快照排序**：本 tick 内派出去的单从 PEND 删了，但本轮继续按快照走。
11. **排队充电**：低电量机器人找不到"没被占且电量够到"的桩时，去最近的桩排队（`CHG_NEAR`，
    不看电量不看占用）；一个桩都没有（地图无 'C' 或全被封）就原地待着。
12. **REPORT 热点**：跳过墙格但不跳过封锁格；并列取 y 行优先扫描的第一个（严格 `>` 才更新）。
13. 延迟平均值：`(sum + n/2) / n` 整数除法（四舍五入风格，别改成除法）。

## 性能画像

公开负载合计：基线 ~42s CPU，本版 ~1.0s（约 40 倍）。瓶颈现在主要在 BLK 频繁变化导致的
距离场重算（pub_dynamic 那种封路多的负载）。隐藏负载上限 W,H≤200、R≤300、T≤20000、E≤200000，
本版应该都在秒级。

## 改需求变更时的建议

- 派单逻辑在 sim.cpp "4. 派单" 一节；电量/充电在 "3. 充电" 和 "5."；报表在 "7. 报表"。
- 改了任何会影响"格子能不能走"的状态（比如新的封锁类型），记得递增 `BLKVER`，否则距离场缓存会脏。
- 改了机器人位置/生死，记得维护 `occAdd/occRemove`。
- 新增订单字段直接加在 `Order` 结构体里；别再回到字符串数组。
- 验证方法：`python tools/bench.py`（公开负载），`work/fuzz.py`（换种子 + 边界用例对拍基线，
  需要先用 `g++ -O2 -std=c++20 -static -o work/base.exe baseline/*.cpp` 编出基线）。

## 第 3 轮接手记录（需求变更 + 重新优化）

**需求变更**：`PRM[8]`（多了 agingEvery、carryCost）；派单每 tick 按有效优先级
`prio + (t-arrival)/agingEvery` 重新排序（订单顺序随时间变，不能再缓存排好的顺序）；
行进一步的耗电 `stepCost`（DELIVERING 为 carryCost，其余 1）用于停机判断和扣电（含让路）；
派单电量条件 `RB >= a + b*carryCost + c + margin`（用 long long）；REPORT 加 `aged=`。

**主要优化（util.cpp，距离场）**：原来每次封锁变化（BLKVER++）就让全部距离场作废、整张图重算，
是大负载里的头号开销。现在：
- **惰性 BFS**：`Field` 保存 BFS 队列和进度，只推进到查询够用为止（`fieldDist` 推进到目标格被发现；
  `fieldBestStep` 推进到 4 个邻居的最小值定型为止），之后可以接着算。BFS 内核用扁平数组 + `PASS`
  （非墙且未封锁）字节图，没有边界判断（地图四周是墙是前提）。
- **增量修复**：封锁变化记在 `BLKLOG`，场按版本差逐条重放（落后超过 300 条就整体重置）：
  BLOCK 一个未被发现的格子 → 场不动；BLOCK 已展开的格子 → 若它的每个子节点都有别的同层父节点则场不动，
  否则回退到该格所在层（`fieldRollback`，丢弃更深层，队头退回上一层重新展开）；
  UNBLOCK → 若邻居里有已发现的，回退到 min(邻居)+1 层。被封但留在场里的旧节点（d 是旧值）
  在 `fieldStep` 里被弹出时不再向外扩，读取处都先判 `OK()`，所以不会被用到。
- 回退/重放时的"别的父节点是否可通行"必须用该条变化发生时的 `PASS`，所以重放前先把 `PASS` 倒回再顺着放。
- 派单：不再给机器人缓存 memo；`idleLeft`（可接单机器人都派完）后直接停止扫描剩余订单。

**失效条件 / 注意**：场缓存按内存上限（约 300MB）满了整体清空（只影响速度）；地图四周必须是墙（BFS 不判边界）。改动 PASS/BLK 必须同时记 `BLKLOG` 并 `BLKVER++`
（见 sim.cpp 的 BLOCK/UNBLOCK 处）。

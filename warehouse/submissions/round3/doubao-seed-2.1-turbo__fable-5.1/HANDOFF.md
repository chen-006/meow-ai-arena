## 三、优化机制（按收益排序）

### 3.1 距离场缓存池 + "陈旧距离场仍可用"判定（`util.cpp`，核心）
- 所有距离都来自"从某格出发的 BFS 距离场"（语义同基线 `BFS`：起点距离 0 且**不论是否可通行都向外扩展**，之后只进入可通行格）。
  派单里 `a`（机器人→取货点）利用对称性复用取货点的场；机器人站在封锁格上时按基线从机器人出发算（不对称）。
- 缓存池：每格一个槽（uint16 距离表，轮转淘汰，总量 ~48MB），记录计算时的封锁版本 `BLK_VER`。
- **封锁变化后不立刻重算**。`setBlocked` 把每次变更记进 `CHLOG`；查询时按日志判断旧场在"需要的格子"上是否仍精确：
  - UNBLOCK 的格子 c：若 c 的某个邻格 F < val，经 c 可能出现更短路径 → 重算；
  - BLOCK 的格子 c：若 F[c] < val（落在查询格的"球"内），则沿 F 梯度（每步 −1、当前可通行）从查询格走回起点；走得通说明长度 val 的路径仍在 → 仍精确；走不通 → 重算。
  - 不变式：满足上述 UNBLOCK 规则时，任意格真实距离 ≥ min(F, val+1)，所以 F > val 的格子不会"掺进"最小值。
  - 版本差超过 `MAX_GAP=256` 直接重算。
- **截断 BFS**：移动阶段只需要机器人四邻格的距离，`fieldForMove` 把四邻格作为"观察格"，BFS 到观察格的最小距离层就停（`SLOT_LIM` 记录半径）。
  截断表里 INF 代表"未知"：`distFrom` 遇到 INF 且表是截断的，会重算完整表。
- 重算时只清上次发现过的格子（`SLOT_LIST`），不整表 memset。

### 3.2 多源充电桩距离场
- 基线 `CHG_DIST(d)` = 从 d 出发到最近可通行充电桩。对可通行的 d，等价于"从所有可通行充电桩出发的多源 BFS"在 d 的值，一张表服务所有订单。
- d 不可通行时（只会在 p == d 的怪情况出现）按"邻格值 + 1"算。
- 失效判定同 3.1，另外 UNBLOCK 一个充电桩会新增源，必须重算。

### 3.3 派单
- 没有"IDLE 且电量 ≥ 低电量阈值"的机器人时整个阶段无副作用，直接跳过（flood 负载的主要节省）。
- 排序改为 `make_heap` + 逐个 `pop_heap`，候选机器人用完就停，不用把 PEND 全排完。
- `b`、`c` 按封锁版本缓存在 `Order` 里；`b×carryCost + c + margin > 满电` 的订单直接跳过。

### 3.4 其它
- `OCC` 用每格活机器人计数 `OCC_CNT`（DEAD 不计）O(1)。
- 报表热点用逐行差分数组：每个活机器人的曼哈顿菱形拆成行区间，O(R×radius + W×H)。
- 事件预解析一次；输出攒在 `OUTBUF` 一次 `fwrite`（文本模式，行尾与基线一样是 `\r\n`，评测比较前会归一化）。

## 四、失效条件 / 性能退化场景
- 封锁极其频繁且集中在机器人路径上（每 tick 多个 BLOCK 落在各机器人的最短路上）→ 梯度验证失败，退化为每 tick 每机器人一次截断 BFS（仍比基线快很多）。
- 同时存活的不同目标格 / 取货点超过缓存池槽数（≈ 48MB / (2×W×H)，200×200 地图约 600 槽）→ 轮转淘汰导致重复 BFS。
- 版本差超过 `MAX_GAP` 的旧场一律重算（只影响长期不动又很久没被查询的场）。

## 五、保留的基线怪行为（别"修"）
1. 派单选机器人 `a <= best`：同距离取编号大的。
2. `DIST(a,b)`：b 不可通行直接 BIGNUM；a 不可通行仍从 a 向外扩展。
3. `CANCEL` 对任何已存在订单都 `CNT[3]++`，即使最终 `CANCEL_FAIL`。
4. 充电 `RB*10 >= max*9` 即视为充满；救援恢复 `max/2`。
5. 热点取行优先第一个最大值；DEAD 机器人不计。
6. 走阶段的顺序：先到达判定 → 电量不够则 DEAD → 目标被封等待 → 邻格最小 → 占用/让路。

## 七、本轮结果与未完成的想法
- `--big`（本机，有其它程序同时运行，时间有波动）：flood ≈ 311×，dynamic ≈ 69×，crowded ≈ 134×。
- 剩余的 BFS 主要来自 UNBLOCK 规则偏保守（解封格落在"球"内就重算）。尝试过"解封格的可通行邻格 F 值相差 ≤ 2 则不会制造捷径"的放宽规则，
  **有漏洞已回退**：解封格本身可能恰好是机器人的邻格（它的 F 是 INF 但真实距离很小，会漏进候选），而且后续变更检查会把它当成不可达。
  要再做需要：(1) 查询时把机器人四邻格 / 查询格本身排除在放宽规则之外；(2) 对日志里已按放宽规则放行的解封格记录其距离下界，后续规则用下界而不是 F=INF。
- 其它可做：BFS 用带哨兵的填充网格去掉 `nc < 0` 判断；派单堆改成增量维护。

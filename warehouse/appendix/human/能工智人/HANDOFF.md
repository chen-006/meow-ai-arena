## 2. 已完成的关键优化（及实现原理）

### 优化 1：订单管理 `PEND` 数据结构重构（从 $O(N \log N)$ 排序到动态维护）
- **原实现**：每 tick 将所有处于 `PENDING` 状态的订单放入 `vector<string>` 并调用 `sort()`，开销巨大。
- **优化后**：使用 `std::set<string, OrderCmp> PEND`。订单到来时 $O(\log N)$ 插入，订单被派发或取消时 $O(\log N)$ 移除。
- **保真要点**：严格保持基线的比较逻辑（优先级高者优先；优先级相同时到达时间早者优先；仍相同时字典序小的订单号优先）。

### 优化 2：订单数据从全字符串转原生结构体 `struct Order`
- **原实现**：`unordered_map<string, vector<string>> ORD`，每次访问坐标、电量、优先级都需要频繁调用 `atoi`/`S2I`/`I2S`。
- **优化后**：在 `common.h` 中定义 `struct Order`，直接以 `int` 存储 `px, py, dx, dy, prio, arrival`，消除运行时的字符串解析与序列化开销。

### 优化 3：寻路重构为双向 A*（Bidirectional A*）+ 版本戳零内存分配
- **原实现**：每次调用 `DIST(ax, ay, bx, by)` 均在堆上分配二维 `vector<vector<int>>` 进行全图 BFS 泛洪。
- **优化后**：
  - 采用 **双向 A\***，以曼哈顿距离 $L_1$ 为启发函数，正向反向交替推进。
  - 使用静态平坦数组 `s_distF`, `s_distB` 和 `s_tagF`, `s_tagB`，借助单调递增的版本戳 `s_epoch` 区分搜索轮次，**单次寻路 0 堆内存分配，0 `memset` 开销**。
  - 充电桩距离 `CHG_DIST` / `CHG_NEAR` 复用 `DIST` 并引入曼哈顿距离下界剪枝（若曼哈顿距离已 $\ge best$ 则直接 break）。

### 优化 4：全图连通分量 $O(1)$ 快速判定（`s_comp`）
- **原实现**：面对不可达的终点时，BFS 会把整个连通区域甚至整张地图搜穿才发现不可达。
- **优化后**：
  - 在 `src/util.cpp` 中维护 `s_comp` 静态染色数组。
  - 仅在地图出现动态障碍变更（`BLOCK` / `UNBLOCK`）或首次启动时标记 `s_compDirty`，采用单次 $O(W \times H)$ 扫描更新连通块编号。
  - 在 `DIST(ax, ay, bx, by)` 入口处，若两点连通分量不同，直接在 $O(1)$ 时间内返回 `BIGNUM`。此改动在连通受阻用例（如 `pub_flood`）上提速 2.4 倍。

### 优化 5：派单循环不变量惰性求值（Lazy Evaluation）
- **原实现**：对每个待派订单，内层循环遍历所有可用机器人；在判断机器人电量时多次重复计算 `b = DIST(px, py, dx, dy)` 与 `c = CHG_DIST(dx, dy)`。
- **优化后**：在发现第一个空闲机器人时才对 `b` 和 `c` 进行计算，单次订单循环内复用。若 `b >= BIGNUM` 或 `c >= BIGNUM`（说明取送点或充电桩不可达），立即 `break` 放弃该订单，避免无谓计算。

### 优化 6：BFS 缓存加速启用与生命周期修复
- 启用了 `#define FLAG_FAST_BFS 1`，并在地图障碍物更新和每次模拟开始时通过 `clearBfsCache()` 联动调用 `markCompDirty()`，确保无陈旧脏数据。

## 3. 基线代码的“怪异行为”与防击穿红线（高危避坑！）

在修改代码时请千万注意以下几个与常规直觉不符的**基线怪异行为**，任何修改若破坏了这些行为，均会导致攻手击穿：

1. **派单平手判定（Tie-breaking）实际上是“后到者胜”！**
   - 基线中的注释声称“小车编号越小越优先”，但是其实际代码写的是：
     ```cpp
     if (a <= best) { best = a; who = i; }
     ```
   - **注意是 `<=` 而不是 `<`**！这意味着如果两个小车距离一样，**编号更大的小车会替换先前的结果**！这个规则必须原样保留，绝对不要改成 `<`。
2. **起点受阻时的非对称寻路语义**：
   - 如果起点 `(ax, ay)` 恰好被动态障碍物 `BLOCK` 阻挡，基线的 BFS **仍然会将起点入队并扩展其合法相邻格**！
   - 我们的双向 A* 中对 `!OK(ax, ay)` 专门做了反向允许进入起点的判定，保留了此行为。
3. **`DEAD` 状态小车的处理**：
   - 小车电量耗尽或损坏进入 `DEAD` 状态后，在占用检测 `OCC` 中不视为阻挡格，派单时也绝对不能分配任务给 `DEAD` 车。
4. **返回值与常量一致性**：
   - 不可达时必须严格返回 `BIGNUM`（不能返回 -1，因为上层有 `b + c` 的加法判断）。

## 4. 需求变更修改指引（你想改哪类逻辑该动哪里）

如果你在接手后需要增加或变更业务逻辑，请参照以下路径修改：

### A. 修改派单逻辑（如新的优先级规则、轮询策略、分配算法）
- **位置**：`src/sim.cpp` 中的 `RunSim()` 函数，查找注释 `// 派单`。
- **注意**：
  - 遍历待处理订单时使用 `for (auto it = PEND.begin(); it != PEND.end(); )`。
  - 若需要修改订单排序规则，请修改 `src/common.h` 中的 `struct OrderCmp`。

### B. 修改电量计算或充电策略
- **位置**：`src/sim.cpp` 中的充电检查和电量扣减部分。
- **相关工具**：`CHG_DIST` 和 `CHG_NEAR` 位于 `src/util.cpp`。

### C. 增加或修改输出报表
- **位置**：
  - 每个 tick 的事件打印：`src/sim.cpp` 中搜索 `cout << ...`。
  - 仿真结束时的汇总报表：`src/sim.cpp` 尾部的统计与输出部分。

# 回放格式（.wrp）

版本：**1**（2026-11-11 定）。以后要改，只往后加字段或加事件，不改已有字段的含义；真要改布局就把版本号加一，并在本文末尾"改动记录"里写清楚。

读取的参考实现：`工具\读回放.py`（Python，约 150 行，含一个画俯视图的小函数）。示例回放在 `示例回放\`。

## 1. 整体结构

一个二进制文件，小端序。开头 11 个字节是 `WARREPLAY1\n`，后面是一串"块"：

```
[4 字节标签][4 字节无符号长度 n][n 字节内容]
```

| 标签 | 内容 | 出现几次 |
|---|---|---|
| `META` | UTF-8 JSON：地图、座位、开场的全部物体、数值表（第 2 节） | 1 次，在最前面 |
| `FRAM` | 二进制：一帧里所有物体的位置、朝向、状态（第 3 节） | 每隔 `rec_every` 步一帧 |
| `EVNT` | UTF-8 JSON 数组：这段时间里发生的事件（第 4 节） | 有事件时出现，在它覆盖的那几步之后、下一帧之前 |
| `RSLT` | UTF-8 JSON：这一场的结果，和 `war.exe run` 输出的结果一样（第 5 节） | 1 次 |
| `ENDR` | 空，表示文件结束 | 1 次 |

时间：物理每秒 60 步（`dt` = 1/60 秒）。"步"是整数时间轴，帧和事件都按步标。默认每 2 步记一帧（30 帧每秒）；`war.exe run --rec-every 1` 可以每步一帧。第一帧是第 0 步（开打之前的摆阵），最后一帧是结束那一步。

不认识的块标签直接跳过（按长度往后跳）。

## 2. META

```json
{
  "format": "war-replay", "version": 1,
  "dt": 0.016666668, "rec_every": 2, "decide_every": 6, "time_limit_steps": 5400,
  "mode": "duel",               // duel 1v1 | melee 四人混战 | level 闯关 | sandbox 测试
  "map_name": "樱丘", "theme": "春樱",
  "seats": [ {"seat":0, "team":0, "origin":[0,-28], "yaw":0.0, "name":"示例指挥", "deploy_ok":true}, ... ],
  "objects": [ ... 开场就有的物体，见下 ... ],
  "scenario": "……地图/关卡文件原文（JSON 字符串，要再 parse 一次）……",
  "nav": {"x0":-38, "z0":-31, "cell":0.5, "w":152, "h":124},
  "params": {"rules": {...}, "units": {...}}   // 这一场用的全部数值（含 --cfg 改过的）
}
```

**objects** 里每个开场物体一条：

| 字段 | 单位 `type:"unit"` | 道具 `type:"prop"` |
|---|---|---|
| `id` | 物体编号（全场唯一，帧和事件都用它） | 同左 |
| `kind` | 兵种英文名：`militia` 新兵、`shield` 盾卫、`spear` 长枪兵、`archer` 弓手、`cavalry` 骑兵、`hammer` 大锤、`bomber` 炮仗兵、`catapult` 投石车、`giant` 大块头、`boss` 镇山兽、`lord` 主帅 | `snowball` 雪球、`keg` 火药桶、`flag` 军旗、`barrier` 木栅、`gate` 木栅门、`pillar` 立石 |
| `team` | 属于哪一方（0 起；闯关里选手是 0、主办方是 1） | 军旗属于哪方；其他 -1 |
| `seat` | 哪个座位的指挥程序管它（-1 = 主办方） | — |
| `hp` | 满血 | 满血（立石是一个很大的数，表示打不坏） |
| `scale` | 体型缩放（大块头 3.2，其余 1） | — |
| `r`、`size`、`yaw` | — | 雪球、火药桶的半径；木栅、门、立石的长宽高（米）和朝向 |
| `pos`、`yaw` | 开场脚底位置、朝向 | 开场位置（底面中心） |
| `tag` | 布阵文件或关卡文件里起的标签 | 同左 |

**地形**不在帧里（它不动）：从 `scenario` 原文的 `terrain` 数组画。图元有 `box`（`min`/`max` 或 `c`/`h`，可带 `yaw` 度）、`ramp`（从 `from` 到 `to` 的斜坡，宽 `width`，两端顶面高 `h0`、`h1`，底 `base`）、`cyl`（圆柱，`c`、`r`、`y0`、`y1`）、`mound`（圆台，底半径 `r0` 在 `y0`、顶半径 `r1` 在 `y1`）、`hull`（凸包顶点），每个带 `mat`（材质名，渲染自己定颜色和贴图；`edge` 是地图四周的围墙，可以画成篱笆或不画）和可选的 `tag`。带 `tag` 的图元可能在比赛中被移除（例如第 2 关的 `桥中段`），见事件 `terrain_removed`。`water` 是水面（固定高度或随时间涨的潮水）；`zones` 是区域（计分区、泥塘、出口）。泥塘可能带 `stick_secs`（11-11 起，"脚上带泥"：离开泥塘后这么多秒内仍按泥里的速度走）；帧里没有单独的"带泥"标记（flags 的 8 位都用了），画面要表现的话按位置自己推：身体中心最后一次在泥塘里的那一帧之后 `stick_secs` 秒内算带泥。格式版本不变。详细字段见 `接口说明.md` 第 5 节。

## 3. FRAM（一帧）

```
u32 step        这一帧是第几步
u32 count       后面有几条记录
count × 32 字节的记录
```

每条记录（32 字节）：

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | u32 | id | 物体编号 |
| 4 | u8 | otype | 1 单位、2 石头、3 道具、4 箭 |
| 5 | u8 | state | 见下表 |
| 6 | u8 | flags | 位标记，见下表（只对单位有意义） |
| 7 | u8 | team | 0、1、2、3；255 = 中立 |
| 8 | u16 | hp | 当前血量，向上取整 |
| 10 | u16 | aux | 附加值，见下表 |
| 12 | f32×3 | x, y, z | 位置（米）。单位和投石车 = 脚底中心；石头、雪球 = 球心；箭 = 箭头；火药桶、军旗、木栅、门、立石 = 底面中心 |
| 24 | i16×4 | qx, qy, qz, qw | 朝向四元数，每个分量 × 32767 存成整数（读的时候除以 32767） |

一个物体从哪一帧开始出现、到哪一帧不再出现，就是它在场上的时间。不出现在某帧里 = 已经不在场上（尸体消失、箭消失、石头消失、道具被毁）。

**state**

| otype | state |
|---|---|
| 单位 | 0 站着、1 倒地、2 正在起身、3 阵亡（尸体还在场上，会被撞、被炸飞） |
| 石头 | 0 在飞或在滚、1 停住了 |
| 箭 | 0 在飞、1 插在地上或墙上 |
| 道具 | 0 正常；1 雪球已松开在滚 / 火药桶已点着（0.6 秒后炸） |

**flags**（单位）

| 位 | 值 | 含义 |
|---|---|---|
| 0 | 1 | 正在起手（挥砍、拉弓、甩头）；起手进度见 aux |
| 1 | 2 | 长枪兵已架好枪 |
| 2 | 4 | 炮仗兵已点火 |
| 3 | 8 | 原地守 |
| 4 | 16 | 在自己走（有走路速度；渲染补走路摆腿用） |
| 5 | 32 | 冲锋中（骑兵速度超过 3.5 米/秒，或镇山兽在冲撞） |
| 6 | 64 | 盾卫站着（盾举在正面） |
| 7 | 128 | 腾空：脚离地 0.4 米以上或竖直速度很大（被击飞、掉下去、翻墙） |

**aux**

| 对象 | aux |
|---|---|
| 单位，正在起手 | 起手进度 0～1000（1000 = 这一下马上落下） |
| 投石车 | 离下一发还有几步 |
| 道具 | 道具种类：0 雪球、1 火药桶、2 军旗、3 木栅、4 木栅门、5 立石 |
| 其他 | 0 |

**投石车**的四元数是它瞄准的方向（它本身不会动）；木栅、门、立石的四元数是盒子的朝向；箭的四元数把 +z 转到飞行方向。

### 3.1 渲染要的"姿态"怎么从这些字段推出来

| 姿态 | 判断 |
|---|---|
| 站立 | state 0，没有 16、1 |
| 走路 | state 0 且 flags 有 16（速度可以用相邻两帧的位置差算） |
| 攻击 | flags 有 1：用 aux 的进度放挥砍动作；落下那一刻对应事件 `strike` / `shoot` |
| 被击飞 | state 1 且 flags 有 128（人在空中翻滚，刚体的四元数就是真实的翻滚） |
| 倒地 | state 1 且没有 128 |
| 起身 | state 2 |
| 死亡 | state 3（尸体照常有位置和朝向；坠崖、淹死的另有事件） |

刚体本身的位置和四元数已经包含了倒地翻滚、被撞飞、尸体堆叠，渲染不需要另外演；只需要按"走路""攻击"两种状态补肢体动作。

## 4. EVNT（事件）

每块是一个 JSON 数组，每个事件是一个对象，必有 `s`（第几步）和 `t`（种类）。编号字段（`u`、`a`、`v` 等）都是物体编号；-1 表示"没有"。

| t | 字段 | 含义 |
|---|---|---|
| `swing` | u, target, dagger | 近战起手（dagger=1 是弓手的匕首） |
| `draw` | u, target | 弓手拉弓 |
| `strike` | u, n, w | 近战落下，打中 n 个；w 是武器（militia/shield/spear/cavalry/hammer/sweep/boss/dagger） |
| `shoot` | u, arrow, team, p, v | 放箭：新箭的编号、出手点、初速（之后每帧都有这支箭） |
| `launch` | u, stone, p, v, aim | 投石车发石头：新石头的编号、出手点、初速、瞄的落点 |
| `hit` | a, v, w, dmg, blk, ff | 谁打中谁、用什么（arrow/stone/explosion/charge/brace/snowball/boss_charge/prop/近战武器）、伤害、被盾挡了没有、是不是误伤自己人 |
| `stone_hit` | stone, v, speed | 石头砸中人 |
| `snowball_hit` | ball, v, speed | 雪球撞到人 |
| `knock` | u, why | 被打倒（why = 武器名，或 `topple` 被挤倒） |
| `getup` / `stand` | u | 开始起身 / 站稳 |
| `climb` | u, h | 翻矮墙（往上跳 h 米） |
| `brace` | u, v, speed | 长枪架枪迎击：枪兵 u 戳中冲过来的 v |
| `fuse` | u, by | 炮仗兵或火药桶点着了（0.6 秒后爆） |
| `explode` | src, p, by | 爆炸：来源（炮仗兵或火药桶的编号）、爆心位置、算在谁头上 |
| `death` | u, cause, killer, kteam | 阵亡：死因（武器名，或 `fell` 坠落、`drown` 淹死、`explode` 自己炸了）、最后一击的单位和它的阵营 |
| `fell` / `drown` | u | 掉出地图 / 掉进水里（紧接着有 death）；11-11 起投石车被潮水淹到也有 `drown` |
| `remove` | u, hit? | 物体离场（尸体到时间、箭插中人或消失、石头停稳消失、炸掉的炮仗兵） |
| `release` | u, by | 雪球被推下去或被敲下去 |
| `destroyed` | u, kind, tag, why | 道具毁了：火药桶炸了、军旗倒了、木栅或门碎了、立石碎了 |
| `terrain_removed` | tag | 带这个标签的地形图元被移除（第 2 关"桥断"） |
| `reroute` | u | 行军的敌人改走备用路线 |
| `rally_go` | tag, why, n | 改道的敌人从集结点出发（11-11 全歼改版加）：tag 是触发改道的地形标签，why = `gathered`（人到齐了）/ `time`（等够了时间）/ `sortie`（集结时挨了够不着的远程攻击），n = 出发的人数 |
| `sortie` | u, squad, by, n | 主办方的一队守军出击（11-11 全歼改版加）：u 是挨打的那个守军，squad 是队名，by 是打他的人，n 是这一次改成出击的人数。画面可以在这一刻给这一队一个"冲出来"的表现 |
| `boss_state` | u, state, dx, dz | 镇山兽换状态：0 游走、1 刨地、2 冲撞（dx,dz 是锁定方向）、3 晕 |
| `boss_stun` | u | 镇山兽撞上立石、石墙或门 |
| `pillar_hit` | u, hits | 立石被撞了第几次 |
| `boss_fall` | u | 镇山兽冲出台地边缘（坠崖） |
| `fault` | seat, kind, detail, fatal | 指挥程序出了问题（超时、非法输出、崩溃）；fatal=1 表示程序没了，此后不再下新指令，兵各自保持最后一条指令（11-11 起；之前是改回默认行为）。kind=invalid 且 detail 以"丢掉 N 行"开头 = 这一回合丢掉的多余输出行 |
| `eliminated` | team | 某一方全灭 |
| `end` | winner, reason | 比赛结束：闯关里 winner 0 = 过关、-1 = 没过；对抗里是胜方阵营，-1 = 平 |

## 5. RSLT

和 `war.exe run` 打印的结果 JSON 一样（字段说明见 `接口说明.md` 第 6 节）：模式、地图、胜负和原因、每一方剩多少兵多少造价、计分区造价、歼敌造价、混战名次和得分、闯关的关键数（军旗血量、带标签的目标还剩几个、主帅和镇山兽的血）、物理统计。

## 6. 坐标系

- 右手系，**y 朝上**，单位米。朝向（yaw）0 = 面朝 +z，正值往 +x 转。四元数是 Jolt 的约定（x, y, z, w）。
- 设计稿配图是"x 向右、z 向上"的俯视图。要让画面和配图一样（甲方在下面、x 向右），导入 Blender（z 朝上的右手系）时用 **Blender (X, Y, Z) = (x, z, y)**，四元数换成 **(qx', qy', qz', qw') = (−qx, −qz, −qy, qw)**（这是一次镜像，两步一起做朝向才对）。这样每一方"我方视角"的 +x 在画面上就是他自己的右手边。
- 单位的模型原点在脚底中心，面朝 +z。骑兵是人马一体（马头朝 +z），大块头是普通人形放大 3.2 倍，镇山兽是 2.6 × 2.6 × 4.8 米、头朝 +z。各兵种的碰撞形状（几个方块拼成）见 `src\sim.cpp` 的 `humanShape`、`cavShape`、`bossShape`，渲染可以照着做体素模型，也可以只对齐大小。

## 7. 大小

60 秒、80 个单位、每 2 步一帧，约 2 MB。主要是箭（每支箭在场上 4～6 秒）。

## 改动记录

- 版本 1（11-11）：首版。
- 11-11（按常识审读改引擎，版本号不变，没有新增或删掉字段）：① 同一步里的打击统一在这一步末尾生效，所以同一步的 `hit` 事件都排在 `death`、`knock` 之前，一个人在同一步里可能连挨好几下（原来死了以后的那几下不记）；`death` 的 cause 是这一步最重的那一下的武器，killer 是这一步打他最重的人。② `hit` 的 v 可以是军旗（箭、石头、爆炸都会伤到旗，不分敌我）。③ RSLT 和 `end` 的 reason 多了 `timeout_cost`（1v1 时间到、山头上双方都没人，按全场剩余造价判）。④ META 的 params 多了 `flag_hit_mul`。
- 11-11（全歼改版，版本号不变，只加了事件）：新增 `sortie`（守军全队出击）、`rally_go`（改道的敌人从集结点出发）两种事件，旧的读回放程序遇到不认识的事件类型跳过即可。`boss_fall` 还在，但五关里已经没有能掉下去的豁口，正常不会出现。

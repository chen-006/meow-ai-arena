# 《纸上谈兵》接口说明

这份说明讲"怎么用工具"：本地怎么跑一场、布阵文件怎么写、指挥程序怎么接、关卡文件里哪些字段要看懂。
各关的规则（敌军、过关条件、机关）写在规则文档和关卡文件的 `desc` 里，这里不重复。

本地的 `war.exe` 就是裁判用的同一个模拟器。战斗完全确定：没有随机数，同一份布阵和同一个程序，每次跑出来的结果一模一样。

---

## 1. 本地跑一场

### 1.1 跑一关

```
war.exe run 关卡\第3关_拔炮台.json --deploy level3.json --cmd commander.exe
```

- `--deploy`：你的布阵文件。
- `--cmd`：你编好的指挥程序。不写程序就写 `--cmd -`，兵按布阵文件里的姿态和默认行为打。
- 一场不到一秒到几秒。

常用选项：

| 选项 | 作用 |
|---|---|
| `--json 结果.json` | 结果写进文件（不写就打印到标准输出） |
| `--replay 回放.wrp` | 存回放 |
| `--stderr-dir 目录` | 把你的程序写到标准错误的内容存进这个目录（`g0_p0.txt`），调试用 |
| `--secs 30` | 只跑前 30 秒（试开局用；结果按"时间到"判） |
| `--match-wall-s 120` | 一场的墙上时钟上限（秒，默认 120；`0` = 不设）。正常一场一两秒，到点还没跑完说明引擎出了毛病，这一场记成 `engine_timeout`（见下）。用调试器单步跟自己的程序时可以设成 `0` |

**退出码**（方便写脚本）：`0` 过关，`1` 没过，`3` 布阵不合法，`2` 命令行或文件有错，`4` 引擎超时（`engine_timeout`）。

**引擎超时**：一场超过 `--match-wall-s` 秒还没跑完时，引擎结束这一场的指挥程序，结果写成
`{"id":0,"error":"engine_timeout","detail":"这一场超过墙上时钟上限 120 秒还没跑完……","match_wall_s":120}`，没有胜负，退出码 4。
这是引擎自己的错误，遇到请把布阵和程序发给主办方。正常的指挥程序不会触发它：每回合 CPU 上限 20 毫秒（第 3.2 节），
每回合都用满，一整场也只有二三十秒。

标准错误最后一行是一句话的摘要，例如：

```
战场 第3关_拔炮台（level）2899 步 = 48.3 秒  过关（win:destroy:炮台）  0 方剩 2/9  1 方剩 26/29  造价 90  炮台 还剩 0/3
```

### 1.2 结果 JSON 里要看的字段

| 字段 | 含义 |
|---|---|
| `passed` | 过没过 |
| `reason` | 怎么结束的：`win:eliminate`（全歼）、`win:destroy:<标签>`（拆掉/打倒带这个标签的目标）、`win:reach` 和 `timeout_win`（关卡文件里写了"走到某处"或"时间到算赢"才会出现，目前五关都没有）、`lose:destroy:军旗`、`lose:dead:主帅`、`timeout_lose`（时间到没达成）、`eliminated`（我方全灭，场上的石头、雪球、炮仗都停了以后还没赢） |
| `secs` | 比赛用了几秒 |
| `teams[0]` / `teams[1]` | 我方 / 敌方：`start_units`、`alive_units`、`start_cost`、`alive_cost` |
| `seats[0].deploy_cost` | 你的造价 |
| `seats[0].deploy_ok`、`deploy_errors` | 布阵合不合法、哪里不合法 |
| `seats[0].faults` | 程序出的问题（超时、崩溃、看不懂的指令、丢掉的多余输出行），每条带发生在第几步 |
| `seats[0].ignored_orders` | 被忽略的指令条数（对死人、别人的兵下令，兵种不支持这条指令等） |
| `level_info` | 这一关的关键数：`tags`（每个标签还剩几个，例如 `炮台`、`护卫`、`东门`）、`flags`（军旗血量）、`boss_hp` |
| `winner`（1v1、混战） | 1v1 的胜方座位，`-1` = 平。`reason`：`annihilation`（一方全灭；同时全灭算平）、`timeout_zone`（时间到，"山头"计分区里活着的兵造价多的一方胜）、`timeout_cost`（时间到、山头上双方都没有兵，全场剩下的兵造价多的一方胜）、`timeout_draw`（时间到，以上都一样） |
| `commanders[0]` | 程序的运行情况：`status`（`ok` / `crash` / `lost` / `timeout_limit` / `output_limit` / `start_fail`）、`timeouts`、`invalid`（看不懂的应答和丢掉的多余输出行，一共几行）、`avg_ms`、`max_ms` |

### 1.3 检查布阵、批量跑、查数值

```
war.exe check 关卡\第5关_镇山兽.json level5.json
```
打印 `{"ok":true,"units":10,"cost":250,"budget":550,"max_units":60,"count_by_type":{…},"errors":[]}`。合法退出码 0，不合法 1。

```
war.exe batch --workers 8 < 任务.txt
```
任务文件每行一个 JSON：`{"id":1,"map":"关卡\\第1关_草甸迎击.json","deploys":["a.json"],"cmds":["commander.exe"]}`，
可选 `"replay"`、`"secs"`。每跑完一场打印一行结果 JSON（带 `id`），顺序不保证。适合一次试很多种布阵。
`--match-wall-s` 对 batch 里的每一场分别算：超时的那一场打印 `{"id":…,"error":"engine_timeout",…}`，其他场次照常跑完；
出错的场次（地图读不了、布阵数量不对、引擎超时）都是带 `"error"` 字段的一行。

```
war.exe info
```
打印全部兵种数值和规则常数（JSON）。下面第 4 节的表就是从这里摘的。

## 2. 布阵文件

```json
{ "units": [
    { "type": "盾卫",   "x": -1.0, "z": 3.0, "stance": "原地守", "tag": "塞子" },
    { "type": "长枪兵", "x": -1.0, "z": 2.0, "stance": "原地守", "tag": "塞子" },
    { "type": "弓手",   "x":  4.5, "z": 0.5, "tag": "点名组" }
] }
```

| 字段 | 说明 |
|---|---|
| `type` | 兵种中文名（`新兵 盾卫 长枪兵 弓手 骑兵 大锤 炮仗兵 投石车 大块头`），也认英文 id（`militia shield spear archer cavalry hammer bomber catapult giant`） |
| `x`、`z` | 我方视角坐标（见下），**必须是 0.5 的整数倍** |
| `stance` | 开场姿态，`"自由"`（默认行为，不写就是它）或 `"原地守"` |
| `tag` | 随便起的标签，程序里按它找人。最长 32 字节，不能有空白 |

**我方视角坐标**：x 向右，z 朝敌人，单位米。每关的布阵区写在关卡文件 `seats[0].deploy` 里，是几个矩形 `[x0, z0, x1, z1]`（也是我方视角，边界算在里面）。指挥程序里看到的坐标也全是这个视角。

**合法的条件**（`war check` 会逐条报出来）：

- 每个兵都在某一块布阵区里，坐标是 0.5 的整数倍；
- 兵种认识、而且是能买的（镇山兽、主帅不能买）；
- 总造价不超过 `budget`，人数不超过 `max_units`，至少 1 个兵；
- 两个兵的占地矩形不重叠。占地（半宽 × 半长，米）：步兵类（新兵、盾卫、长枪兵、弓手、大锤、炮仗兵）0.25 × 0.25，所以挨着站隔 0.5 米就行；骑兵 0.4 × 1.1（前后要隔 2.5 米以上）；投石车 1.1 × 1.5；大块头 0.8 × 0.5；
- 关卡文件里写了限购（`seats[0].limits`）时，不超过限购数量。目前五关都没有限购。

不合法的布阵这一关不开打，判 0 分。主帅（第 4 关）不写进布阵文件，他的起点由关卡定。

## 3. 指挥程序

### 3.1 写法和编译

单个 C++17 文件，包含 `commander.hpp`，写两个函数：

```cpp
#include "commander.hpp"

void on_start(Game& g) {
    // 开局调用一次。这时已经收到第一回合的状态，g.units / g.props 都有内容
}

void on_tick(Game& g) {
    // 每 0.1 秒调用一次，在这里下指令
    for (Unit* u : g.by_tag("点名组")) {
        Unit* e = g.nearest_enemy(u->x, u->z);
        if (e && u->order != 打) g.attack(u->id, e->id);
    }
}
```

```
g++ -O2 -std=c++17 -static -I 引擎\commander commander.cpp -o commander.exe
```

`commander.hpp` 里已经有 `main()`，不要自己写。同一个程序打所有场次，用 `g.mode`（`"level"` 闯关、`"duel"` 1v1、`"melee"` 混战）和 `g.map`（地图名，例如 `"第3关_拔炮台"`、`"樱丘"`）分支。

### 3.2 规则

- **每 0.1 秒一回合**（物理每秒 60 步，每 6 步问一次程序）。第 0 回合在开打的那一刻。
- **必须是确定的**：不许读时钟、不许用随机数、不许依赖多线程的先后。裁判和本地用同一个模拟器，结果要一模一样。
- **调试输出写标准错误**（`g.log(...)` 或 `std::cerr`），**不要写标准输出**：标准输出是给模拟器的指令通道。万一写了：模拟器每回合只认开头是这一回合回合号的那一行，别的行（你多打的调试信息、上一回合多出来的行）直接丢掉，每丢一行记一次"输出无效"（`commanders[0].invalid`），同一回合的指令照常生效，下一回合也不受影响。
- **时间**：每回合的计算时间（按 CPU 时间算）上限 20 毫秒；第 0 回合（含程序启动、读地图）上限 2000 毫秒。正常的程序每回合用不到 0.1 毫秒。
  - 某一回合超时：**这一回合的指令作废**，兵继续执行上一条指令；记一次 `timeout`。
  - 累计超时 50 次，或者某一回合迟迟不回复（墙上时钟超过 2 秒，第 0 回合 10 秒）：程序被结束。
- **崩溃、退出、被结束**：从那一刻起程序不再下指令，**每个兵继续执行它最后收到的那条指令**（守的继续守，走的走到了就原地守，打的目标没了就回到自由）；从没收到过指令的兵保持布阵文件里的开场姿态（"原地守"的继续守，"自由"的按默认行为）。这和"指令一直有效，直到下一条"是同一条规则。
- 其他限制：内存 1 GB；不能再开子进程；一行指令最长 256 KB；标准输出累计不超过 64 MB，还没被读走的输出最多积压 4096 行。
- 编译不过或者没交程序：所有场次按布阵文件里的姿态加默认行为打。

### 3.3 每回合能看到什么

没有迷雾、没有延迟，全场都看得到。坐标全是我方视角。

**`g.units`**：全场还在场上的单位（含还没消失的尸体，尸体 `alive == false`）。

| 字段 | 含义 |
|---|---|
| `id` | 编号，整场不变 |
| `kind` | 兵种：`新兵 盾卫 长枪兵 弓手 骑兵 大锤 炮仗兵 投石车 大块头 镇山兽 主帅` |
| `team`、`mine` | 阵营；是不是我的兵 |
| `state`、`alive` | `站着 / 倒地 / 起身 / 阵亡`；前三种都算活着 |
| `x, y, z`、`vx, vz` | 位置（y 是脚底高度）、水平速度 |
| `hp` | 血量 |
| `cooldown`、`attacking` | 离下次能出手还有几秒（投石车 = 离下一发）；正在起手 |
| `braced`、`holding`、`fuse` | 长枪兵已经架好枪；正在原地守；炮仗兵已经点火 |
| `facing` | 朝向（弧度，0 = 朝 +z，正值往 +x 偏） |
| `order`、`target` | 当前指令（`自由 原地守 走到 打 瞄 行军 不动 推`）和正在打的目标编号 |
| `tag` | 布阵文件里的标签（只有自己的兵有） |

主帅（第 4 关）也在 `g.units` 里，`kind == 主帅`，`mine == true`；`g.lord()` 直接拿到他。

**`g.props`**：道具。`type` 是 `keg`（火药桶）、`snowball`（雪球）、`flag`（军旗）、`barrier`（木栅）、`gate`（木栅门）、`pillar`（立石）；另有 `id`、`x y z`、`hp`、`alive`、`triggered`（雪球已经松开 / 火药桶已经点着）、`tag`（关卡文件里起的，例如 `东门`）、`team`（军旗属于哪一方）。

**`g.flying`**：飞行中的石头和滚动中的雪球：位置、速度、`land_x, land_z`（预计落点，估算）。箭太多，不给。

**`g.bosses`**（第 5 关）：镇山兽的状态。

| 字段 | 含义 |
|---|---|
| `id` | 镇山兽在 `g.units` 里的编号（位置、血量去那里看） |
| `state` | `游走 / 刨地 / 冲撞 / 晕` |
| `dir_x, dir_z` | 冲撞锁定的方向（单位向量）；刨地完成之前是上一次的 |
| `next_charge` | 离下一次冲撞开始还有几秒（正在冲 = 0） |
| `state_left` | 这个状态还剩几秒；冲撞时是还要冲几米 |

**`g.events`**：上一回合（0.1 秒内）发生的事，每条一个字符串：

| 例子 | 含义 |
|---|---|
| `terrain_removed 桥中段` | 带这个标签的地形被移除了（第 2 关桥塌）。`g.terrain_removed("桥中段")` 可以随时查 |
| `destroyed 37 gate` | 37 号道具没了（`keg` `gate` `pillar` `barrier` …） |
| `released 12` | 12 号雪球松开了 |
| `boss 41 paw` | 镇山兽换状态：`wander`（游走）、`paw`（刨地）、`charge`（冲撞）、`stun`（晕） |
| `sortie 坡顶` | 主办方的这一队守军出击了（见 3.6）；没有队名的单个守军写他的编号 |
| `rally_go 桥中段` | 桥断以后改道、在集结点等着的敌军出发了（见 3.6；后面是触发改道的地形标签） |

**其他**：`g.time`（第几秒）、`g.tick`（第几回合）、`g.time_limit`、`g.team`、`g.seat`、`g.water`（当前水面高度，没有水是很小的数）、`g.info[兵种]`（造价、血、伤害、出手间隔、射程、速度、半径、能翻多高）。

**地图（开局给一次）**：

| 函数 | 作用 |
|---|---|
| `g.height(x, z)` | 地面高度；空洞、墙里、水下返回 -1000 |
| `g.walkable(x, z)` | 站得住吗 |
| `g.path_dist(x0, z0, x1, z1, climb)` | 绕路走过去有多远（米），走不到返回 -1。`climb` 是能翻过的高度：步兵 1.1，骑兵 0.5 |
| `g.in_zone(名字, x, z)` | 在不在某个区里（例如第 1 关的 `泥塘`） |
| `g.to_world` / `g.to_local` | 我方视角和关卡文件世界坐标互换（一般用不到） |

**查找的便利函数**：`g.mine()`（我还活着的兵）、`g.enemies()`、`g.by_tag(标签)`、`g.mine_of(兵种)`、`g.unit(id)`、`g.prop(id)`、`g.nearest_enemy(x, z)`、`Game::dist(a, b)`。

### 3.4 能下的指令

指令下了以后一直有效，直到下一条。一回合里对同一个兵下多条，最后一条算数。

| 函数 | 含义 |
|---|---|
| `g.move(id, x, z)` | 走到 (x, z)，自动绕开悬崖和墙，路上不还手。走到（0.4 米内）以后变成在那里原地守 |
| `g.move_straight(id, x, z)` | 同上，但走直线、不绕路，自己负责别掉下去 |
| `g.attack(id, 目标)` | 追上去打这个目标。目标可以是敌方单位，也可以是道具（射火药桶、砸木栅门、砸木栅）。目标没了就回到自由。弓手射道具和射人一样：箭要真的碰到桶身才算射中，被桥面、墙、人挡住就没中 |
| `g.hold(id)` | 原地守：守住现在这个位置，只打够得着的。长枪兵站定 0.5 秒就架好枪；弓手射射程内最近的 |
| `g.free(id)` | 自由 = 默认行为 |
| `g.aim(id, x, z)` | 只对弓手和投石车：朝一个地点射（封路口、预判）。对别的兵种无效 |
| `g.detonate(id)` | 只对炮仗兵：立刻点火，0.6 秒后炸 |
| `g.push(id, 雪球)` | 走到雪球背后顶住它，顶满 1 秒它就滚下去；大锤是走到跟前敲一下。目标要是还没松开的雪球 |

- 主帅只听 `move`、`move_straight`、`hold`，别的指令会被忽略；没下过指令时他站着不动。
- 投石车不能走，`move` 对它无效；可以 `attack`（打一个目标，会按目标的速度预判）和 `aim`。
- 对敌人的兵、死了的兵、不存在的编号下令，这条被忽略（计入 `ignored_orders`），同一回合别的指令照常生效。
- 开头是这一回合回合号、但后面整行看不懂的应答（例如指令字母写错），这一回合的指令全部作废，记一次 `invalid`，程序不会被结束，下一回合照常。开头不是这一回合回合号的行按上面"调试输出"那条丢掉，不影响这一回合的应答。
- 指令不保证被准确执行：兵会被挤开、撞退、打倒，倒地的 2.5 秒里什么都做不了。要自己发现"他没到位"再补救。
- 同一步里所有人同时出手：每一步先按这一步开始时的局面让每个兵、每支箭、每块石头、每次爆炸算出打中了谁，再一起扣血、击退、判倒地和阵亡。所以两个人同一步互砍会同时生效，结果和编号、座位无关。
- 道具挨打的规则和兵一样，"飞出去的东西不认人，手里的武器只打敌人"：箭、石头、爆炸打到军旗、木栅、门都会掉血，不分敌我（打在旗上的伤害和打在一个普通兵身上一样）；近战只有敌军砍得动军旗。火药桶被箭射中、被石头砸中、被爆炸波及都会点着。挂在一段地形上的火药桶（关卡文件里桶的 `breaks` 指向它，例如第 2 关挂在桥中段上的桶），那段地形没了以后跟着往下掉，掉的过程中照样能被射中、炸着，掉出地图就没了（事件 `destroyed <编号> keg`）。

### 3.5 默认行为（没有程序、或者下了 `free` 时）

| 兵种 | 怎么打 |
|---|---|
| 近战（新兵、盾卫、长枪兵、大锤、大块头） | 找最近的、走得到的敌人，绕路过去，够得着就打。每 0.25 秒重新找一次；除非另一个敌人近了两成以上，否则不换目标 |
| 弓手 | 走到离目标 24 米以内就站住射，不后退；有敌人贴到 3 米内改用匕首 |
| 骑兵 | 朝目标直冲；撞上以后原地对砍，不会自己拉开再冲 |
| 炮仗兵 | 朝最近的敌人跑，贴上就点火 |
| 投石车 | 开场上弦 5 秒，之后每 5 秒打 15～45 米内敌人最密的一团（按 3 米半径数人头，一样多打离它近的） |

默认行为不会去碰道具：不推雪球，不射火药桶，不砸门，不砸木栅。

### 3.6 主办方的守军：分队出击、改道集结

关卡里预设的敌军（主办方的兵）分成几队，队名和"会不会出击"写在关卡文件的 `units` 里（`squad`、`sortie`，见第 5 节）。

- **挨了远程攻击会出击**：写了 `sortie` 的守军在"原地守"的时候，如果被箭、石头或爆炸打到，而打他的人不在他够得着的地方（近战兵：他的攻击距离再加 0.6 米；弓手：他的射程，站得高射得远），**他那一队的人一起出击**：改成默认行为，去找最近的、走得到的敌人打，不再回原地。一个人挨打，全队出动；火药桶被你点着、炸到了守军，也算你打的。打他的人在他够得着的地方（贴身砍、或者在他射程里对射），他照常原地守着还手，不出击。走不到你那里的（例如崖顶下不来的、被木栅挡着的），出击了也只会去打走得到的人，走不到就站着。
- 被近战砍、被骑兵撞、被雪球撞、被镇山兽撞，都不算远程攻击，不会引起出击。
- 只对主办方的守军生效。**你自己的兵下了"原地守"，挨了箭也照样守着不动**，要不要还手由你的程序决定。
- **桥断以后改道的敌军先集结**（第 2 关）：桥断时还没过桥的敌军改走备用路线，走到集结点（`alt_route` 的第 `rally_idx` 个路点）附近（`rally_r` 米内）就停下等；改道的人全到了，或者从桥断那一刻起过了 `rally_secs` 秒，再一起往下走。集结的时候挨了够不着他的远程攻击，就不等了，全部立刻出发。路上照旧只打挡在面前 4 米内的人。
- 出击和集结出发都会在 `g.events` 里出现（`sortie <队名>`、`rally_go <标签>`）。

## 5. 关卡文件里要看懂的字段

关卡文件在 `关卡\第N关_名字.json`，全部公开。坐标是**世界坐标**（和你的视角不一定一样，见 `seats[0]`）。

| 字段 | 含义 |
|---|---|
| `name`、`desc` | 关名；一段话讲这一关的地形、敌军、过关条件 |
| `time_limit` | 时限（秒） |
| `bounds` | 场地范围 `[x0, z0, x1, z1]`（世界坐标） |
| `kill_y` | 掉到这个高度以下就出局 |
| `seats[0].origin`、`seats[0].yaw` | 你的视角原点（世界坐标）和朝向（度）。换算：世界 x = 原点 x + x·cos(yaw) + z·sin(yaw)，世界 z = 原点 z − x·sin(yaw) + z·cos(yaw)。程序里用 `g.to_world` / `g.to_local` 就行 |
| `seats[0].deploy` | 布阵区，几个矩形 `[x0, z0, x1, z1]`，**我方视角** |
| `seats[0].budget`、`max_units` | 预算、人数上限 |
| `seats[0].lord` | 主帅的起点（第 4 关，世界坐标） |
| `terrain` | 地形图元：`box`（盒子，`min`/`max` 或中心 `c` 加半尺寸 `h`，可带 `yaw`）、`ramp`（坡道，`from` → `to`，`width`，高度 `h0` → `h1`）、`cyl`（圆柱，`c`、`r`、`y0`～`y1`，树干和台地）、`mound`（土丘，底半径 `r0`、顶半径 `r1`、高 `y0`～`y1`）。`tag` 是能被移除的地形（例如第 2 关 `桥中段`）；`boss_stun` 是镇山兽撞上会晕的墙 |
| `zones` | 区域：`name`，`rect [x0,z0,x1,z1]` 或 `circle [x,z,r]`；`speed_mul` 是减速区（泥塘：身体中心在里面，最高速度乘这个数）；`stick_secs` 是"脚上带泥"：身体离开泥塘以后这么多秒内，最高速度仍乘 `speed_mul`（不写 = 0，出来就恢复；倒地、起身时也照样计时；再踩进泥里重新算）。第 1 关的泥塘两个都有 |
| `props` | 道具：`type`（`keg` `snowball` `flag` `barrier` `gate` `pillar`）、位置、`hp`、`tag`。火药桶的 `breaks` 是它炸了以后移除哪段地形；雪球的 `release_speed`、`yaw` 是松开时的初速和方向；立石的 `boss_hits` 是被镇山兽撞几次碎 |
| `units` | 敌军。单个写 `type`、`x`、`z`、`yaw`、`behavior`、`tag`；成方阵的写 `group`（`rows` × `cols`，间距 `dx`、`dz`）。`behavior`：`default`（默认行为）、`hold`（原地守）、`march`（行军：沿 `route` 的路点走向 `to_tag` 的目标，路上只打 4 米内挡在前面的；桥断时还在 `alt_region` 里的人改走 `alt_route`）、`idle`（不动）。`squad` 是这个守军所在的队名，`sortie: true` 是这一队挨了够不着的远程攻击会出击（见 3.6）。行军的 `rally_idx`、`rally_secs`、`rally_r` 是改道以后的集结点（备用路线的第几个路点）、最多等几秒、走到多近算到（见 3.6） |
| `boss` | 镇山兽的参数：`interval`（冲撞间隔）、`paw_secs`（刨地时长）、`charge_speed`、`overshoot`（冲过头几米）、`charge_dmg`、`stun_secs`、`stun_mul`（晕时受伤倍数）、`front_mul`（正面受伤倍数） |
| `objectives` | 过关条件：`win` / `lose` 里每条一个条件（`eliminate` 全歼、`destroy` 带 `tag` 的目标全没、`reach` 带 `unit_tag` 的单位进 `zone`、`dead` 带 `tag` 的单位死了），`on_timeout` 是时间到算 `win` 还是 `lose` |

对抗图（`maps\樱丘.json` 等）格式一样，另有 `score_zone`（计分区的名字）和 `water`（水面；`tide` 是会涨的潮水，`t0`～`t1` 秒内从 `h0` 涨到 `h1`）。水面高过脚底 0.3 米就算淹死（死因 `drown`）；投石车也一样，按它的底面算（11-11 起；原来投石车泡在水里也不算死）。

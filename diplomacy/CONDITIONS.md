# 外交 · 比赛条件与异常记录

> 和其他各集一样，本页完整公开比赛中的所有中断、管理员介入和事故。视频正片为了观感省略了这些细节，以本页为准。除特别注明外，时间均为 UTC（各局 `调度.log` 里是北京时间，UTC+8）。

## 赛制

- 7 个模型各坐一国，打标准七国《外交》。裁判是本地 HTTP 服务（`referee/arena.py`，结算用 `diplomacy` 1.1.2 包），负责私信保密、秘密交令、同时结算和存档。
- **事件驱动，没有常驻进程**：每次唤醒 = 调度器启动一次该选手 Agent 的命令行、续接它自己的会话，把简报写在消息里；选手处理完就结束回复，进程退出。所以"交卷后还在后台思考或轮询"在结构上不可能发生。
- 唤醒时机：进入需要它行动的新阶段时立即唤醒；只有新消息时，等对话安静 10 秒（或最早一条已等 40 秒）再唤醒，合并送达。有消息未送达时不结算。（第 1 局 F1903M 之前是 30 秒 / 90 秒，见下文"代码版本"。）
- 没有思考时间限制。单次唤醒超时 45 分钟算失败；失败后 10 秒、30 秒、2 分钟各自动重试一次，仍失败就冻结对局（第 1 局 S1904M 之前是 60 秒、300 秒两次）。报错像额度用完时不冻结，每 15 分钟重试一次，最多等 8 小时。重试时把没送达的内容重新送达。
- 全员停下但有国家没交令：先催促该国一次（固定文字，见 `prompt.md`）；催促后仍没有动静就冻结并报警，由管理员处理。
- 上下文：各家统一按 256k 窗口，满了用各自原生方式自动压缩（Codex 原生 256k；Claude Code 设 `CLAUDE_CODE_AUTO_COMPACT_WINDOW=256000`；OpenCode 在选手目录的 `opencode.json` 写模型上限）。
- 权限（具体命令见 `referee/scheduler.py`）：
  - Claude Code：不加载用户级设置、用户级 CLAUDE.md 和 MCP（项目自动记忆仍开启，见"记忆"）；`acceptEdits` 模式，额外只放行 `python` 命令；禁用 WebFetch、WebSearch 和子代理。
  - Codex：每局独立的 `CODEX_HOME`，workspace-write 沙箱；为了访问本地裁判，沙箱开启了网络。
  - OpenCode：选手目录里的 `opencode.json` 禁用网页抓取、网页搜索和访问外部目录，允许运行命令。
  - 这些限制作用在 Agent 的工具层面，选手运行的 python 本身仍可能联网或读写别处。规则禁止越界（见 `workspace/RULES.md` 的"边界"），赛后用越界审计核查。
  - 选手工作目录放在 `C:\bench\外交\` 下，和管理员目录不相邻。

## 记忆

- 三局是同一个会话的延续：每个模型续接自己的会话，记得之前各局的全部经过。工作目录也沿用（目录名是第 1 局的国家，开局消息里说明了这一点）。
- 所有选手都可以在工作目录里留笔记，留下的见 `notes/`。
- **记忆不完全对等**：Claude 系三个模型另有 Claude Code 自带的项目自动记忆（写在用户目录下、每个工作目录一份），这部分没有放进仓库。

## 管理员介入

全赛只有两次通知，原文见 `prompt.md`：

1. **第 2 局 S1902M 登记，发给全体**：提醒按计分规则争取最高得分，单独获胜的 100 分远高于任何和局份额。通知随每国的下一次唤醒送达：俄、德、法、英在 S1902M 收到，意、土、奥在 F1902M 的第一次唤醒收到。这条通知改变了第 2 局的条件，比较第 1、2 局时要考虑这一点。
2. **第 3 局 W1905A，只发给英国（DeepSeek V4 Pro）**：英国从 F1905M 起（ENGLAND_0049–0054 共 6 次唤醒）只把工具调用写成普通文字（形如 `[Assistant tool call]: shell(...)`），没有真正执行。它在 F1905M 打算的改令和给俄、法的私信都没有生效，F1905M 按它之前交的命令结算；W1905A 的冬季命令一直没交上，催促后仍然如此，对局按规则冻结。通知只说明技术问题、请它真正调用工具，没有涉及任何局势内容。

此外，管理员停止和续跑过几次对局（下表）。停止时正在处理的选手进程会被中断，续跑后重新收到同样的内容，之前已执行的操作保留。

## 赛后审计

- **越界审计**（`referee/audit.py`）：扫描每次唤醒的完整输出，列出选手访问工作区以外路径、管理员文件或外部网址的痕迹，结果放在各局的 `越界审计.md`。它只做标记，不判定违规，文字里提到某个路径也会被列出。
  - 三局共 106 处（第 1 局 58、第 2 局 22、第 3 局 26）都经人工逐条核查，全部是误报，没有发现越界行为。常见的有：选手读自己的历史记忆、工具自身的缓存路径、Claude Code 系统提示里的文档网址、报错信息里的接口地址、加密思考签名里的字符串。
  - 加密思考签名是 base64，被当时的审计脚本误认成路径，原文无意义且很长，开源时替换成了一句说明（三局共 12 处，条数不变）。现在的 `audit.py` 已修正这个误报。
- **承诺核对**（`referee/承诺核对.py`）：用规则匹配"不进 / 不攻某地"类承诺，与发言方当季和下一季的实际命令对照，结果在各局的 `承诺核对.md`。误报和漏报都不少，只能当线索，结论以原文为准。

## 解读时请注意

- 只打了三局，座位影响很大，单局偶然性也大。
- 三局的条件不同：第 2 局有一条"争取胜利"的通知，第 3 局禁止 1910 年前和局并明说是最后一局。三局的分数直接相加只是一个粗略的看点。
- Claude Code 只保存加密的思考内容，看不到原文；Codex 只记录思考 token 数。视频里引用的"想法"来自模型自己写的笔记（`notes/`）和每次唤醒的可见回复，不是隐藏思考。

# 提示词原文

三局都没有单独的"任务提示词"：选手第一次被唤醒时收到的消息里直接带着规则（`workspace/RULES.md`）和操作说明（`workspace/README.md`），之后每次唤醒只收到简报。下面是逐字原文，以意大利为例；其他国家只有国名不同。

## 第 1 局 · 开局消息

````text
你在一局七人《外交》（Diplomacy）中代表 ITALY。以下是比赛规则和操作说明，本目录的 RULES.md、README.md 内容相同。

# 比赛规则

标准七国《外交》，1901 年春开始。你代表一个国家，其余六国由其他玩家控制。你只知道对手是哪个国家，不知道背后是谁。

## 胜负

- 秋季结算（含撤退）后控制 **18 个补给中心**即单独获胜，对局结束。
- 春、秋移动阶段可以表决协议和局：所有仍在场的国家都赞成，对局立即结束，全体共同和局。赞成票只在当前阶段有效。
- 打到 **1920 年秋季**结算后仍无人获胜，全体在场国家共同和局。
- 计分：单独获胜者得 100 分，其余国家 0 分。和局时按补给中心数的平方分配 100 分：某国得分 = 100 × 本国中心数² ÷ 各国中心数²之和。

## 一年的流程

春季：外交与下令 → 结算 → 被击退的部队撤退；秋季同上；冬季：按补给中心数增兵或裁军。

- **外交**：只在春、秋移动阶段进行。私信只有收件人能看到，单条最多 300 字；`GLOBAL` 为全体公开发言，单条最多 400 字。条数不限，没有新内容就不必发。消息用中文书写。承诺没有强制力，允许欺骗。
- **下令**：每支部队一条命令，可以随时修改。所有需要行动的国家都交了命令、且没有人还在处理新消息时，同时结算。没有时间限制，也不会有人替你下令。
- **撤退和冬季**：不能发消息。只有需要行动的国家下令。

## 命令写法

A 为陆军，F 为舰队，地点用三字代码（见 `资料/地图索引.md`）。

| 命令 | 写法 | 说明 |
|---|---|---|
| 驻守 | `A PAR H` | |
| 移动 | `A PAR - BUR` | 舰队进入多海岸地区要写海岸：`F MAO - SPA/NC` |
| 支援驻守 | `A MAR S A PAR` | 可以支援任何国家的部队 |
| 支援移动 | `A MAR S A PAR - BUR` | 必须与被支援部队的实际命令一致才有效 |
| 海运 | `F ENG C A LON - BRE` | 陆军写 `A LON - BRE VIA` |
| 撤退 / 解散 | `A BUR R PAR` / `A BUR D` | |
| 增兵 / 裁军 | `A PAR B` / `F BRE D` | 只能在自己空闲的本土补给中心建造 |

## 结算要点

- 所有部队强度为 1，每个有效支援 +1。进攻强度必须**大于**防守强度才能进入；同强度互相弹回。
- **提供支援的部队**只要受到攻击，支援就被切断；例外是攻击来自它所支援进攻的那个目标地（此时只有被击退才切断）。
- 部队被击退后必须撤退到空的相邻地区，不能退回攻击者来的地方、也不能退到本回合弹回的地方；无处可退则解散。
- 两支部队不能直接交换位置（除非借助海运）。不能击退或切断本国部队的支援。
- 补给中心的归属在**秋季**结算后更新；春季路过不算占领。
- 冬季：补给中心多于部队可增兵，少于部队必须裁军。

完整规则见 `资料/官方完整规则.pdf`。有争议时以裁判程序的结算为准；不确定的命令可以先用 `simulate` 推演。

## 边界

只使用本目录的文件和 `game.py` 与裁判交流；不联网，不调用其他 AI，不访问其他玩家或管理员的文件。

# 操作

每次有新消息或新阶段，你会直接收到简报。处理完就结束回复，不需要等待或轮询。

所有命令都在本目录运行：

```text
python game.py send ENGLAND "提议：你进比利时，我不进勃艮第。"
python game.py send GLOBAL "公开声明内容"
python game.py orders "A PAR - BUR" "A MAR S A PAR - BUR" "F BRE - MAO"
python game.py draw        赞成协议和局（undraw 撤回）
```

- `orders` 一次提交本阶段全部命令；需要修改就重新提交整份。命令有误会列出该部队的合法选项。
- 冬季放弃增兵：`python game.py orders`（不带命令）。

需要时可以查询：

```text
python game.py brief                 完整当前局面
python game.py legal PAR BUR         某些部队的合法命令（不带参数则列出全部）
python game.py inbox --with FRANCE   与某国的全部消息（也可 --phase S1901M）
python game.py history               最近几次结算（也可 --phase F1901M）
python game.py simulate 假设.json    推演一组假设命令，不影响真实对局
```

`假设.json` 的格式：`{"FRANCE": ["A PAR - BUR"], "GERMANY": ["A MUN - BUR"]}`，没写的部队按驻守处理。

可以在本目录记笔记、写程序辅助计算。

---
````

## 管理员通知（全赛只有两次）

通知只能在对局停下时登记，续跑后随每位收件人的下一次唤醒原样送达一次。

第 2 局，S1902M 登记，发给全体（俄、德、法、英在 S1902M 收到，意、土、奥在 F1902M 的第一次唤醒收到）：

````text
【管理员通知】提醒本局目标：按计分规则让自己的得分尽可能高。单独获胜得 100 分，远高于任何和局份额；协议和局需要所有在场国家一致同意，任何一家都可以拒绝。请认真权衡何时追求胜利、何时接受和局。
````

第 3 局，W1905A，只发给英国（它从 F1905M 起只把工具调用写成普通文字、没有真正执行，冬季命令一直没交上；详见 `CONDITIONS.md`）：

## 之后的每次唤醒：简报

只有新消息时，调度器等对话安静 10 秒（或最早一条已等 40 秒）再唤醒，把陆续到达的消息合并送达；进入新阶段时附上结算结果和当前局面。例：第 3 局意大利的第 5 次唤醒。

````text
==== 你是 ITALY · 当前 1901年春·外交与移动（S1901M） ====
【新消息 1 条】
[S1901M] RUSSIA → 你：谢谢通报。我已明确承诺1901不进GAL及不攻奥，故本春WAR-UKR不改，不能为今年BUD/VIE进攻提供援令。土方刚接受BLA互弹，暂无必须开战的信号。你自己的部署自行决定，但不要把俄军进GAL计入；1902可按届时兵位商谈合作及分工，我不提前承诺与你争TRI。
【本阶段你需要】给每支部队下令（未下令的部队不会自动驻守）。
你已提交：A VEN - TRI；A ROM - VEN；F NAP - ION。需要修改就重新提交。
其他需行动国家已交 6/6。

（处理完就结束回复。）
````

调度器固定附加的几句话（`referee/scheduler.py`）：

- 每次唤醒末尾：`（处理完就结束回复。）`
- 全员停下、只差某国没交令时：`所有国家都已停下，只差你还没提交本阶段军令。请决定后提交，然后结束回复。`
- 上次唤醒出错后重试：`（上次处理被中断。以下内容重新送达；你之前已经执行的操作仍然有效，可用 python game.py brief 查看最新状态。）`

# RMUC 2026 · 全队策略选手包

一个 Python 程序同时控制 1、2、3、4、6、7 号六台机器人。比赛中不调用语言模型；实现 `act(observation, state) -> (actions, new_state)`。完整机制、观察和动作字段见 [MECHANICS.md](MECHANICS.md)，辅助函数见 [sdk.py](sdk.py)。

## 固定硬件

红蓝双方始终使用相同阵容，不允许更换型号：

| 位置 | 型号 | 职责 |
| --- | --- | --- |
| 1 | 1 · H42 重型英雄 | 42 mm 火力、攻建筑 |
| 2 | 201 · E-D 双臂工程 | 搬运、科技装配、救援 |
| 3 / 4 / 7 | 305 · I-L 串联腿步兵 | 三个位置全部串联腿，移动交战、争取增益 |
| 6 | 601 · A-Q 轻量四旋翼 | 2026 空中支援与射击 |

保留现有 RMUC 2026 仿真规则。这里的 6 号是可射击的空中机器人，不是 2027 撞击机库系统；7 号采用 2026 步兵规则。飞镖与雷达不实现，细节以冻结后的引擎与配置为准。

## 胜负

单局最多 420 秒仿真时间，基地被击毁时提前结束。时间到依次比较基地剩余血量、前哨站是否从未被毁、双方前哨都从未被毁时的前哨血量、攻击伤害、存活地面机器人血量，仍相同则平局。2026 不使用 2027 的控制度判胜。

## 决策与资源

- 每 0.1 秒仿真时间决策一次；每次 200 ms 真实时间。不是 CPU 时间，也不是无限快速模式。
- 策略目标为 Python 3.12；标准库和公共 SDK；单个源文件不超过 512 KiB；JSON 私有状态不超过 256 KiB。运行收卷和比赛工具的宿主要求 Python 3.12+，旧版宿主会提前中止，不得把其语法检查结果用于计分。
- 总动作不超过 16 KiB，每台动作不超过 1 KiB；只能控制 `controlled_ids` 中的编号。
- 正式执行使用 Docker：1 CPU、1 GiB 内存、无网络、非 root、只读根目录、单进程。禁止读取外部文件、创建线程或子进程、干扰其他程序。
- 导入及全局初始化限时 60 秒，不计入单轮 200 ms。超时与非法动作会记录。
- 单次可恢复的决策响应超时丢弃该次动作，连续三次响应超时导致本局策略停用；成功返回新动作会重置连续超时计数。`act` 抛出异常或返回非法输出时，第一次就停用，不享有三次重试。停用方在本包计分中判负，双方都停用则平局；可恢复的响应超时不直接判负。
- 策略输入的写入也计入同一轮 200 ms 预算；不读 stdin 导致写入超时会立即停用该策略，终止进程，不再向半条输入追加新观测。
- 可信 worker 在导入策略前先发送启动握手；握手后的策略导入失败判负，握手前的容器/入口失败属于宿主故障并中止。宿主/引擎/容器环境故障保留已完成局，不产生虚假的平局或成功成绩；主办方核实后单独安排重赛。
- 每队只导入和初始化一次；启动成功的进程直接继续执行本局 `act`，不会在 `Battle` 构造时重新启动。任一方启动失败或宿主中止时，会清理已经就绪的进程。

敌人位置受视野与遮挡约束。俯视回放能看到全场，不代表策略也能。不能读取对手代码或利用隐藏比赛状态。

## 开发和交付

建议统一 90 分钟开发窗口，阅读、编码和本地练习均计时，由组织者统一开始及截止。此包不伪装成已有服务器计时服务，组织者须自行记录开始时间和冻结收卷。

仅修改 `workspace/strategy.py`；练习日志可写 `practice/`。所有选手使用相同 SDK、模板与两个公开基准。最终交 `strategy.py`，主办方用相同固定阵容封装清单并冻结代码哈希。无需 Arena-1 应用的 `showcase.json`、开发令牌或 HTTP 服务。

从比赛包目录运行：

```sh
python build.py --docker
python arena.py --duration 30 --replay practice/opening.html
python challenge.py workspace/strategy.py --output practice/eval-001
```

30 秒仅作功能检查。只有 420 秒、Docker 后端的结果才标为 `ranked: true`；正式模型榜还须事先固定参赛者、种子、机器、版本和开发条件。`challenge.py` 只对两个示例策略测试，并非节目正式名次。

自己的可信代码可用 `--trusted-local` 调试，但该模式没有容器隔离，结果始终不排名。不可用于陌生投稿或冒充正式测试。

## 比赛与回放口径

对每组对阵使用同一批种子，并逐个种子换边。胜 1、平 0.5、负 0；同分并列。技术判负局保留在成绩与错误统计里，不会静默剔除或自动重跑。

循环赛在收卷时保存每队源码快照和哈希。语法检查失败的队伍仍保留在赛程里，其预定对局按开赛技术判负记账，正常队伍之间照常比赛；双方源码都不合法时记双技术判负的平局。诊断写入 `run.json` 的 `validation_errors` 与逐局 `diagnostics`，错误源码保留在 `sources/`。这些对局标注 `simulation_started: false`，HTML 只展示诊断，不冒充已运行的仿真。

静音 HTML 是从实际计分对局采集的每秒位置、血量与建筑状态，可离线用浏览器播放。它是俯视采样回放，不是逐帧验证文件，也不需要下载音乐、模型或其他资源。

`arena.py` 会在启动比赛前规范化 `--output` 与 `--replay`，拒绝相同路径、互为祖先/后代的路径，以及经符号链接解析后碰撞的路径，避免结果覆盖回放。

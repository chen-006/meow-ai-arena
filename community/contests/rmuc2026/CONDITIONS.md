# 社区比赛运行条件与验证

本目录是 RM-Arena 自建的非官方 RMUC 2026 社区比赛，独立存放于 `community/contests/rmuc2026/`。验证记录用于说明这个本地比赛包的行为，不代表节目正式集数或模型能力排名。

## 版本与固定条件

- Arena-1 物理引擎、SDK 与规则来自 `e70c1f010edfd5d2b4454c6d5a21bee71c0baba4`；逐文件指纹、宿主执行器补丁和原始哈希见 [SOURCE.json](SOURCE.json)。核心物理和判胜未改。
- 红蓝均为 `1:1, 2:201, 3:305, 4:305, 6:601, 7:305`，地图 `rmuc2026`，完整比赛为 420 秒仿真时间。
- 宿主要求 Python 3.12+；当前本地验证平台为 macOS 26.7.2 arm64 / Python 3.15.2，Docker Engine 29.9.2。
- 策略镜像为 `meow-rmuc2026-policy:e70c1f0-r2`，容器目标 Python 3.12；1 CPU、1 GiB、无网络、只读根目录、非 root、每次决策 200 ms 真实时间。
- 新结果的 `runtime_revision` 为 `pr39-process-reuse-r3`。worker 协议和 SDK 不变；每方就绪进程直接进入比赛，不会二次导入。

## 当前目录的本地验证（2026-11-03）

在本比赛目录执行：

```sh
RMUC_DOCKER_TESTS=1 python3 -B -m unittest discover -s . -p 'test*.py' -v
```

**39 项全部通过**，包括：

- 实际引擎中的双方固定串联腿阵容、源码指纹与冻结后篡改拒绝。
- 实际 Docker 不读 stdin、无效入口、正常短局、Python 3.12 的 PEP 695 类型别名及每局只启动两个策略进程。
- 启动或构造失败后的进程清理、错误配置拒绝复用、旧宿主在编译和创建输出前拒绝；3.11 版本拒绝使用版本信息模拟，未冒充一台真实 3.11 主机。
- 单队和双队语法错误的换边判负、正常对阵继续、宿主磁盘或运行环境故障中止、首次异常/非法输出与三次响应超时的区别。
- 输出路径、Unicode/大小写/末尾空格和点导致的队名冲突在创建输出前拒绝。
- 手册示例与实际 CLI 参数一致，独立选手包以平铺目录导出，能从自身目录启动。

还实际执行了文档对应的 30 秒 Docker CLI 练习，生成结果 JSON 和 31 帧静音采样 HTML，零策略错误，明确标为不排名。命令和导出方式见 [README.md](README.md)。

## 历史完整示例赛（2026-11-01）

`results/example/` 保留两个公开基准在种子 11 下的正反两局：每局 420 秒、零策略错误，实际耗时分别为 101.597 / 109.801 秒。结果和 HTML 来自同一场比赛。历史记录保持原样，不冒充本次迁移或后续修复后重跑的长局。

一次短故障注入曾在首场示例赛期间运行，该场报告零策略超时。这里的少量示例不能推断普遍胜率或机器性能；`reason: timeout` 表示比赛时间到，策略超时另见诊断。

## 范围与边界

本比赛包不新增或修改仓库 workflow，也不改根 README、其他集数或共享评测代码。仓库已有检查按维护者现有机制运行；本目录的完整回归可在本地独立执行。

静音 HTML 只保存每秒状态采样，不是逐帧动作/通信轨迹。错误源码判罚局标记 `simulation_started: false`，仅展示诊断。开发计时、收卷和重赛决策由社区比赛组织者统一管理，没有异步任务服务、在线提交子命令或自动续跑。

尚未完成 Windows / Linux 主机上的完整 420 秒端到端对照，不声称跨平台逐帧一致。输出不得复用，避免已记账的技术判负被覆盖。许可与素材范围见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

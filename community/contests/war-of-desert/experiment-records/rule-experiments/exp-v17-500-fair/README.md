## 本轮改动（相对 v1.7）

- **出兵角镜像化**：生产单位的出生角不再用全局 `NextID`，改为「本方第 N 台 + 座位错开 π」。
  v1.7 里两侧同拍生产时角度差 2.3 rad 而不是 π，出兵点不镜像，采矿机从第二台开始就出现系统性起步差。
- `tick.me.research` 修复：v1.7 及以前该字段被 `ts.Me = TickMe{...}` 整体覆盖，研究进度从未真正下发给 Bot。
- 规则数值、tie-break 链与 v1.7 完全相同。

## 结论

1. **出兵角确实是真实缺陷，但不是全部**：同一 Bot 双座位镜像局里，首次镜像破裂从第 25 拍推迟到第 505 拍，说明这个修正是有效的；但 510 局整体座位差只从 58.1/41.9 降到 57.3/42.7，几乎没动。
2. 用 40 个 seed 的同一 Bot 镜像局（80 局）复核：送达 304 : 272，配对差 0.40 ± 0.70，**t≈5**，座位差依然显著（约 +11%）。地图 `base` 层 255 张全部 0.0000% 非对称，战斗击杀 45.3 : 44.1 基本对称，所以问题不在战场，而在**遗产运输闭环**。
3. 采矿机第一次偏离镜像发生在 295–685 拍，也就是第一次遗产入库前后；一旦某一侧先拿到下一件遗产，「场上最多 2 件、每 100 tick 补 1 件」的供给会把几拍的先手滚成整局优势。
4. 已尝试并**回退**了三个理论上的对称性修正：引擎 BFS 邻域枚举顺序、botkit 流场等距邻居决胜、遗产刷新严格轮转。实测都不改变送达差（304:272 / 302:272 / 300:270），说明剩余分叉不是枚举顺序或刷新顺延造成的，保留它们只会让已跑结果与代码不一致。完整证据见 [座位偏差排查报告](../../座位偏差排查报告_v1.7.1.md)。
5. **当前 tie-break 仍在放大这个经济差**：遗产科技等级 66:33、送达件数 13:1。即便经济差只有 10% 左右，终局判定把它放大成了 57:43 的决胜偏置。

## 建议

- **短期（推荐）**：先删掉 tie-break 里的「遗产科技等级」和「唯一送达件数」，只保留 KD → 母舰 HP → 旗控制，其余判平。平局率预计回到 33–35%，但决胜座位差会回到 52–53%，先把公平性拉回可接受区间。
- **中期**：继续查遗产闭环里剩下的先后差（重点看 `stepRelics` 的装卸读条与遗产补给节奏），把经济差压到 2–3% 以内再恢复科技/送达 tie-break。
- 在完成上述任一修正前，不建议把 v1.7/v1.7.1 的 tie-break 直接用于正式赛。

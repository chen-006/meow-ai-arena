## 1. 胜利分（VS）

`tick.vs` 是双方数组，每项 `{kills, relics, flags, total, delivered, stored}`；
`total` 恒等于前三项之和。

| 来源 | 分值 |
|---|---:|
| 第 1/2 件遗产入库 | 每件 **+50**，每方上限 **100** |
| 第 3 件起遗产入库 | **0 胜利分**，只推进遗产科技 |
| 插旗 | **0** |
| 被拔旗（守方） | **−25**，每次失去 VP 都扣 |
| 拔旗（攻方） | **+25**，同一 VP 每方只结算一次 |
| 击杀 | 基础 `min(造价 × 2 ÷ 3, 200)`，母舰 300；再乘击杀方军衔系数 `1 + 0.15×(等级−1)`（满级 ×1.6） |
| 阈值 | **300**（任一方达到立即收局，同分判平）；时间到按 VS → KD 差 → 母舰 HP% → 旗控制（时长差 > `max(15, 5%×Turn)` tick 才判） → 平 |

**库存遗产分会被撤回**：旗被击毁时，该 VP 上已发过分的遗产逐件扣回 50，然后守方再扣 25；
遗产掉回地面，攻方可以捡走重新入库，拿自己的 50 分和科技。

## 2. 新单位：研究舰（RESEARCH）

| 属性 | 值 |
|---|---|
| HP / 装甲 | 80 / light（脆皮） |
| 速度 / 视野 | 5.0 / 9 |
| 攻击 | 无 |
| 造价 / 建造 / 人口 | 100 CU / 25 tick / 2 |
| 击杀分 | 66（基础值，吃军衔乘数） |

研究舰只能做一件事：**停在己方旗附近（约 2.5 个 VP 半径），研究遗产科技**。

- 该 VP 必须有己方旗，并且库存遗产数量达到节点要求。研究舰进入「库存 ≥2 的己方旗」圈
  即**自动开始**下一节点，无需动作；每方同一时间只推进一个节点，多旗时优先库存最多的旗。
  `relicresearch` 动作可让引擎托管寻路到该旗（见 §7）。
- 研究舰离开 VP 圈：研究**暂停**，进度保留。
- 库存遗产跌到节点要求以下：研究**取消**，进度损失。
- 研究舰被击毁：当前研究**取消**，进度和已投入 CU 损失；库存遗产保留，可造新舰从 0 开始。
- 旗被拔：当前研究**取消**，进度和 CU 损失；库存遗产掉地并撤回已发胜利分，再扣 −25。
- 已完成的研究节点**永久保留**；之后旗再被拔，只撤遗产胜利分和过载。

## 3. 遗产科技树

科技从**第 2 件库存遗产**开始，第 1 件只给 50 分。

| 节点 | 该旗库存要求 | 研究 | 效果 |
|---|---|---:|---|
| R1 遗产电池 | 2 件 | 60 tick / 0 CU | 全体单位伤害 +10%（含对旗伤害） |
| R2 磁轨超导 | 3 件 | 85 tick / 0 CU | 炮塔转速 +15%，CEP −10% |
| R3 复合遗产装甲 | 4 件 | 110 tick / 0 CU | HP +10%（含母舰，按当前血量比例折算），受到伤害 −10% |
| R4 遗产核心 | 5 件 | 135 tick / 0 CU | **全体单位**射程 +15%、伤害 +15% |
| 过载 | 单面旗库存 >5 件 | 被动 | 该旗每多 1 件 +2% 伤害（**全军生效**，取库存最多的旗），最多 +20%；旗毁即失去 |

遗产科技**不能**通过普通 `research` 动作研究；必须由研究舰在旗下自动推进。

## 4. 遗产运输与插旗

- 4 个镜像遗迹点，位于地图中心 ±10% / ±6%；开局 2 件，每 70 tick 补 1 件，场上最多 3 件无主。
- 采矿机发 `{"type":"relic","id":12,"relicId":3}` 后自动：寻路 → 装载 30 tick → 送往最近己方旗 → 入库 30 tick。
  `relic` 会**取消该车的采集运输线**；目标遗产必须是无主（ground）状态。
- 负重移速 ×0.8。携带遗产时**可以插旗**；但若场上没有己方旗，运输车默认原地等待——
  v1.9.2 起此时恢复接受 `move`，可自己走去无旗 VP 插旗；也可下达 `harvest` 弃货转采集
  （遗产丢回地面，可被任何采矿机重新拾取）。
- 入库时若 VP 圈内有**敌方战斗单位**（LAV/AAV/RAILGUN/ARTILLERY/CARRIER），读条暂停（不重置）。
- 插旗仍是采矿机在无旗 VP 圈内**静止** 30 tick 自动完成（移动 >1 px 重置读条）；
  挂着采集运输线的采矿机不插旗；插旗 0 分。一 VP 一旗。
- 旗 HP 160，任何**武装单位**（射程 >0；母舰需已造好主炮）可 `attackFlag`，
  不能打自己方的旗；旗毁后库存遗产全部掉地。

## 5. 射击、火控与等级

与 v1.5 相同：`facing`/`turret`、射界、CEP、全局直伤 ×1.8、火控 C1–C3、五级军衔。
遗产科技 R1–R4 是额外的战斗加成。要点：

- 射界/转速/CEPmax 逐单位见 `hello.rules.v15`（`arcHalf` / `traverse` / `cep`）；
  CEP 按 `r/range` 线性缩小（最低 35%），再 ×0.75、×(1−科技缩减)、×等级系数。
  车体朝向随移动自动更新；`face` 动作可原地设定朝向（见 §7）。
- **HE 溅射对友军 ×0.5**（溅射半径 30 m，溅射伤害 55%）。
- 单位**自动射击**射程内最近敌人（obey 也打，只是不自行移动）；neutral/aggressive
  在没有单位目标时会自动打射程内的敌旗。
- 军衔：经验只来自击杀（目标造价/100），阈值分轻/中/重三档（`vetThresholds`）；
  每级 +4% 伤害、−3% 受伤、击杀胜利分 ×1.15；精度加成 = 火控科技缩减量的 60%（满级）。
- RAILGUN/ARTILLERY 对母舰：克制 2.5/2.0 × 攻坚倍率 1.5 = **3.75/3.0**。

## 6. 计分卡

七领域：**胜利分 / 歼敌 / 保存兵力 / 母舰完整度 / KD 差 / 旗控制 / 遗产吞吐**。
权重 `[0.25, 0.25, 0.10, 0.10, 0.05, 0.10, 0.15]`。
字段 7 用**唯一送达件数**，所以第 3 件以上遗产虽然 0 VS，仍会提高遗产吞吐分和科技。
口径：胜利分 = 50 + 50×(我方 VS−对方 VS)/300（截断 0–100）；歼敌 = 击杀造价/对方生产总造价；
保存兵力 = 存活造价/己方生产总造价；KD 差 = 50 + 10×(击杀−损失)；
旗控制 = 有旗 tick 累计/(Turn×4 VP)；遗产吞吐 = 唯一送达件数/8。
时间到双方 0 击杀且 0 遗产分的平局标记 **invalid**，不进 BT 与加权总分。

## 7. 协议新增

- `tick.vs`：**双方**数组 `[{kills, relics, flags, total, delivered, stored}, …]`；
  `tick.me.vs` 是本方同一结构。`delivered` = 唯一送达件数，`stored` = 当前库存件数。
- `tick.relics[]`：`{id, x, y, state, by?, vp?}`，`state` = ground/carried/stored；
  `relic` 动作的 `relicId` 从这里取。
- `tick.flags[]`：`{id, vp, side, x, y, hp, stored}`，`stored` = 该 VP 库存件数。
- `tick.me.research`：`{node, vp, ship, progress, total, active, paused}`。
- `units[]` 新增：`lvl`（军衔 1–5）、`kills`、`facing`/`turret`（度）、`relic`（携带遗产 id）。
- 动作新增（都占「每台单位每拍 1 条」额度，计入动作总数上限）：
  - `{"type":"relic","id":<采矿机>,"relicId":<无主遗产>}`：遗产运输（§4）。
  - `{"type":"attackFlag","id":<武装单位>,"flagId":<敌旗>}`：拆旗（§4）。
  - `{"type":"face","id":<单位>,"deg":<角度>}`：设定车体朝向（0–360，移动会覆盖）。
  - `{"type":"relicresearch","id":<研究舰>}`：引擎托管寻路到「库存最多的己方旗」并自动研究。
- 事件：`research-start` / `research-done` / `research-cancel` / `flag-bounty` /
  `relic-blocked` / `relic-pick` / `relic-in` / `flag-up` / `flag-down` / `levelup`。

你要参加一场 AI 算法对抗赛：**Desert Arena · 沙漠遭遇战**。请写一个 Go 程序，在程序生成的沙漠地形上指挥部队，争夺 VP 点并保护/摧毁母舰。当前比赛规则为 **v1.9.2**（ruleset `v15`，1500 tick），细节见 `RULES.md` 与 `RULES_V15.md`。

## 你会拿到什么

一个 `workspace/` 目录：

- `RULES.md`：完整规则与行协议（**先读这个**）
- `submission/<选手名>_bot.go`：可运行的骨架，已经实现协议循环，但**不含任何策略**
- `arena/`：正式赛的引擎、裁判与比赛程序源码（只读）——本地调试用的就是它
- `arena/workspace/botkit/`：可选工具库（读 hello、解地图、寻路辅助）
- `bots/`：一个骨架 + 两个预编译基线（`baseline@1.exe`、`baseline@2.exe`）
- `tournament/local.json`：本地赛季配置（两个基线 + 你的 Bot）
- `本地对局.bat` / `本地赛季.bat`：双击编译并对打，不用记命令
- `clock.py`：查看编码期已用时间

## 你要交什么

**一个 `submission/<参赛选手名称>_bot.go`**（文件名用下划线接 `_bot.go`，不要改名）。编译命令：

```bash
go build -o bot.exe ./submission
```

想先确认能跑通：

```bat
本地对局.bat
```

它编译你的代码，然后跟两个基线各打 2 个 seed（换边两局），打印逐局 VP、
判定层级、故障与决策耗时，回放落在 `matches\local\`。

程序通过 stdin/stdout 与裁判通信：

```text
读 hello → 打印 {"ready":true} → 每读一行 tick，打印一行 {"actions":[...]} → 读到 end 退出
```

- `hello` 里有全图（`map.base` / `map.elev` / `map.surf`）、VP、资源点、单位表、科技表、时序。你可以在这里预计算路径、距离表、流场。
- `tick` 里有你方全部单位、视野内敌方单位、比分、你的经济与生产/研究状态。
- 每拍 120 ms 预算，指令固定晚 1 tick 生效。超时、崩溃、返回非法结构，连续 3 次红牌判负。

动作格式：

| 动作 | 字段 | 说明 |
|---|---|---|
| 移动 | `{"id":7,"type":"move","x":1280,"y":900}` | 世界像素坐标，引擎不寻路 |
| 攻击 | `{"id":7,"type":"attack","targetId":12}` | 原地指定优先目标 |
| 待命 | `{"id":7,"type":"idle"}` | |
| 分配 | `{"type":"alloc","alloc":{"produce":35,"attack":35,"research":15,"move":15}}` | 和必须 100 |
| 生产 | `{"type":"produce","kind":"LAV"}` | |
| 研究 | `{"type":"research","tech":"A1"}` | |
| 造炮 | `{"type":"weapon"}` | 母舰主炮，独立队列 |
| 模式 | `{"type":"mode","mode":"neutral"}` | `obey / neutral / aggressive` |

## 规则要点（细节以 `RULES.md` 为准）

- 地图 256×256 格，1 格 = 6 像素（物理 10 m），像素世界 1536×1536。`base=3` 是山脉，**绝对不可通行**；山脉还会挡直射视线。
- 20 tick/s，单局 600 tick。上坡减速、下坡略加速；母舰坡度阈值更严。
- 双方初始 500 CU、母舰 + 2 LAV。Salvager 站在资源点旁采集，是唯一稳定收入来源。
- 母舰四项分配决定生产槽、武器槽、研究槽和移动速度；生产/研究每 5% 一档、最多 3 槽。
- 四条科技树：火力、装甲线性；机动、工业交叉分叉。
- 弹道是真实的二次阻力 + 重力，RK4 积分。高地优势来自物理，不是固定加成。
- 五级判定链：斩舰 → VP → KD 差 → 母舰 HP → 平局。
- 七领域加权总分独立于胜负：赢得多不等于分高。

## 严格禁止

- 读写文件、联网、启动子进程、读取选手包之外的内容；
- 修改裁判、引擎、赛程、结果、封存记录；
- 硬编码单张地图坐标：正式赛逐场换 seed，同场换边两局；
- 假设进程活到终局：超时/崩溃后裁判会 kill 并重启你。

## 怎么评测

- 每场对阵换边两局，同一 seed、同一张点对称地图，双方各重启进程；
- 40 局起步，正式名次用 Bradley–Terry 全池拟合（基准 0，差 400 ≈ 10:1）；
- 另设七领域加权总分榜，与 BT 名次并列公示；
- 每局都做确定性复核：同 seed + 同指令必得同结果。

## 交卷前自检

1. `go build -o bot.exe ./submission` 通过（在 `workspace/` 目录下执行）；
2. 双击 `本地对局.bat`，或 `cd arena` 后 `go run ./cmd/arena check -seed 20261109`，输出 `CHECK_OK`，两局 `故障=0/0`、`确定性复核：true`；
3. 每拍决策耗时远低于 120 ms（参考 Bot 约 0.1 ms）；
4. 换 2–3 个 seed 各跑一次，确认不是背地图。

时间规则：解压选手包开始计时，**90 分钟**目标完成，**120 分钟**强制收卷。到点时 `submission/<选手名>_bot.go` 是什么就算什么。

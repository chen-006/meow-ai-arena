# NNUE Vanguard·联合出招版 — 思路说明

## 来源

网络上沿官方 NNUE Vanguard（`community/tank/lite0812__nnue-vanguard/bot.cpp`，MIT）：
244 个人工特征槽 → 嵌入 3504×64 int8 → 两层 64 宽 MLP → 每车 25 个动作的 policy + 一个 value，
搜索是 PUCT 的 MCTS，每层六辆车各自选动作、拼成联合动作推进真实局面，叶子用同一个价值回传。

本条目是同一路线的**后续迭代**，替换了本目录上一版内容。

## 这一版改了什么

1. **搜索深度 12 → 24**。同时间预算下（首回合 2000 ms、其后每 50 ms CPU）：
   - 对上一版 1,000 局：**56.0% ± 3.0%**；
   - 深度 16 / 20 / 28 分别为 54.0 / 54.8 / 56.1，说明收益在 20 附近饱和，28 已开始回落。

2. **出招改为「取被评估过的联合组合」**（本版主要改动）。
   原出招是「三辆车各取自己访问数最多的动作，再拼起来」。但搜索的访问统计记在**单车节点**上，
   所以拼出来的组合**可能从未被模拟过**。用一个固定局面探针可以复现：

   ```
   发出的组合 = (22,6,7)，该组合在 512 次模拟中出现 0 次
   实际被走得最多的组合 = (22,6,4)，151 次
   单车边际访问数 = 434 / 170 / 248
   ```

   改法：在根节点额外统计「本次搜索实际走过的三车组合」，出招取其中访问最多的那个。
   训练标签（`root_policy`，每车边际访问分布）不变，因此**不需要重训**。
   - 对上一版 2,000 局：**56.15% ± 2.2%**（95% CI [53.9, 58.4]）。

3. 上一版的 AVX2/SSE2 推理路径与运行时回退保持不变。

## 自测数据（官方原生正式模式：首回合 2000 CPU ms，其后 50 CPU ms）

| 批次 | 局数 | 结果 |
|---|---|---|
| 官方 16 对手 × 120 | 1,920 | 1,916 胜 / 2 平 / 2 负 = **得分率 99.84%** |
| 另一批新种子 × 240 | 3,840 | 3,828 胜 / 3 平 / 9 负 = **得分率 99.73%** |

全程无超预算、无非法输出（`timeouts=0, illegal=0`）；单回合耗时 45.05–45.21 ms，
落在 50 ms 预算内并保留了 5 ms 余量。

## 试过但**没有**采用的改动（都是负结果，如实列出）

以下每一项都在同一套对拍上测过，均是零或负，因此不在本版中：

- 全局/开局加大单次模拟的展开深度（`K_EXP` 2 / 4：42.9% / 27.9%）；
- 每回合清空节点表（48.5%，不显著）；
- 把击杀/吃星并入节点哈希键（45.5%）；
- 三种软件预取、节点结构压缩（均 −2~+2%）；
- 搜索形状（根部宽/窄、中间宽、中间窄五种，全部落在对照 ±3.2 点内）；
- 在叶子价值上加「减员惩罚」（平摊 46.9%、按复活时间加权 41.1%）；
- 提高真实结局在价值目标中的权重（0.5 / 0.7：48.9% / 50.8%）；
- 用更深视野的标签只重校准价值头（47.9%）；
- 根节点按「限定访问数后取均值最高」选组合（23.9%，明显有害——不同访问数的均值不可比）；
- 根先验的价值权重 `K_REF` 加倍（2,000 局复核 49.9%）；
- 节点容量上限放大 2.5 倍（49.3%）；
- 出招前做友军伤害规则过滤（47.8%）。

一个可能对别人有用的结论：**在这台机器上，从外部给搜索加判断（惩罚项、过滤器、额外规则）
一律是负收益；唯一有效的是让「搜索算出来的」和「实际执行的」保持一致。** 第 2 条改动就是这一类。

## 已知弱点（留给后续）

- 长局（60 回合以上）里坦克战容易崩：3,840 局中 12 个非胜局里有 5 局是碾压，共同特征是
  我方阵亡数与友军误伤显著偏高（其中一局丢 15 辆车、友伤 4 次；另一局友伤 8 次）。
- 基地每回合最多掉 1 血，实测 **44% 的回合**我方有至少两辆车同时压在一条已饱和的基地线上，
  多出来的攻基地车辆在边际上没有收益。这条我没能修好（见上「试过但没有采用」）。
- 价值函数对「丢一辆没有升级的车」几乎不收费（实测 Lv0 快车被毁只值约 0.29 个基地血，
  中盘约半数局面符号还是反的），但三种修法全部无效，说明它影响的是**排序以外的刻度**。

## 合规说明

- 单文件，包含官方 `tank.hpp`，只定义 `init` 与 `decide`，没有自定义 `main`；
- 运行时不读写文件、不联网、不启动进程或线程、不重置官方计量器；
- 未内嵌任何其他选手的策略代码。本条目只使用公开的官方头文件与自身权重。

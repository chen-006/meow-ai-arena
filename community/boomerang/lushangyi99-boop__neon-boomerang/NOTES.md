# 《飞镖乱斗》程序对战赛 —— 技术说明与迭代总结 (`notes.md`)

---

## 一、程序是怎么打的：整体思路、核心算法与模块拆解

### 1.1 顶层设计哲学：拥抱 Delay-4 物理现实的“双阶段精确物理规划器”

《飞镖乱斗》（`dartfu-v3`）本质上是一个 **20Hz 离散整数物理 + 4 步观测延迟（`DELAY=4`）+ 连续向量动作 + 一击必杀** 的高频实时博弈游戏。与传统棋类不同，在 10ms/步 的 CPU 预算下，盲目展开稀疏随机树（如浅层 MCTS）很难覆盖连续的移动/瞄准角度，更容易因为误差一步送命。

因此，本程序（`player.cpp`，最终版 `v10b`）采用 **“精确延迟状态重建 + 高质量领域候选集生成 + 物理级快评打分 + 原生 `dart::Game` 双场景对抗校验”** 的四级流水线架构，单步实测平均耗时仅 **`0.15~0.36 ms`**，最坏单步峰值 **`~1.0~3.5 ms`**（远低于 10ms 预算），在超过 500 局本地全场景压测中保持 **0 超时、0 崩溃、0 非法输出**。

核心设计围绕五个从引擎源码（`dart.hpp`）推导出的关键物理法则展开：
1. **不可反应窗口（Unreactable Window）**：观测 `obs` 提供的是 `t_obs = max(0, t - DELAY)` 步**开始前**（`acts[t_obs]` 执行前）的对手状态。于是第 `t` 步发起的 `A_THROW`，对手最早在第 `t + 5` 步才能在观测里看到 `S_THROW`，最早在第 `t + 6` 步 Phase 4 挥出格挡。换算成距离：**约 `4.0 m` 内（`hit_h <= 5`）的精准掷镖在物理上不可靠反应格挡或躲闪**；而 `>= 4.2 m` 对着持镖且自由移动（`S_FREE && D_HAND`）的强手盲目直扔，极易白送格挡并把镖掉在对方脚下。
2. **1-Step 冲刺砍不可见性**：`DASH_PRE=2` 后第 1 步冲刺位移（`1000 mm`）立刻取消接 `A_MELEE`（`DASH_SLASH=1`，滑行 `500+250 mm` + 挥砍半径 `1600 mm`），在第 `t + 4` 步即判定斩杀——比对手第一次在观测里看到 `S_DASH`（`t + 5` 步）还要早 1 步。
3. **砍克踢（同帧结算顺序）**：同一步 `SLASH` 触发 `CUT` 击杀，而 `KICK` 仅触发 `KICKHIT` 眩晕；但若对手尚未在 Phase 1 持镖（哪怕 Phase 3 即将捡镖），先手 `KICK` 会在下一帧 Phase 4 提前命中并打断对手后手 `SLASH`。
4. **回旋镖格挡与召回穿墙的博弈**：格挡（`BLOCK=1`）能把对手飞行中的 `D_OUT`/`D_BACK`/`D_CALL` 直接打落脚下形成绝对武器差；而 `RECALL_WALL=1` 允许隔墙穿墙召回，躲在墙后召回既免疫敌方直射又可威胁穿墙狙杀。
5. **实时己方飞镖状态构成“0 延迟间接雷达”**：虽然对手有 4 步延迟，但自己与自己的飞镖是 0 延迟的。当自己飞行的镖未撞墙却突然变成 `D_GROUND` 时，程序可以提前 4 步瞬间分辨是 **对镖（CLASH）** 还是 **被敌方格挡（BLOCK）**。

### 1.2 模块逐一拆解

#### 模块 A：第 0 步全波次地图预处理与动态寻路（`init` / `run_dijkstra` / `ensure_dash_links` / `run_point_bfs`）
- **解决什么问题**：比赛包含未见地图、多波次塌陷（`COLLAPSE`）、湖泊/孤岛/窄桥和复杂掩体，纯直线启发容易走入死胡同、被塌陷困死孤岛或错过跨坑冲刺捷径。
- **怎么做**：
  - 在 `init()`（1000ms 预算，实测仅用 `7~39 ms`）中一次性生成所有塌陷波次 `w = 0..nwave` 的精确 `Map` 快照，以及每个格子的精确塌陷时刻 `cell_fall[id]`。
  - 为每个波次运行多源 0-1/桶队列 Dijkstra，预计算三张距离场：
    1. `wave_pit_dist[w]`：每个格子到最近坑/地图边界的网格步数（用于边缘安全裕度与防推落坑）。
    2. `wave_core_dist[w]`：到最终不塌陷核心区（`core_cells`）的真实可达步行距离（含对角移动 `14` / 直走 `10`）。
    3. `wave_safe_dist[w]`：到下一波不会塌陷格子的逃生距离。
  - **跨坑冲刺图（`wave_dash_links`）**：按需缓存每个格子向 16 个方向发起 `A_DASH` 时，是否能借助 `P.dashing == 1` 的空中无视落坑机制**精准跨越湖泊/裂谷安全落地**，在孤岛逃生或偷袭时自动纳入候选集。
  - **每步动态目标/飞镖 BFS（`dart_bfs_dist`、`tgt_bfs_dist`）**：每步仅对需要寻路的落镖点与主要目标执行极轻量 BFS（`~0.02 ms`），让追击与捡镖能够优雅绕过墙角、湖泊和桥口。

#### 模块 B：Delay-4 世界重建、对手画像与隐蔽间接信息推理（`update_tracking` / `reconstruct_now` / `build_threat_table`）
- **解决什么问题**：直接拿 4 步前的 `obs` 当当前状态会导致严重误判（如对着 4 步前的位置空砍、撞上已经飞到眼前的镖、或在对手刚格挡完恢复硬直的瞬间冲脸送命）。
- **怎么做**：
  1. **精确对齐回放**：在 `my_hist[64]` 环形缓冲区中保存己方历史每步状态与动作；重建时先在 `t_obs = max(0, t - DELAY)` 时刻构造真实 `dart::Game`，代入己方已执行的历史动作与对手的合理预测动作（`guess_enemy_action`）前推 `DELAY` 步至当前时刻 `o.t`，再以当前帧精确的己方与己方飞镖状态覆写。
  2. **持续跨延迟窗口的间接格挡/对镖推理**：若己方飞镖在 `t - 1` 步未撞墙却突然掉落至 `D_GROUND`：
     - 检查是否有敌方飞行镖在附近：若有，判定为 **`CLASH`**，立即在 `age_drop <= DELAY` 的整个延迟窗口内把敌方飞镖同步修正为掉落点 `D_GROUND`，抢占捡镖先机；
     - 若无敌方飞行镖、而有持镖敌人贴近掉落点：判定为 **`BLOCK`**，立即记录 `last_blocker` 并在接下来 `DELAY` 步内把该敌人的状态修正为剩余 `slash_post - (age_drop - 1)` 步的 `S_SLASHED` 硬直（同时递增该敌人的 `seen_blocks` 格挡画像），彻底杜绝“被格挡后盲目冲刺捡镖，结果在 `DASH_POST` 僵直时被恢复的对手一刀反杀”的经典惨案。
  3. **草丛信念传播（`grass_mask`）**：当敌人进入草丛不可见时，在动态大小 `std::vector<uint8_t>`（支持任意尺寸未见地图）上维护其可达草丛格子的奇偶步扩张集合，并用己方视野半径 `SEE_R` 反向剪枝（若草丛格已在我方视野内却未见人，直接剔除），生成最近的“幽灵威胁点（`ghost_x, ghost_y`）”用于防埋伏。
  4. **双级武装判定（`enemy_armed_now` vs `enemy_armed_soon`）**：
     - `enemy_armed_soon[k]`：对手当前持镖，或延迟期间可能捡镖，或在未来 5 步内会接回/捡起飞镖（用于评估投掷价值与冲刺风险）。
     - `enemy_armed_now[k]`：严格限定为当前 `w_now` 已持镖或延迟 4 步内已可能捡起地上镖（用于 `enemy_can_slash_threat` 踢-砍相克判断）。这样既保证 **0 次拿踢撞对手挥砍自杀**，又能在双方冲向对镖点时抢在对手捡镖前 1 步果断发动 **冲刺踢（Dash-Kick）** 打出先手眩晕斩杀！
  5. **在线对手风格画像**：平滑追踪对手速度方差 `jitter`（走位抖动度）与 `seen_blocks`（格挡倾向），动态微调投掷预测权重。
  6. **双射线 Delay-4 幻影威胁（`PhantomThreat`）**：针对视野内 `S_FREE && D_HAND` 的持镖敌人，同时建立两条可能已在延迟 4 步中出手但尚未显示的隐形弹道射线——**直瞄我方 `t_obs` 位置的射线**与**按我方 `t_obs` 速度提前量预判的射线**（Dual-Ray Anti-Lead Weaving），引导角色自然做出变向/反节奏走位，极大降低被强 AI 盲狙的概率。

#### 模块 C：9 角度 × 6 假设概率掷镖评估器与无撞墙平移（`eval_throw_aim`）
- **解决什么问题**：直线预判极易被强手变向躲开或挥砍格挡，而在墙角边缘随手加平移（throw-strafe）又容易导致飞镖出膛 400mm 就擦墙掉落。
- **怎么做**：
  - 对每个射程内目标构造 **9 组候选瞄准向量**：迭代求解的精确提前点 `lead`、折中点 `mid`、当前点 `cur`，以及围绕 `lead` 的 `±5%`、`±11%`、`±19%` 扇形偏转（专门用于绕开墙角或封锁走位）。
  - 使用与 `dart.hpp` 逐位一致的减速/拐弯物理公式，对每个瞄准方向前推 20 步飞镖轨迹，并检查是否提前撞墙、早对镖或误伤队友（4v4 绝对否决）。
  - 对目标并行模拟 **6 种运动假设**（0=沿当前预测轨迹、1=急停刹车、2=见镖后左垂直躲闪、3=右垂直躲闪、4=反向折返、5=奔向落镖点），依据目标是否处于锁定态（精确计算 `total_lock_steps`：如 `S_SLASH` 为 `timer + slash_post`）与 `jitter` 分配概率权重，加权计算命中概率 `p_hit`。
  - **可格挡折扣与无反应窗口加成**：若敌人在反应时刻 `react_h = DELAY + 1` 持镖且非锁定状态、`hit_h >= react_h + slash_pre - 1`，大幅折扣命中期望并置 `likely_blocked = true`（提高 `empty_cost` 避免白送格挡）；反之若在不可反应窗口（`hit_h <= 5`）或对手空手/锁定，则果断重奖出手。
  - **平移重算防擦墙**：选出最优瞄准后，比较“沿最佳走位平移 / 左右垂直平移”三种掷镖走位时，对偏移后的真实出手点 `(rxi, ryi)` **重新调用 `eval_throw_aim`** 验证不撞墙且保持命中率，彻底消除贴墙掷镖自断武器的失误。

#### 模块 D：动作候选生成、双阶段评估与原生 `dart::Game` 双场景极小极大校验
- **候选动作覆盖全技能树**：
  - **移动（`kind=0`）**：16 方向均匀采样（随帧旋转消除朝向偏置）+ 静止 + 飞镖 BFS 方向 + 目标 BFS 方向 + 塌陷核心方向 + 绕敌切线方向 + 垂直来镖躲闪方向 + 回镖曲线引导方向（主动走位把 `D_BACK`/`D_CALL` 拉过敌人身体实现“甩尾曲杀”）。
  - **挥砍/格挡/踢（`kind=2/3/4`）**：精确计算 1 步刹车滑行点 `(mx1, my1)` 后生成斩杀砍、打落飞镖格挡、踢击与落坑踢候选。
  - **掷镖（`kind=1`）**：每个可攻击敌人的最优 9 角度 × 3 平移方案。
  - **冲刺（`kind=5`）**：1~3 步冲刺取消斩杀（`dash_cancel_step`）、无守卫飞镖的冲刺抢镖、危急时刻的跨坑逃生冲刺与垂直躲镖冲刺。
  - **召回（`kind=6`）**：包含“墙后穿墙安全召回（`!open_los_threat` 奖励）”、“对镖后抢不过距离的召回狙杀”、“开放视野/近身无镖敌落坑踢威胁下的即时取消”以及“取消后 8 步无条件反震荡冷却（彻底消除 `CANCEL -> RECALL -> DIE` 死循环）”。
- **诚实多步快评（`eval_candidate_fast`）**：
  - 前推 10 步（引导回镖/召回时扩展至 14 步），在 `h >= 2` 仅做防落坑急停而**不做虚假自动躲镖**，保证即时躲闪、格挡（`BLOCK`）与走位选择的真实性。
  - 集成多项专项安全与收益模型：
    - **真实物理逃逸半径的挥砍可靠性**：结合 `t_obs` 原始距离 sanity check（杜绝把 4 步推测行走当真而对着空气空砍）与静止目标的精确加速度逃逸界（`v < 60` 时 1 步最多移动 `acc=125mm`，`1470mm` 内即为必杀）。
    - **冲刺砍 + 冲刺踢双威胁区**：对持镖冲脸与空手冲脸分别建立 `reach + 650mm` 的预警惩罚。
    - **反向落坑踢与冲刺落地防踢落坑（`sim_slide_pit`）**：不仅检查自己能否把对手踢进坑，更用逐帧摩擦衰减模拟反向检测“无镖对手在 `h=1,3` 或我方冲刺结束僵直 `h=6,7` 时，能否一脚把我们踢进坑/湖/界外”，将自落坑与被踢落坑压到极低。
    - **冲刺中决策（`decide_dash_moving`）**：当处于 `dash_moving` 阶段时，不仅检查即时取消砍/踢/格挡，还内置 **5 方向冲刺后脱出推演**（避免因假设停步不动而误判必死），并在检测到继续冲刺会落坑时自动触发 **紧急急停取消（Emergency Pit-Brake `A_MELEE`）**。
    - **回镖曲线击杀 2 假设评估** & **召回蹲守（Recall-Camp）**：对方 `D_RISE` 时主动占位至约 `1050mm` 最佳格挡距离准备二次打落。
- **原生 `dart::Game` 双场景对抗校验（`verify_with_exact_game`）**：
  - 对快评得分 Top-14 候选（受 `thread_cpu_100ns()` 严格硬时间预算保护）直接调用裁判同款 `dart::Game::step()` 进行 8 步（冲刺为全程 `dash_pre+dash_t+dash_post` 步）逐位精确验证：
    - **场景 A（基准精确物理）**：验证 0 碰撞误差、0 落坑、0 误伤队友，核验真实击杀、格挡与捡镖收益。
    - **场景 B（对抗极小极大检查）**：假设最近的有视野持镖自由敌人立刻向我方反手挥砍/掷镖；若当前候选是高风险锁定动作（冲刺/召回），则进一步假设对手**在 2 步延迟前已经出手了一发隐藏飞镖（`h=0` 即刻飞出）**，直接筛掉大量冲进延迟隐藏镖里的自杀冲刺！

#### 模块 E：FFA 动态形态切换与 4v4 队友通信
- **FFA（四人各自为战）**：
  - 3~4 人存活时启用 **“外围游走 + 反夹击 + 秃鹫收割”模式**：提高交战理想距离至 `5.1 m`，对两个对手夹角超过 97°（`dot < -0.12`）的夹心位置施加高额惩罚，慎重交出远距离可能被格挡的镖，同时因“每次击杀 = +1 分（等价提升一个名次）”，对高把握斩杀赋予 `1.15x` 击杀倍率。
  - 一旦场上仅剩最后 1 名敌人（`alive_enemies <= 1`），立即通过 `is_duel_like` **无缝切换为完全体 1v1 决斗模式**（理想距离收紧至 `3.7 m`，启用全额格挡与召回蹲守），避免决赛圈过于保守丢掉冠军。
- **4v4 团队赛（`M_TEAM`）**：通过 `msg` 位域协议实时编码并广播己方精确坐标与持镖状态（克服队友间 4 步观测延迟），严禁任何向队友方向挥砍或直射掷镖的候选，并主动与队友保持 `1.55 m` 分散站位防一穿二。

## 二、优势、弱点与“试过但未采用/回退”的方案复盘

### 2.1 程序强在哪里
1. **极高的生存下限与极低失误率**：在 60 局官方 1v1、48 局未见图 1v1、40 局官方 FFA、32 局高强自博弈 FFA 中多次打出 **0 落坑**（自落坑几乎归零，仅剩极少量高难度被迫被踢落坑）；全流程物理逐位对齐且有双场景 `dart::Game` 把关。
2. **极强的未见地图与异构规则泛化力**：全动态网格尺寸（无硬编码地图上限）、多波次塌陷 Dijkstra + 跨坑冲刺图 + 动态 BFS 寻路，全部距离/速度/开关均读取 `Config`，在 6 张自制复杂未见图（立柱迷宫、多桥河谷、草丛森林、开阔竞技场、孤岛跳板、狭窄长廊）上 1v1 胜率高达 **77.1%~83.3%**、FFA 均分 **3.81**；在 `DELAY=2`、`DASH_SLASH=0`、`RECALL=0` 等改动配置下同样稳健（`DELAY=2` 对 `strong` 直接打出 **8-0 零死完胜**）。
3. **FFA 统治级表现**：凭借“3~4 人外围反夹击 + 高效收割残血/锁定目标 + 决赛 2 人切 1v1 杀手模式 + 无镖敌落坑踢防护”，在对阵 3 个 `strong` 的 40 局官方 FFA 中均分高达 **`4.01`**（60% 第一名、1.75 均击杀，远超对手的 1.15~1.90），在多代顶级自博弈混战中也稳居第一（`3.02` 分且 0 落坑）。
4. **充裕的 CPU 裕量**：平均每步 `< 0.20 ms`（4v4 仅 `0.36 ms`），峰值 `< 3.5 ms`（10ms 预算内自带硬时间断路器），绝无超时风险。

### 2.2 程序弱在哪里
1. **延迟 4 步下的不可见 1-step 突袭**：面对高水平对手在 4 步盲区内发动的 1-step 冲刺砍或冲刺踢（比我方看到 `S_DASH` 早 1 步生效），目前主要靠保持距 `cd==0` 敌人的安全间距与反提前量走位来预防，无法做到绝对免疫，在 1v1 强强对话中仍有约 10%~15% 输于此类突发贴脸。
2. **缺少多层博弈树搜索（仅做 1 步决策 + 10~14 步固定策略推演）**：面对极其刁钻的“两步连招陷阱”（例如先故意丢镖引诱我方冲刺捡镖，再在 3 步后用回镖封走位），单层规划器的远见仍有天花板。
3. **草丛深水区的主动探草略偏保守**：目前草丛信念传播主要用于“防被埋伏”和接近幽灵位置，没有加入“当剩余草丛格子 `<= 4` 时主动扔镖盲扫探草”的进攻逻辑，在超大面积草丛图上节奏会稍慢。
4. **4v4 中队友间的“返镖/召回穿行误伤”**：虽然直射 `D_OUT` 与 `SLASH` 严格检查不误伤队友，但 4v4 混战中我方飞镖在 `D_BACK`/`D_CALL` 阶段返回时，队友可能因延迟走入回镖路径导致偶发误伤（好在海选个人榜只计 1v1 与 FFA，且 4v4 仍以 11-1 碾压对手）。

### 2.3 试过但最终放弃/回退的想法（附实测教训）
本着“用大样本对局和回放解剖说话、绝不凭感觉保留负优化”的原则，我们在迭代中果断放弃了以下四个听起来很美、实测却拉垮的设计：

1. **放弃方案一（`v4`）：掷镖直线后撤平移 + 空手超强反冲刺排斥场（`12500 * r^2`）**
   - **初衷**：想在掷镖和空手时拉开距离，避免被冲刺砍贴脸。
   - **实测翻车**：直线后撤和强排斥场把角色一路推向地图边缘与湖边，导致对 `v1` 单轮出现 6 次落坑，对 `strong` 在 6 张未见图胜率从 75% 跌至 68.8%。
   - **结论**：彻底回退；改为“横向切线平移 + 偏移点重新调用 `eval_throw_aim` 防擦墙”。

2. **放弃方案二（`v5`）：在快评 rollout 的 `h >= 2` 加入 `reactive_rollout_move` 自动垂直躲镖**
   - **初衷**：认为规划 `h=0` 动作时，假设未来 `h >= 2` 自己会聪明躲镖，可以减少不必要的恐慌。
   - **实测翻车**：这是一个极其隐蔽的“乐观偏置陷阱”！因为系统以为 `h >= 2` 自己能轻松躲开来镖，导致在 `h=0, 1` 迎着敌方飞镖走看起来不再致命，直接把 **格挡率从 ~1.0 次/局腰斩到 0.3 次/局**，FFA 均分从 `3.52` 暴跌至 `2.62`，`v5 vs v3` 跌到 `16-24`。
   - **结论**：`v6` 立刻回退为“诚实推演（`h >= 2` 仅防落坑急停，不做虚假躲镖）”，FFA 均分当场反弹回 `3.52`！

3. **放弃方案三（`v6/v7`）：过度叠加的掷镖保守惩罚（双幻影射线乘 `lock_mult=2.5` + `2550mm` 危险圈 + `jittery` 把直行权重压到 `0.17` + `seen_blocks>0` 压低 `p_hit` 破阈值）**
   - **初衷**：减少近距离掷镖被反砍、提高对高频抖动与格挡对手的筛选门槛。
   - **实测翻车**：四重惩罚叠加导致出手极其犹豫，对 `strong` 60 局飞镖击杀数从 `v3` 的 38 次骤降至 25 次，且对 `v3` 1v1 跌至 `15-22-3`（每局仅扔 1.1 次镖）。
   - **结论**：`v8` 将 `S_THROW/S_THROWN`（仍可 60% 移速走位）的 `lock_mult` 合理降至 `1.35`，收紧瞄准扇形至 9 角度并恢复合理权重，对 `v3` 胜率立刻单步反弹 `+16.2%`（翻盘至 `23-17`），未见图对 `strong` 飙升至 `81.3%`！

4. **放弃方案四（`v9`）：把非锁定站立挥砍的观测距离门槛 `obs_rad` 从 `+350mm` 收紧到 `+220mm`，并放大 `P.st != S_FREE` 时的回镖接近惩罚**
   - **初衷**：进一步杜绝极少数空气空砍与迎着回镖掷镖。
   - **实测翻车**：门槛过严导致对手在 4 步延迟内迎面走近时被误判为 `slashed_reliable = false`，错失反杀窗口，对 `strong` 60 局被砍死亡从 3 次翻倍到 7 次、胜率从 `46-14` 跌至 `40-20`。
   - **结论**：`v9b` 仅保留核心的“召回防无镖敌踢落坑 + 反震荡冷却”，并恢复 `obs_rad = +350mm`，对 `strong` 瞬间回升至 `46-14`，FFA 更是冲上 **`4.01` 分**！

## 四、规则细节剖析与对裁判/引擎的观察建议

通读 `RULES.md` 与 `dart.hpp`（约 2310 行引擎源码）并结合 500+ 局逐帧回放验证，规则引擎 `dartfu-v3` 整体非常严谨、完全确定且自洽，**未发现破坏公平性的物理逻辑 Bug**。以下几个工程细节与机制边界值得特别记录，供主办方评估与赛后解说参考：

1. **`dart.hpp` 在 Windows 下包含 `<windows.h>` 带来的非显式宏污染（如 `VER_H`）**：
   - `dart.hpp` 第 28 行贴心地保护了 `near`/`far`/`small` 并定义了 `NOMINMAX` 和 `WIN32_LEAN_AND_MEAN`，但 `<windows.h>` 间接拉入的 `<winver.h>` 仍暴露了 `VER_H` 等全大写宏。我们在 `v1` 中定义 `constexpr int VER_H = 8;`（验证步数）时直接触发了编译语法错误。虽然容易改名规避，但建议在文档或头文件注释中提示选手避免常见 Windows 宏前缀，或在 `dart.hpp` 中把线程计时封装得更隔离一些。

2. **规则与文档里最容易产生“微妙理解偏差”的延迟边界**：
   - `obs` 中的对手状态是 `t_obs = max(0, t - DELAY)` 步**开始前**（尚未结算 `acts[t_obs]`）的快照，而很多选手容易直觉以为包含 `acts[t_obs]`。差这 1 步直接决定了：第 `t` 步的 `A_THROW` 最早在 `t + 5` 才被对手看见、第 `t + 6` 步才能挥出格挡；而 1-step `DASH-SLASH` 在 `t + 4` 步斩杀生效时对手根本还没观测到 `S_DASH`。引擎实现与 `RULES.md` 一致，非常精妙，但也确实是本作最具决定性的机制门槛。

3. **`DASH_SLASH=1` 的隐性“紧急刹车”用途**：
   - 规则允许在 `dash_moving` 阶段用 `A_MELEE` 取消冲刺转为挥砍/踢，并按正常 `acc` 减速（滑行约 750mm）。这意味着即便面前空无一人，程序也能在“发现继续冲刺会落入新塌陷坑”时靠空挥 `A_MELEE` 实现紧急制动救命。我们的 `decide_dash_moving` 专门利用了这一合法机制，并在多局残局回放中成功保命。

4. **“己方 0 延迟落镖”构成的超前间接信息渠道**：
   - 规则规定自己与自己的飞镖为 0 延迟，对手为 4 步延迟。当己方飞行飞镖在空旷处（未撞墙）骤变为 `D_GROUND` 时，程序无需等 4 步就能提前推断对手刚触发了 `CLASH` 或 `BLOCK`（后者意味着对手此刻正处于 6 步 `S_SLASHED` 硬直）。这属于完全合法的信息推演，也是拉开强弱 AI 信息利用率差距的一大看点。

5. **内置陪练 `strong` 在高压场景下的偶发超时记录**：
   - 在大样本测试中观察到 `strong` 在少数长局（及 `DELAY=2` 配置下）偶尔出现单步 CPU 超过 10ms（如 17.3ms）触发裁判记故障；这反向印证了 `arena.exe` 的线程 CPU 计时与故障统计准确可靠，也提醒我们在代码中必须内置基于 `dart::thread_cpu_100ns()` 的软硬双层时间截断以保证 100% 零故障。

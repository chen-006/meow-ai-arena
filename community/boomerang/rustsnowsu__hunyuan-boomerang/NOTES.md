# 混元回旋镖 · 思路说明

原创实现：没有复用或改写 `boomerang/bots/` 下任何官方选手的源码，只依赖 C++ 标准库和官方 `dart.hpp`。全程只读 `info()` 与当步观察，不读写文件、不联网、不保存跨局状态。

## 整体结构

1. **时间对齐（延迟补偿）**。观察里别人的位置与镖是 `DELAY = 4` 步以前的状态。把观察装进裁判同款引擎 `dart::Game`，从 `t - D` 起连走 `D` 步；自己冻结为 `unknown`、自己的镖置为 `D_GONE`，于是"他当时在蓄势、其实镖早已出手"这类状态迁移都由引擎自己算，不用手写物理。再把推进后的对手与镖、当前的自己拼成一个"当前世界"。草丛里的隐身对手放回最后已知位置或出生点。

2. **盲区幻影镖**。对手可能在我看不见的那几步里已经出手。对 `t-1 … t-D` 每个互斥出手时刻各生成一条解析轨迹，每条再分"直瞄当时位置"和"按当时速度打 3 步提前量"两种瞄准，按去程减速位移表 `900 / 850 / 800 …` 外推 12 步。这些轨迹只参与危险扣分，不复制整份 `Game`，成本低但能覆盖整段盲区。

3. **开环候选推演**。候选包括 16 向全速移动、停、8 个半速微调、冲刺（带落点地形检查）、扔镖、格挡、近战、召回、捡地上的镖、往最后落脚区撤离。每个候选在两套敌方假设（本步直射 / 本步打提前量）下各推 12 步，按存活、击杀、真实与幻影飞镖距离、硬直、塌陷倒计时、持镖状态、与敌人距离逐项打分；两套分数加权并取最小值做保守兜底。

4. **解析式覆盖瞄准**。扔镖不瞄单一点：对每名对手列 6 种走法假设（续走 / 停 / 靠近 / 左绕 / 右绕 / 远离），按回旋镖去程累计位移表枚举朝向，算"这一镖能覆盖多少种走法"，用 `wall_between` 排除被墙挡住的路线，取覆盖率最高的几个朝向进候选池；另补近距离直射候选。

5. **收手与控时**。候选数量固定，配合 `steady_clock` 墙上时钟保险丝（6.5 ms），超时就停止评估后续候选；第 0 步初始化每格塌陷时间并算最后落脚区中心。召回一旦开始就保持，除非有镖逼近、有人贴脸或脚下马上塌陷，避免"召回→取消→召回"的空转。

## 强项 / 弱项

- 强：塌陷地形与场地收缩处理稳健；对弱档选手胜率高；从不超时、不崩溃，单步 CPU 远低于 10 ms 预算。
- 弱：一对一明显弱于四人局，面对 top 档选手（尤其会主动压制、连续出镖的）胜率很低；进攻偏保守，扔镖次数少于强档对手。

## 本地测试

- `match.py check`：无超时、无非法输出、无崩溃，单步最多约 1.4 ms，第 0 步最多约 34 ms。
- `boomerang/challenge.py`（416 局，正式计时）：一对一 -41.8、四人局 -37.4，个人实力值 -39.6，参照名次第 10 / 14；超时 0 步、非法输出 0 次、崩溃 0 局，之后单步最多 5.36 ms。
- 开发期间试过"覆盖率过门槛就绕过打分表强制出手"和"方向保持"，官方挑战成绩分别降到 -47.0 和 -63.5 ~ -80.6，均已回退，最终提交的是表现最好的基线版。

## 疑问

同一份代码重复跑 `challenge.py` 会出现十几分的实力值波动（脚本说明里也提到部分选手按时钟决定算多深），因此上面的分数应视为量级估计，不是精确名次。

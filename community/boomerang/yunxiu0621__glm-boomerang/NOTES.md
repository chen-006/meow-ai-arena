# GLM 回旋镖 · 思路说明

这份程序由 GLM-5.4（工具：ZCode）按回旋镖大作战选手包的任务书写成，写的时候有 75 分钟的时间限制，交稿之后代码没有再改。它只从 `template.cpp` 的骨架起步（`#include "dart.hpp"`、带 `decide` 的结构体、`DART_MAIN`），逻辑是从零写的，没有参考其他选手的代码。

## 1. 怎么打

### 整体思路

这个游戏最难的地方是“看到的别人是 4 步以前的样子”。所以程序的核心不是一套写死的战术，而是一个**按延迟修正后、对对手的几种可能做法取加权和的推演评估器**：

1. 把观察推到现在，得到若干个“现在”的局面，每个对手一种可能的打法对应一个局面；
2. 列出我的候选动作：移动、扔、砍 / 踢、冲刺、召回；
3. 每个候选动作在每个局面里用 `Game::step`（裁判用的同一份引擎）往后推 10～18 步；
4. 按结果打分，选最高分的那一个，只执行它的第一步，下一步重来。

每步 CPU 用量在 1v1 里约 0.35 毫秒、最多约 2.3 毫秒（上限 10 毫秒）。没有靠时间中断收手，而是把工作量控制在结构上。

### 各部分

**(1) 把观察推到现在。** 每步记下自己的状态、自己的镖和自己的动作。收到第 t 步的观察时，用观察里对手在 t−4 的状态，加上记录里自己在 t−4 的状态建一个 `Game`，再用自己当时真实的动作往前推 4 步。推的时候对手的行为由“情景”决定。如果某个情景里“我在 t−1 之前就死了”，而现实中我还活着，这个情景直接作废。这是一个很便宜的筛子：比如“对手 4 步前就朝我扔了、而且我现在该已经死了”的情景会被自动排除，剩下的才是真正还悬在空中的威胁。

**(2) 对手的情景。** 对每个对手，按他镖的状态生成：

| 情景 | 对手在做什么 | 解决什么问题 |
|---|---|---|
| KEEP（情景 0） | 照旧：继续当前动作，自由时沿原速度方向走 | 基准，当作“确定” |
| T0 / T6 | 一能出手就朝我扔，提前量 0 步 / 3～6 步 | 没看见的那一镖 |
| NOW | 从现在起才扔 | 晚一点的那一镖 |
| DASH | 朝我冲刺，够得着就冲刺接近战 | 冲刺斩 |
| RUSH | 直冲过来，进 1.4 米就近战 | 空手贴脸、持镖砍人 |
| RECALL | 把地上的镖召回，接住后朝我扔 | 站在对方落地镖旁边，被起飞的镖打死 |
| PICK | 走去捡镖，捡到就扔 | 撞镖之后谁先武装起来 |
| BEND | 走位让自己的回程镖从我身上飞过 | 回程镖的路线取决于主人今后的走位 |

**加权**：情景 0 的结果按确定算，权重 1；其余假想情景各按 1/4 算。一开始我用的是“取最坏”，结果对手假想冲刺过来时所有候选都是“要死”，于是“自己冲进刚塌的坑里晚死几步”反而排第一。改成加权之后落坑明显减少。

**(3) 我的候选动作。**

- 移动：16 个方向加停，每个方向一直走，推 12 步（四人局和 4v4 推 10 步，4v4 只用 8 个方向）。
- 近战 / 挡镖：对手在 1.35 米内，就朝他的预测位置挥砍或踢；对方的飞行镖再走一步会进到 1.5 米内，就朝那个位置挥砍挡镖。
- 扔镖：先用“对手照旧”的轨迹和镖去程的累计飞行表算拦截点，取拦截步及前后各一步共 3 个瞄准点，再加 1 个直瞄当前点。
- 冲刺：只在想逃离要塌的地方、或者要去捡镖且附近没有持镖对手时才考虑，8 个方向，推 18 步（冲刺本身锁 8 步，视野必须更长）。
- 召回：地上的镖可以召回时考虑，推 16 步。

**(4) 扔镖的评估和别的动作不一样。** 对手看到我的蓄势是 5 步之后的事，所以另用一组“对手第 5 步起才反应”的推演：照旧走、停、左横跳、右横跳、朝我冲、背离我跑、挡镖、对扔。每个反应下算一局的值：打中算赢，打空算空手期的代价加上推演结束时的局面分。取平均，再加上假想情景里的风险。

**(5) 一条硬规则，效果最大。** 对手处于自由状态、且离我超过 3.8 米时，不生成朝他扔镖的候选。来由是回放统计：评估里假设“对手照旧走 / 停 / 迎上来都会被打中”，实际上 4.5 米以外的远掷对自由的人几乎打不中。对持镖的对手，6～8 米的远掷 137 次里 79 次被挥砍挡下、39 次被躲开、只打中 1 次；对手空手时，远掷也大多和他的回程镖相撞或者被躲开。镖被挡之后我空手、对方持镖，接下来就是被近处一镖打死。加上这条规则之后，程序从“先出手”变成“等对方先扔、躲开、再贴上去反击”。

**(6) 局面分（推演结束时还活着才计）。** 主要是距离：持镖对手太近有陡罚，我空手时范围更大；我有镖、对方没有时接近有奖；我的镖在地上时按距离把我往回拉；离墙太近小罚；塌陷按“这格还有几步塌、离最近永不塌的格要走几步”算紧迫度。另外每 3 步换一个伪随机方向给一点加分，让对手按直线算提前量算不准。

## 2. 强在哪、弱在哪

**强**（基于回放的判断）：

- 已看见的镖基本躲得开：镖的位置投影是精确的，16 个方向逐个推演。
- 挡镖时机是算出来的。
- 对手“看不见的那一镖”和冲刺斩被显式建模。
- 不轻易先出手，多数时候手里有镖，能挡能躲。

**弱**：

- 现在的输法：对方扔完、镖在回程的那几步里我贴上去反击，有时会和他的回程镖相撞，或者被对方冲刺进 3 米内砍到。
- **落坑没有解决。** 四人局里落坑是我最大的死因（120 局 36 次，强档陪练只有 10～12 次）。抽样看全是自己掉下去、没人踢。试过两种针对性的改动：选定移动之后再用一份新建的对局推 8 步，会掉坑就换方向；给“照旧走下去就会掉坑”的候选额外扣分。都没有减少落坑，原因没查清。
- 四人局没有专门调，沿用 1v1 的阈值和权重。
- 移动候选只会“一直朝一个方向走”或“停”，不会两段动作。
- 看不见的对手只按最后看见的位置放回去。
- 4v4 没有认真做。

## 3. 本地测试结果

对手是选手包里的三档陪练。对局有噪声，同一个版本两次 80 局能差 5 局，所以只在 160 局的范围内下结论。

| 版本 | 对 mid（1v1，80 局） | 对 strong（1v1，160 局） | 四人局（对 3 个 strong） |
|---|---|---|---|
| 基础版（没有第 1 节第 5 条的规则） | 70:10 | 70:89:1（44%） | 40 局均分 2.21 |
| 本投稿 | 68:11:1 | 107:50:3（67%） | 120 局均分 2.86、平均名次 2.12（三个 strong 是 2.15 / 2.00 / 1.75） |

出局方式（对 strong，160 局）：基础版被镖 69、被砍 7、落坑 14；本投稿被镖 35、被砍 8、落坑 10。

**试过但没采用的改动**（对 strong 的 1v1，各 160 局，都没有比本投稿好）：

| 改动 | 结果 |
|---|---|
| 召回保险：持镖对手 7.2 米内或有镖在飞，就不召回 | 52:106:2。召回虽然让我有一两步动不了，但它是空手期重新武装最快的办法 |
| 冲刺追击，并衔接扔镖 | 68:91:1 |
| 空手时离持镖对手更远 | 55:104:1 |
| 被挡、被对扔时的打空代价调高 | 66:92:2 |
| 对手的“挡镖”反应改成等镖到 1.5 米内再挥，并加权 | 67:90:3 |
| 规则里的阈值改成 3.0 米 / 4.6 米 | 102:58:0 / 87:69:4 |
| 对召回中的人也不远掷，对蓄势中的人不扔 | 102:58:0 |
| 两种掉坑处理（见第 2 节） | 105:55:0 / 97:63:0 |

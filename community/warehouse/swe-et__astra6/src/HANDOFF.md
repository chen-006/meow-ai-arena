# 仓储调度仿真 · 第 1 轮交接

本轮的行为参照是 `baseline/`。从 workspace 运行 `.\run.cmd tools/bench.py` 即可用规定参数编译整个 `src/` 并核对五份公开输出。加 `--baseline --repeat 7` 可看各组 CPU 时间的中位数。程序只使用 C++20 标准库、标准输入和标准输出，缓存限于一次仿真。

## 从哪处改

| 需求 | 入口与关联状态 |
| --- | --- |
| tick 顺序、输入、充电、救援、移动和到达 | `sim.cpp` 的 `Simulation::run` 是总入口。参数、机器人、订单和计数器在 `simulation.h`。事件按 tick 单向读取，同 tick 保留输入顺序。 |
| 订单排名和候选选择 | `Order::key` 定义排序，`dispatch.cpp` 的 `dispatch` 遍历，`tryAssign` 核算预算，`selectRobot` 决定机器人和平局。外部 ID 和内部数组下标是两个量。 |
| 电量与去充电 | 派单预算在 `acceptOrder / tryAssign / selectRobot / approachBudgets`；实际扣电在 `move`，找桩在 `sendToChargers`，补电在 `charge / rescue`。修改任一段耗电时，复查对应的预算下界和上界。 |
| 报表、日志、汇总 | `report.cpp` 的 `report / updateHotspot / finish`。事件在状态转换处直接写出；送达、丢失、拒单分别在发生处计数。`cancelAttempts` 是特殊口径，见下表。 |
| 地形、距离、下一步 | `routing.h/.cpp` 的 `Grid`。`legDistance` 求正向距离，`distancesFrom` 返回一张距离表，`nextStep` 决定移动方向。占位决策留在仿真层。 |

tick 内的顺序是 **事件 → 救援 → 充电 → 派单 → 低电找桩 → 按机器人编号移动 → 报表**。同一台机器人本 tick 到取货点时只取货，即使送货点相同也要等下个 tick 才交货。

## 基线中影响输出的细节

| 情形 | 必须保留的结果 |
| --- | --- |
| 派单平局 | 订单按优先级降序、原到达 tick 升序、**数值**订单号升序。合格机器人取到取货点的距离最小者，同距选编号**最大**者。等于低电阈值可以接单，电量恰好够预算也可以。 |
| 封路与距离 | 新单仅因越界或永久墙被拒绝，临时封锁仍可入队。原地距离为 0，包括被封的同一格；可以从被封的起点走出，不能从外面走进被封的终点。取送同在被封格且机器人原地时，也要从该格核算到开放桩的距离。 |
| 取消 | 只有 PENDING 和 ASSIGNED 可成功取消。**每次**取消已存在的订单都给 SUMMARY 的 cancelled 加一，包括重复取消、已取货、送达或丢失。不存在或被拒绝的 ID 只记 CANCEL_FAIL，不加一。 |
| 占位和让路 | 活车占位，死车不占位；先移动的车即时影响后车。相邻格最短距离和让路均按上、右、下、左。路径断开或目标被封只加累计等待，保留连续碰撞次数。已有四次碰撞，且被占的下一格不是目标时，才尝试让路。让路同样扣电，也可能走到目标。 |
| 到达、停机、救援 | 已在目标时先到达，再考虑零电和封路。没到目标且零电则停机。取货前停机按原到达时间重新入队，取货后停机记 LOST。满 100 tick 且原地未被活车占用，按机器人编号救援，电量为满电向下取半，可为 0。 |
| 充电桩 | 首选可达、未被预订、到达后还够安全余量的桩；否则选任意可达开放桩，不管电量和预订。两次选择均按距离、再按行优先。预订可多人共享，用计数维护，赴桩和正在充电都算。已在桩上的车即使格子被封仍可充电，电量达到满电的 90% 即离桩。 |
| 报表与延迟 | 热点按曼哈顿距离统计活车，候选包含被封的非墙格；并列取行优先首格，全部死车时也是首个非墙、计数 0。平均延迟按 `(sum + delivered / 2) / delivered` 取整，无送达为 0。 |

## 优化成立的条件

**派单。** `pendingCount` 是全量待派数。`pending` 是按排名排列的搜索索引，省去每 tick 复制和排序。永久地图不连通、无可达桩、或所需电量下界已超过满电的订单仍保留 PENDING，并能正常取消。空闲合格机器人的位置和电量不变，派单只会删减候选；单纯封路也只会减少可行路线。因此旧的失败订单只在有车新获资格或有效解封时重试，新单和重新排队的订单单独处理。如果派单资格随时间或其他状态变化，需同步更新 `reconsiderPending`。如果优先级随时间变化，还需更新索引中的排名键。

`tailCost` 按地图版本缓存取货到送货、送货到最近开放桩的距离与安全余量。面对大量失败订单时，`approachBudgets` 从所有候选的实际电量向外传播，得到每格可剩余电量的上界；随候选被派走，这个上界只会偏宽，最终选择仍用实际机器人复核。改变载货成本时，尤其要核对“到送货点的直接预算”这个剪枝仍为上界。

**寻路。** `Cell = y * width + x`，永久围墙保证从内部格检查四邻安全。格数最多 40,000，16 位距离足以表示任一有限最短路；65535 表示不可达，65534 仅在完整 BFS 的内部表示待访问。不能拿不可达哨兵直接和电量比较，因为合法电量可达 100,000。单源强制种入起点，多源充电桩表只种开放桩。反查开放目标时，对被封的出发格取相邻距离最小值加一。

- 有畅通直角路线就能证明距离达到曼哈顿下界。移动时只能对**第一个开放且缩短曼哈顿距离**的方向应用这一证明，不能跳过可能存在折线路径的更早方向。
- 对短绕路按方向顺序逐步增加搜索深度。只在较小界限已穷尽时增加 2；网格上所有路径长度的奇偶性相同。同一格已用更宽的剩余预算搜索过时可剪枝。搜索工作超限直接用精确距离表。递归深度受曼哈顿距离加 4 限制。
- 已缓存路线必须仍从当前位置到当前目标。若被封格在剩余路线上，或新开放的格子可能构成同长或更短的路（包括改变方向平局），就重算。单独检查占位和让路；机器人位置不进入地图距离缓存。
- 单源表按使用顺序回收，距离数据预算 128 MiB。拓扑变化后先撤销失去所有最短前驱的旧距离，再从保留的边界及新开放的格子传播改进；修改太多、波及太广或表被回收时，完整 BFS 重建。返回的单源表引用只供当前查询使用，不可跨另一次 `distancesFrom` 长期保存。

**热点。** 每台活车在菱形覆盖到的每行贡献一个闭区间，做行差分，再按行优先扫描非墙格。一次报表为 `O(W*H + R*min(H, 2*radius+1))`。只有移动、停机和救援会改变活车位置集合；这三处维护 `hotspotDirty`。更改热点定义时同步检查缓存失效条件。

## 验证和剩余风险

- 官方五组公开输出逐字节通过。基线 CPU 合计 42.594 秒；优化版七次取各组中位数后合计约 0.062 秒。本机 CPU 计时粒度约 0.016 秒，单个负载的精确倍数波动较大。
- 最终版运行 `.\run.cmd work/differential.py --count 900 --seed 2201 --public-seeds 1`，8 个定向、900 个随机和 5 个换种子生成器用例全部通过。脚本先用官方校验器检查输入，再比较基线和优化程序的完整标准输出，仅归一化换行。覆盖同 tick 事件、重复取消、堵车、低电、重排、丢失、救援、全封桩和同格取送。测试辅助脚本位于 workspace 的 `work/`，交付的 `src/` 可独立编译。
- `.\run.cmd work/test_routes.py` 用独立普通 BFS 比对 71,500 张完整距离表、99,639 次选步及 14,300 对端点距离，包含批量修改和封锁出发格。`.\run.cmd work/full_boundary.py` 检查所有主要规模上限同时取满、CRLF 的场景，对照独立推导的完整输出。
- 隐藏负载未测。频繁开关狭窄通道可能让多张距离表重建；大量看似可行但实际无法完成的积压单仍可能触发线性扫队列。若要继续提速，可用 `work/stress.py` 分别观察这两类开销。其压力数据用于计时，不代替基线对拍。

# 开源范围

这份说明写清楚每一集会公开什么、不公开什么、什么时候公开、各部分用什么许可，以及每一集的目录应该怎么放。

目标只有一个：拿到这个仓库的人，能看懂每一集比的是什么，能用一条命令重算出榜单，能拿自己的程序或模型按同样的条件再比一次。

## 每一集公开什么

**游戏本体**

- 引擎源码和规则文档。
- 全部地图和关卡数据，包括比赛时对选手保密的那部分（隐藏地图、隐藏负载、隐藏场景）。
- 本地构建和对战工具：编译脚本、本地裁判、回放查看器。

**比赛材料**

- 选手包原样：比赛时发给选手的全部文件，逐字节保留。开源时如果有替换（例如比赛时只给可执行程序的陪练，开源时换成源码），在这一集 README 的"和比赛时的差别"里写明。
- 提示词原文：开赛、中场、续跑等主办方发给选手的全部消息。
- 比赛条件：每位选手的模型、思考档、接入方式、工具和版本、限时、实际用时，以及所有中断、补时和事故，写在 `CONDITIONS.md`。

**选手作品**

- 每位选手交的代码、设计文件和笔记，原样不改。

**裁判和计分**

- 裁判程序、赛程（包括随机种子）、计分脚本。做到一条命令就能从逐局结果重算出榜单，并和仓库里的成绩表核对。

**结果**

- 成绩表、逐局结果、有代表性的回放。回放按事先定好的规则挑（指定的对阵或人数里取典型的一局），不专挑反杀和名场面。

**渲染器**

- 把回放做成视频画面的全部代码、场景主题、兵种和道具模型，以及出片命令。

**各家 AI 的体素小人**

- 视频里代表各个模型的体素（方块）小人：模型文件、方块数据、生成它们的脚本、预览图，以及每个角色的原形象出处。

**角色立绘和表情差分**

- 节目组制作的角色立绘（交付版）和每个角色的表情差分（切好的单张和头像），包括节目自己的串场角色。

**生图提示词和模型参数**

- 定稿实际用到的提示词原文（含通用画风段）、模型名、尺寸、质量、背景等参数，以及出图、整理、切图脚本。脚本里的密钥从环境变量读，不写进仓库。
- 生图时用到的参考图不打包：第三方的（各家商标图、别人的设计图）只在说明里写明参考了什么；节目组自己的参考图（早期样稿、母版的缩小或裁切版）也不另放，说明里写明每张是什么。

**声音的清单和配音设置**

- 背景音乐和音效的清单：曲名、作者、出处和编号、用在哪一集。
- 配音设置：合成服务和模型、每个角色的音色名、提示词原文、后期参数、逐句语气表。
- 都放在顶层 [`audio/`](../audio/README.md)。

## 不公开什么

- 配音成品、音乐和音效的文件（都是第三方的素材或服务生成的，许可不允许再分发；清单和设置见 `audio/`）、解说稿、成片和剪辑工程。
- 选手的原始会话记录：对话、思考过程、工具调用日志。
- 主办方的运营脚本：调用各家命令行工具、计时收卷、查询余额这类只服务于办比赛的程序。
- 密钥、令牌、账号信息、内部记录、一次性脚本。
- 第三方的东西不打包进仓库。物理库等依赖按名称和版本引用，并注明出处和许可；Blender 由使用者自己安装，README 里写明测试过的版本。

## 什么时候公开

跟视频同时公开。视频还没播出的集，不提前放任何材料，包括题目、选手包和成绩。

## 许可

整个仓库只用一种许可：[MIT](../LICENSE)。上面列的每一类都适用 MIT：游戏本体、比赛材料、选手作品、裁判和计分、结果、渲染器和美术素材、角色立绘和表情差分、体素小人、生图提示词、文档、社区投稿。

- **MIT**：可以自由使用、修改、再发布，包括商业用途，保留版权和许可声明即可。用渲染器、立绘、体素小人做出来的画面和视频也一样。
- 个别自带许可的第三方目录不变，以目录里的说明为准：第 4 集回放网页里的 jDip 地图图形（GPL，经 AGPL 的 `diplomacy` 包渲染）、社区比赛 `community/contests/rmuc2026/`（Arena-1 非商业学习许可）。
- 第三方依赖不打包，按各自的许可使用；用到第三方依赖的目录放一份 `THIRD_PARTY_NOTICES.md`，列出名称、版本、出处和许可。

### 怎么署名

- 代码、规则、数据：按 MIT 保留版权和许可声明即可。
- 从第 10 集起的角色形象（立绘、表情差分、体素小人）：`角色形象设计：小叶子XIYZ（B 站）；美术和制作：喵了个猫了个咪了个猫`，附仓库链接 `https://github.com/chen-006/meow-ai-arena`。新形象参考自小叶子XIYZ 的设计，由节目组制作。逐个角色的说明在 `art/README.md` 和 `characters/CREDITS.md`。
- 第 1～9 集视频里的旧角色形象大多来自 B 站博主 ZipZipPipe（[主页](https://space.bilibili.com/4168597)），不在本仓库内，也不适用本仓库的许可。
- 角色名里的模型名和公司名属于各自的权利人，只用来说明角色对应哪个模型，不表示这些公司认可或参与本项目。

## 从哪一集起执行

- 这份范围从第 10 集《纸上谈兵》起完整执行，渲染器、体素小人、新立绘和表情差分、生图提示词也从这一集起随视频公开。
- 第 1～9 集不补渲染器、体素小人和立绘。这几集的其余材料已经按大致相同的范围公开；个别与范围不一致的地方（例如某一集的终场需要主办方的总控脚本才能完整重跑），写在那一集 README 的"和比赛时的差别"或复现说明里。往期目录里的旧图和旧说明保持原样。
- 体素小人、立绘、表情差分和生图提示词是各集共用的，放在顶层 `characters/` 和 `art/`，以后新增角色也加在这里。

## 每一集的目录

以后每一集照下面的结构放。目录名用游戏的英文短名（小写，单词之间用连字符），不用集数或内部题号。某一项这一集没有，就不建那个目录。

```text
<游戏短名>/
├── README.md、README_en.md         开头三件事：这一集是什么、目录里有什么、怎么复现榜单
├── CONDITIONS.md、CONDITIONS_en.md 比赛条件和全部中断、补时、事故
├── prompt.md、prompt_en.md         开赛提示词原文；有多条消息时另建 prompts/
├── workspace/                      选手包原样：RULES.md、引擎、本地裁判和对战工具、模板、回放查看器、公开地图
├── engine/                         （可选）选手包里只有编译产物时，放引擎源码和构建脚本
├── bots/                           选手作品原样；分上下半场时用 half1/、half2/；作品不是代码时改名 designs/
├── notes/                          （可选）选手笔记、赛前赛后发言，原样
├── results/                        成绩表（.md 给人看，.json 给程序读）和逐局结果（.jsonl.gz）
├── replays/                        代表性回放（浏览器直接打开的 .html），README 写挑选规则
├── tournament/                     裁判、赛程（含种子）、计分脚本；赛时保密的地图和关卡放 tournament/hidden/
│   └── README.md                   复现榜单的一条命令，和重打全部对局的命令
├── renderer/                       渲染器
│   ├── README.md                   出片命令、依赖、测试过的 Blender 版本
│   ├── THIRD_PARTY_NOTICES.md      引用的第三方依赖
│   ├── src/                        回放转画面的代码
│   ├── themes/                     场景主题
│   └── models/                     兵种和道具模型
├── challenge.py                    （可选）一键挑战：用自己的程序和全部选手打一轮
└── appendix/                       （可选）不计成绩的附加实验
```

各集共用的东西放在仓库顶层：

```text
characters/                 各家 AI 的体素小人
├── README.md               文件格式、怎么读、怎么在渲染器里用
├── CREDITS.md              每个角色照哪张立绘做、形象出处
├── <角色>.glb、.json、_正面.png、_斜45.png   模型文件、方块数据、预览图
└── src/                    生成它们的脚本
art/                        角色立绘、表情差分、生图提示词和脚本
├── README.md               角色表、署名、模型和参数、参考了什么
├── portraits/              立绘（交付版）
├── expressions/<角色>/     表情差分（切好的单张和头像）
├── prompts/                定稿实际用到的提示词和任务单
└── tools/                  出图、整理、切图脚本
arena/                      通用对战平台（第 3 集夺旗的正式赛用它办）
community/                  社区投稿和社区榜
docs/                       跨集的说明（评分方法、开源范围等）
```

另外几条约定：

- **README 开头**：第一段说这一集比什么、几个选手、多少局；然后是一张"目录里有什么"的表；然后是"复现榜单"的命令。规则、成绩、回放、怎么玩放在后面。
- **复现榜单**：`tournament/README.md` 第一条命令读 `results/` 里的逐局结果，重算成绩并和成绩表逐项核对，几分钟内跑完；重打全部对局要很久的，单独写一条命令并注明大概用时。
- **原件不改名**：选手包、选手作品、比赛时裁判的输出都保留原来的文件名（包括中文名）。说明文档用英文文件名，英文版加 `_en` 后缀。
- **选手命名**：选手的目录或文件名用模型的短名（小写、连字符，例如 `gpt-6-astra`、`opus-5.5`），同一个模型用不同工具或多次参赛时加后缀区分，对照表写在 README 的"选手"一节。
- **开源时改了什么**：路径脱敏、补源码、修复查看器等，都写进 README 的"和比赛时的差别"。
- **社区投稿**：这一集如果收投稿，投稿目录是 `community/<游戏短名>/`，规则写在 [`community/README.md`](../community/README.md)。

# 计分和复现

## 一条命令重算个人榜

```text
python tournament/score.py
```

在 `boomerang/` 下运行，只要 Python 3.9+，不用编译、不用第三方包，约 20 秒。它读 [results/games.jsonl.gz](../results/README.md) 里的 32,904 局逐局结果，按比赛时的换算方式得到每局的得分（一对一：名次高的赢；四人局：名次分 3/2/1/0，并列平分，加每次击杀 1 分），交给比赛时的出榜程序 `rating.py` 拟合，再和 `results/海选成绩.json` 逐项核对。实测输出的最后一行：

```text
核对通过：13 位选手的实力值、区间、名次和误差判断与 results/海选成绩.json 完全一致。
```

`--quick` 不做重抽样，只核对实力值和名次，1 秒。

## 出榜方法

- 一对一实力值：全部一对一小局，胜 1、平 0.5、负 0，Bradley-Terry 拟合。
- 四人局实力值：每一小局里四个人两两比较这局的得分，高的算赢、相同算平，一局 6 组比较，同样拟合。
- 拟合用 `bt.py`（第 8 集足球用过的实现）：每对交过手的加一局虚拟平局，刻度 400/ln10（差 400 分约 10 比 1），十三位的平均定为 0。
- 个人实力值 = 两项平均，高的靠前；相同先比一对一实力值，再按固定抽签。
- 区间：一对一和四人局各自按地图整块重抽样（图数不变），每次两项都重新拟合再平均，2000 次，取 2.5%～97.5% 分位。相邻两名的差的区间含 0 就注明"差距在误差内"，名次照排、不加赛。

这些写在 `rating.py` 的文档字符串里，和选手包 [RULES.md](../workspace/RULES.md) 第 11 节一致。

## 文件

| 文件 | 内容 |
|---|---|
| `rating.py`、`bt.py` | 比赛时的出榜程序，原样。`rating.py` 末尾的 `main()` 要调用主办方不公开的运营脚本 `host.py`，复现不需要它，用 `score.py` |
| `score.py` | 从逐局结果重算并核对（开源时写的） |
| `rerun.py` | 重新生成赛程、重打对局（开源时由比赛时的赛事脚本改写：只改了路径和输出位置，赛程生成逐行相同） |
| `hidden/` | 赛时保密的 6 张地图：一对一 / 四人局的 `icefloes`（裂冰）、`ruins`（古塔）、`skybridge`（天桥）、`stonecircle`（石阵），4v4 的 `oldtown`（老城）、`forest`（林地）。公开的 4 张在 `workspace/maps/` |

## 重打对局

先编译裁判：`python build_engine.py`（见 [../README.md](../README.md)）。然后：

```text
python tournament/rerun.py --schedule-only   重新生成赛程，和 results/schedule.json.gz 逐局核对（几秒；实测逐局相同）
python tournament/rerun.py --limit 600       均匀抽 600 局重打，报告和比赛时名次一致的比例（几分钟）
python tournament/rerun.py                   重打全部 32,904 局并出榜（16 线程约 15～20 分钟），写到 rerun/
```

规则引擎没有随机数，但有几位选手的程序按时钟决定搜索多深，机器忙闲不同，同一局重打的结果就可能不同。实测抽 120 局重打，62 局（52%）名次和比赛时完全相同；做视频时重打的 117 局里 45 局相同。所以重打全部对局得到的是一份新的抽样，实力值会有几分的出入，名次靠得近的几对可能互换。正式成绩以 `results/` 里比赛时的逐局结果为准。

比赛时的 13,392 局是在 16 线程下打的；另外 19,512 局是 11-16 在机器同时跑着六位对照选手做题时打的（见 [CONDITIONS.md](../CONDITIONS.md#海选比赛)）。

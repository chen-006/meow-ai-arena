# 飞镖乱斗参赛说明

## 1. 整体思路

这是一个带显式不确定性假设的滚动时域控制器。它不依赖地图名字，也不读取其他选手的源码；所有地形、出生点和规则参数都来自 `GameInfo`。决策时使用 `dart::Game` 实际执行候选动作，避免自己重新实现投掷、回程、碰墙、格挡、相撞、身体互推等复杂规则时产生偏差。源码是一个 C++17 文件，运行时只读写比赛协议，不访问文件或网络。

最终采用按赛制分开的两套策略：一对一是跨版本联赛最强的 v8short 分支，四人局是该联赛四人项目最强的 v14cost2000 分支。不是根据对手名称或地图名称切换，只读规则中的 mode。两套策略的核心结构相同，但一对一保留更积极的突进，四人局更重视冲刺后的承诺成本和额外的来镖假设。最后又精简重复的近战方向，并减少无法行动时的无用计算。

角色每步重新选择动作。普通移动通常看未来 8 步，投掷、冲刺、挥砍等动作通常看 12 步，召回看 16 步。不同长度是有意的：移动下步就能重新决定，长时间假定它永远沿一个方向走会导致过度保守或来回抖动；召回则必须看完十二步引导。所有这些都是策略的搜索窗口，物理时长仍从配置读取。

### 延迟重建

保存自己最近 64 步的位置、状态、飞镖和已执行动作。收到观察时，把自己的状态换成四步前的历史，将别人观察里的四步前状态放在同一时刻，然后用规则引擎推到现在。最后用当前观察覆盖自己和自己的镖。这比简单地把对手坐标加四倍速度可靠得多：冲刺前摇、移动、收势，扔镖释放，召回起飞，受踢滑行，都能依照真实时间线推进。

对普通移动保持观测到的速度大小；投掷期间按移动比例还原输入意图。这个细节很重要：早期版本把任何非零速度都放大成全速，造成释放点、挡镖窗口和近战方向系统性偏差。

重建最近四步时不只有一种猜测。一对一有四个模型：延续原来动作；在最早恢复自由时朝历史位置出手；按历史速度做更长提前量的投掷；冲刺接近战。四人局增加第五个模型：朝历史位置加约四步速度的位置出手。已经开始的动作按引擎推进。特别注意“观察时还在硬直，但四步里已经结束并再次行动”的情况，不能只在延迟区间第一步尝试新动作。

开发中试过根据观察到的投掷方向与自己的历史速度，在线估计对手通常提前瞄准多少步。这在 v11 分支中存在，但跨版本联赛没有胜过旧的一对一分支，最终一对一不使用这项在线学习。四人分支保留第五种固定提前量假设。这里明确区分试过的算法和实际启用的算法。

### 战术搜索

移动候选包括静止、当前运动方向、寻路方向和均匀分布的 16 个方向；冲刺也枚举这些方向。近战方向来自各个估计局面中的敌人及来镖位置，能够选择挥砍格挡、冲刺接挥砍或空手踢。投掷枚举几个提前量，并与当前评估最好的两种走位组合。对于正在冲刺或被踢的人，额外按引擎推进其被锁定的轨迹，产生瞄准候选。

每个候选都在多种对手假设下评估，不先用单一局面把所有防守走位筛掉。评分混合平均收益和最坏情况收益；死亡代价远大于普通位置收益，击杀、武器回手、成功阻止逼近也有收益。对挥空和没有收益的冲刺收取代价，避免利用长时间动作硬直来“等待到一个好未来”的搜索假象。

具体是 75% 的模型平均分加 25% 的最坏模型分。死亡约扣 26000 分，四人局击杀约加 6500 分；一对一冲刺扣 140、挥空额外扣 1300，四人局冲刺扣 2000、挥空额外扣 2500。它们是局部搜索的启发式权重，不是比赛的实际计分公式。四人局选择参数和测试时始终使用正式的“名次分加击杀，再两两比较”规则。

四人和团队分支将方向相差约两度以内的近战候选合并。这是在候选集合层面的近似，不改变引擎的角度、命中范围或格挡规则。近战扇形大多数时候对这么小的方向差不敏感，合并可节省同一组来镖假设产生的重复推演。特别贴近格挡角边界时仍可能丢失一个精细方向，是明确接受的折衷。

对手的模拟策略包括保持运动、逼近空手目标、退避、捡镖、投掷、近战、冲刺接近战、躲镖和格挡。模拟对手对新出手的反应也受延迟约束，不能让他在我们按下投掷的同一步就知道镖的方向。另有一个保留武器、不随便出手的对手模型，防止程序总幻想对手会主动把自己锁在投掷硬直里。

飞镖相对运动的最近距离除了致死判定，还加一个较小的安全余量惩罚。这不是改引擎的命中半径，而是对擦边路线的策略扣分：延迟中对手释放点可能差几十至一百多毫米，不能把刚好差 1 毫米的格挡当成稳妥方案。

### 地形、武器和塌陷

地图上做八方向 Dijkstra 距离场，斜走不切坑角或墙角，并对靠墙的格子加代价。目的地综合敌人距离、自己的镖落点、其他敌人密度和未来塌陷决定。近处再由连续坐标的引擎推演检查身体碰墙与互推，所以寻路不是最终动作判定。

普通寻路不包含完整的冲刺图；跨坑靠枚举冲刺方向和短期引擎搜索完成。这使代码保持简单，但也是复杂地图上的一个限制。四人/团队分支的冲刺另有独立地形检查：即使战斗模拟认为中途已经获胜，也要确认完整冲刺能安全落地。冲刺接近战会恢复落坑判定，也单独检查其减速滑行。一对一保留旧分支的战斗推演检查；最后的单独对照没有证据说明把这些附加检查一起搬过去能提高胜率。

被踢的最后落点可能超出搜索窗口。四人/团队分支在终点评分前，继续按规则的速度衰减和推墙计算到硬直结束，再判断落坑。这一终端外推不继续模拟其他人的互推和新攻击，因此是近似估计；搜索窗口之内仍由完整 Game 处理。一对一保留普通短期推演和受踢惩罚。不会在实际搜索中把“途中经过坑”错误地判成已经死亡。

镖掉地后，根据安全性选择走过去、冲过去或召回。所有飞镖回程、召回穿墙、自己的回程接镖都在同一引擎推演中。评分鼓励重新持镖，避免长期空手被压制。选择目标格时考虑未来 12～24 步是否塌，当前位置距塌陷过近会扣分，永久保留格正确识别为 `cell_fall_step == -1`。

### 运行预算和团队模式

每步在已有最佳动作之后检查线程 CPU 软预算，并有推演步数硬上限作为第二道约束。一对一软预算约 4.5ms，四人约 3.5ms，团队约 3ms；推演步数上限分别约为 6500、3000、1000。每个候选的一组模型完整算完才检查，因此软预算不是严格实时上界。启动和协议解析也占裁判预算，最终以真实裁判检查为准。四人局把预算从 4500/4.5ms 收紧到 3000/3.5ms，是最后经过混合对手复核采用的调整。

4v4 使用两个模型、八个基本移动方向、更短的动作窗口和一个投掷走位组合来控制成本。队友属于同队，攻击误伤有额外惩罚；没有自己发明一套只有本程序理解的队友消息协议。进入无法接受动作的硬直时，先保存历史、更新观察，再直接返回空动作，不再计算没有用途的导航和搜索。

## 2. 强项、弱项与放弃的方案

强项是把动作时序、四步延迟、飞镖轨迹和地形放进同一套推演；在投掷、闪避、挡镖、捡镖和冲刺接近战之间能自动比较。四人局会避开同时暴露给多人的位置，并在保证存活的同时争取击杀分，不单纯躲到最后。多个可能局面使它不必押注对手只做一种动作。

弱项是对手的自由行动仍然靠模型猜测。搜索不是完备的博弈树，候选方向有限；多个对手的行为假设还存在相关性。看不见的草丛对手是明显弱点，长期消失后的具体位置无法确定。导航以格子中心为基础，对特别窄的通道、需要连续几次跨坑的复杂路线，未必找到好路径。对“动作结束后突然换方向”的预测仍会失准。4v4 主要保证合法、控制误伤，没有专门的团队战术训练或约定消息协议。

团队误伤仍然发生：最后的 24 局团队测试，本程序误伤队友 6 次。对队友未来走位的假设不充分，单靠模拟里的误伤惩罚不能保证真实队友不走进镖路。局部 CPU 预算也会让较晚生成的候选来不及完整比较；算法没有声称找到最优动作。

试过并未最终采用的方案：

- 保持五米以上远距离：在相同对照中明显退步。对手有时间躲或挡，自己却更容易在空手期被追。
- 固定绕圈、定期换绕圈方向：没有稳定超出普通搜索走位的收益。
- 在搜索未来自动替自己闪避：有时高估尚未真正得到的信息，测试收益不如较短的移动窗口。
- 把草丛里所有可能的最近位置当成敌人：对位置不确定性过于悲观，也会产生并不存在的攻击机会；实测对强档和中档均有退步，放弃这套强假设。
- 完全禁止朝持镖敌人冲刺：与提高冲刺代价相比，没有更好的综合成绩。软代价仍允许有充分把握的突进和跨坑。
- 只根据强档陪练选择版本：自我对战揭示某些版本打强档更好、却输给自己的激进旧版，所以后期加入跨版本联赛和自画地图。

自动参数搜索只调整少量战术权重，不在对局间保存学习结果。每局重新初始化，正式运行不需要任何训练文件。

## 4. 规则理解与疑点

最终以 `dart.hpp` 为权威，没有发现能够确认的裁判规则错误。以下是开发中容易误读而特意核对的地方：

- `cell_fall_step` 的永久保留格返回 -1，不是一个很大的将来时刻。若直接减当前步数做危险惩罚，会错误地排斥最终安全区。
- 起手方向一旦确定就不再变化；冲刺前摇、移动和收势都叫状态 7，必须看 timer 分段。
- 空手踢人在十二步滑行结束才判坑。短搜索必须额外检查最后落点。
- `Game::step` 预测到一局结束就不再前进。若预测击杀并不真实，过早停止可能掩盖冲刺之后掉坑，所以额外做纯地形验证。
- 从观察构造的 Game 不知道旧的踢人归属、未观察的动作和不可见人物的位置；这些信息不完整是接口设计的一部分。
- 某些高并发测试偶尔出现约 16～19ms 的单步计时尖峰，自己的版本和陪练都出现过。没有证据说明裁判有错；正式接口按进程周期计时、辅助预算函数按线程时间计时，两者也不是同一个量。最终代码留 CPU 余量并限制候选搜索，最后使用单独的 `check` 和低并发验证。
- strong 陪练在少数局里输出了负数 MSG，例如 `5311 -2659 0 0 0 -45`，被裁判正确判为非法。MSG 规则明定为 0..65535，所以这看起来是陪练编码问题，不是裁判问题。未修改陪练或过滤这些局；原始记录保留。本程序 MSG 恒为 0，没有这类非法输出。

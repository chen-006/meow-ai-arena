# notes.md —— 飞镖乱斗 · 海选交卷说明（选手 sonnet）

交卷文件：`player.cpp`（单个 C++17 文件，只用 `dart.hpp` 和标准库，约 880 行）。
本文按主办方要求分四部分：打法、强弱与取舍、本地测试结果、规则疑点。

---

## 1. 程序是怎么打的

一句话：**每一步用规则引擎本体（`dart::Game`）把局面往后推 16 步，在一组"对手可能怎么做"的假设下，给每个候选动作打分，取分最高的。**
没有手写"看到镖就往左躲"之类的规则表，躲、挡、冲、砍、扔都是候选动作之一，由推演结果决定。下面按模块说。

### 1.1 对齐时间：重建"现在"（解决 0.2 秒反应延迟）
- 每一步把自己的观察和动作存进 `rec[t]`。观察里别人是 `t-4` 步开始时的样子，自己是现在的。
- 所以先拼出"第 `t-4` 步开始时的完整局面"：自己用 `rec[t-4]` 里存的（当时是"现在"，所以是准的），别人用观察里的；
  再用 `Game::step` 一步步推到现在，推的时候**我自己用当年真实发出的动作**，对手用假设动作。
  这样人和人的推挤、我自己的镖、被踢后的滑行都和裁判逐位一致，不是"把别人旧位置当成现在"。
- 看不见的对手（在草丛里、离我 2.5 米以上）：记住最后一次看见的状态（没见过就用出生点），按"往我这边走、但不会比 2.6 米更近（更近我就看得见了）"估出一个**幽灵**放回推演里（引擎默认把看不见的人当成不存在，会让搜索对草丛里的对手完全"失明"，阴阳图左半边尤其明显）。幽灵只当威胁，不当瞄准目标。

### 1.2 对手假设（16 个，带权重）
每个假设 = 一种移动方式 × 是否躲镖 × 是否挡镖 × 在哪一步出手：
- 移动：保持原速度 / 停 / 逼近 / 后退 / 左横移 / 右横移（所有移动都带"不会自己走进坑或马上要塌的格子"的检查，否则推演里对手会"自杀"，被我当成击杀，早期版本吃过这个亏）。
- **出手时间假设**：对手在我看不到的这 4 步里（`T-3..T-1`）或接下来（`T..T+2`）出手，瞄准用的是"他自己看到的我"（4 步以前的位置 + 4 步前的速度 × 飞行步数），所以我的走位只要偏离线性外推就能躲掉——这个模型比"他知道我现在在哪"现实得多。还有"逼近到 4.5 米就扔""6.8 米内立刻扔"两类，模仿参考强档"见面就扔"的节奏。
- 近战：贴到 1.45 米就挥砍 / 踢；中距离冲刺斩。
- 躲镖：我的镖出手 5 步后（他最早能看到的时间）按垂直方向躲。**挡镖**：他持镖时，下一步我的镖会到他前方 0.78~1.45 米处就朝镖挥砍（参考强档真的会这么做，我的远距离扔镖被挡了很多次，见第 2 节）。
- 对手"会不会躲 / 会不会挡"是先验概率（`alert_p=0.5`，`blk_p=0.3`），**在线更新**：只要看到我的镖在飞行中落地、落点离对手 2.8 米内、附近没墙、对手自己的镖没同时落地，就判定"被挡"，两个概率升到 0.92~0.95，之后的假设里大多数对手都会挡 / 躲；我的镖平安飞回则 `blk_p` 打 0.75 折。

### 1.3 候选动作
- 移动：16 个方向 + 停（每个方向在整个推演里保持）。
- 扔镖：对每个目标按镖速表（900,850,…）算拦截点，取拦截点 ±0.12/0.24 弧度共 5 个方向 + 直瞄一个。只在目标预测距离 ≤ `throw_max`（5.2~6.6 米，随对手是否会挡调整）或目标在硬直里时才考虑——远距离扔镖大概率被挡 / 躲，白白丢掉镖。
- 近战：持镖挥砍只在预测距离 < 1.8 米；空手踢只在 < 1.2 米或对手在蓄势 / 硬直 / 召回里。（踢和挥砍锁死 7~8 步，是最容易被一镖带走的动作，所以限制得很严。）
- **挡镖**：对每把飞向我的别人的镖，先算它"下一步开始时"的位置，朝那里挥砍（± 约 10 度共 3 个候选），由推演验证挡不挡得住。
- 冲刺：只保留两种——①冲刺斩（对 4.3 米内的目标冲刺，第 3、4、5 步接挥砍）；②自己的镖落在 3.6 米外、周围 6.5 米内没有对手时，朝镖冲过去。**不做"随便朝某个方向冲"和"冲到对手跟前"**：这两类候选一度存在，实测它们是最大的输球来源（冲刺 8 步里前后摇 4 步不能动、方向定死，对手一镖就带走；冲到一半转近战又会把自己锁 6~8 步）。去掉之后 1v1 对 weak / mid 的胜率从 73% / 70% 升到 83~85%，四人局也明显变好（见 3.2、3.3）。冲刺里每一步还会重新评估"现在就近战结束冲刺""再冲 1~3 步后再近战""一直冲"，防止冲刺终点落进坑（冲刺中途转近战会恢复落坑判定，这个坑我自己踩过：见第 4 节）。
- 召回：只在所有对手都离我 4.5 米以外、且持镖的对手离我 7.5 米以外时才考虑（召回站桩 12 步，贴脸召回基本是送死）；召回引导中给"停"一个加分，避免来回取消。

### 1.4 评估
- 终局：我死 = −1000（越晚死越不糟）；对手被我击杀 +350 / +500（全灭）；对手自己掉坑只给很少的分（推演里对手"自杀"不可信）。
- 局面（推演 16 步后）：
  - **镖就绪度** `ready`：多久能再用上镖（在手 / 去程 / 回程 / 地上走回去 / 召回引导）→ 0..1。我的就绪度 × 65 − 对手的 × 50。这条保证"手里有镖"永远比"镖在外面"值钱，推演才不会因为任何位置奖励就乱把镖扔掉。
  - 距离：双方有镖时嫌近（< 6.6 米或更近 < 4.8 米加重）；我明显占优（对手空手）时想靠近到 3.4 米；对手占优时嫌近（< 7.5 米）。
  - 塌陷：用"到最后落脚区（永不塌格子，没有就用最晚塌的）的步数"和"这格还有多久塌"比，来不及就重罚。
  - **坑边惩罚**：和对手 3.5 米内贴身时，数我周围 1.5 米内（含已塌）的坑格，越多越扣（最多 −40）。目的是防"被踢进坑"（被踢滑 2.8 米，停在坑里就出局）：塌陷后期整场都是坑边，这条会把我推向落脚区中间。
- 多个假设加权平均，死亡结果乘 1.5（风险厌恶：承诺类动作——冲刺、挥砍、踢——若有 20% 的几率送命就不划算）。每个候选的分数再加 ±1 的随机扰动，避免走位被对手预测。

### 1.5 算力控制
- 引擎一步约 0.5 微秒（1v1）。每步先用 5 个关键假设给全部候选打"快速分"，再取前 4（四人局前 3）个，用全部 16 个假设做完整评估。
- **用推演步数当预算**（1v1 4000 步、四人局 2400 步），不用时钟：本机 `thread_cpu_100ns()` 的分辨率是 15.6 毫秒一档，拿它限时会随机截断搜索（实测 17% 的决策被"截断"，结果波动很大，换成步数预算后结果可复现；正常局面下预算基本用不满）。
- 另加一道**应急刹车**：墙上时钟超过 7 毫秒就停止加候选，超过 8 毫秒就跳过剩下的完整评估（只防机器特别慢的极端情况；本机正常 / 16 路并行压测下从未触发，加刹车前后同一批种子的结果逐局一致）。
- `match.py check`（2 路并行）：每步平均约 1.4~2.4 毫秒（随机器当时的忙闲），最多约 2.9~4.7 毫秒，第 0 步最多 26~44 毫秒；16 路并行压测下我的单步最多约 5~8 毫秒（四人局最多约 7 毫秒，仍在 10 毫秒内；偶有一次系统抖动出现过 18 毫秒的孤例，累计远小于 20 次）。

## 2. 强在哪里、弱在哪里；试过没用上的

**强**
- 躲镖和防身是"推演出来的"，对已出手的镖（观察里能看到）推演是精确的；对没看到的镖用出手时间假设覆盖，几乎不会被"看得到的镖"打死，也不会走进自己的坑。
- 会挡镖、会冲刺斩、会在对手蓄势 / 召回 / 硬直时抓机会；不乱扔镖、不贴脸召回。
- 对草丛里看不见的对手有幽灵估计；对塌陷有"到落脚区还来不来得及"的估计。
- 对手建模在线更新（被挡一次就提高警惕），对弱对手（不躲不挡）仍然愿意在 ≤ 6.6 米扔镖。

**弱**
- 对手假设是我拍脑袋的 16 种，真实对手如果有我没想到的套路（例如故意在 5 米外长时间绕圈、专门在我冲刺时扔），推演会被骗。
- 对"强档"这类见面就扔、会挡会躲的对手，我只有 55~58% 左右（见 3；这是 1v1，四人局相对好一些），主要输在：我的镖被挡后我空手、对手持镖逼近（空手时我只有躲和踢）；被踢进坑；冲刺 / 挥砍锁死时被一镖带走。
- 评估函数里的权重（65 / 50、6.6 米、3.4 米…）都是手调，没有系统调参，噪声又大（40 局的标准误约 8%），所以很多改动我无法证明是真的变好。
- 四人局里把三个对手都当成"都冲着我来"，偏保守；没有利用"别人在互相打"的机会做主动的第三方击杀。
- 4v4 没做任何针对性处理（队友当成不动的东西；海选不计分）。
- 最后落脚区（12 秒后塌陷、18 秒只剩约 8~12 平方米）里的近身缠斗：被踢进坑、被挥砍的比例偏高，我没有专门的残局策略。
- 对手的镖如果落在我脚边、之后被他召回，镖会穿过我（召回飞行穿墙）；我只在能从观察里看到他"召回引导中"时才会提前躲开。

**试过没用上 / 放弃的**
- 早期版本（v1~v6）用"对手自己走进坑也算击杀"的奖励，结果推演会奖励"把对手吓得往坑里跑"的远距离扔镖：开局 13 米外就把镖扔出去。已经修掉（对手移动加坑检查，自杀不给分）。
- 不加远距离扔镖限制的版本对弱档 / 中档击杀多一点，但对强档的挡镖没有防备，镖被挡下后空手被追着打，整体更差。
- 想过用 `thread_cpu_100ns` 做时间预算，被它 15.6 毫秒的粒度否掉了。
- 没来得及做：对手行为的贝叶斯后验（用他过去几步的轨迹更新假设权重）、专门的"诱敌挡镖再反击"套路、四人局里的主动三方博弈。

## 3. 本地测试结果

所有胜率都是"我 : 对手 : 平"，1v1 每个种子两边各坐一次，地图 twinlakes / yinyang 轮流（只有这两张公开的 1v1 图）。
同一程序重复跑结果差很大（40 局标准误约 8 个百分点，机器上还有别的任务会改变并发），所以只能看大趋势。

| 对局 | 结果 |
|---|---|
| template : weak | 0 : 20 |
| mid : weak | 20 : 0 |
| strong : mid | 38 : 2（40 局） |

- 对旧版本：v12 对 v8 35:24:1、对 v3 39:21（60 局）；v22 比它们又好了一截（对 weak / mid 的胜率从 50~70% 升到 80% 以上）。
- **交卷版 v26 的最后一轮确认（新种子 1100+，60 局一组）：对 weak 45:12:3，对 mid 52:8，对 strong 34:26。** 合计 v26 对 strong 的几批是 41:19、63:57、34:26，共 138:102（约 58%）。
- 交卷版 v26 相对 v25：对 strong 同一批 180 局种子 104:76 对 94:86（+10 局，在噪声边缘但方向一致），对 weak / mid 持平。
- 发现并修掉的大问题：①对手推演"自杀"被奖励；②草丛里的对手在推演里不存在（对 weak 在阴阳图被直接打死，从 54% 提到 76%）；③冲刺终点落坑（冲刺中途转近战恢复落坑判定）；④用 CPU 计时器截断搜索导致结果随机波动；⑤"朝任意方向冲刺 / 冲到对手跟前"这类承诺动作是最大的输球来源，去掉后 weak / mid 胜率 +12 个百分点。

### 3.4 其他检查
- `python match.py check player.cpp`（交卷版 v26）：通过，每步平均 1.4~2.4 毫秒，最多 3.0~4.7 毫秒，第 0 步最多 26~44 毫秒；无超时、无非法输出、无崩溃（含 4v4 一局）。
- 4v4 抽查（`match.py team player.cpp --vs mid --games 8`）：6 胜 2 负，单步最多 4.4 毫秒，无故障（海选不计分，仅确认稳定；队友被当成"不动的东西"，误伤队友不少，没做优化）。

## 4. 规则里没看懂或有歧义的地方 / 怀疑引擎有问题的地方

1. **`dart::thread_cpu_100ns()` 在本机的分辨率是 15.6 毫秒一档**（`GetThreadTimes` 的时钟粒度），README 推荐用它做 5 毫秒预算，实际会随机提前收手（读数从 0 直接跳到 15.62）。建议提醒选手改用步数预算或高精度计时。
2. `Game(info(), obs)` 对看不见的对手标 `unknown`：推演里他们不存在，也没有任何办法在不改字段的情况下把他们放回去（我自己手动改了 `x,y,unknown`）。文档里有写，但新手很容易忽略，在草丛多的图上等于让搜索失明。
3. 冲刺接近战（5.5）规则"冲刺立刻结束、之后按不能移动减速"，所以**在坑上方给近战 = 当场恢复落坑判定**；规则里写了，但"冲刺越坑途中转近战可能直接掉下去"不太直观，我踩过一次。
4. 5.4：踢中后"记给踢的人"与"被踢滑过坑不掉"这两条我都按代码理解，没发现与代码冲突的地方。
5. 本机 16 路并行时，参考强档自己也会出现 CPU 超时"故障"（单步最多约 9 毫秒），说明并行度对结果有影响；`RULES.md` 第 10 节已提到正式赛会固定并发，我按这个做了步数预算。
6. 没发现裁判结算和 `RULES.md` 不一致的地方。

## 5. 目录里的其他文件（都是我自己的辅助工具，不影响交卷）
- `rv.py`：回放时间线工具（`python rv.py 回放.txt` 打印事件和双方距离；加起止步数则逐步打印状态和动作）。
- `tools/deaths.py`：批量统计"我是怎么死的"（死因、距离、双方状态、镖状态），本次调参主要靠它找输球模式。
- `tools/patch*.py`、`tools/new_decide.txt`：每个版本的修改脚本（已应用）；`old/`：各版本的 `player.cpp` 备份（v1~v26）；`exp1.cpp ~ exp4.cpp`：先验、刹车、坑边惩罚的实验副本。
- `tools/maps/`：两张自己画的测试图；`tools/bench.cpp`：引擎单步耗时测试（1v1 约 0.5 微秒 / 步）。

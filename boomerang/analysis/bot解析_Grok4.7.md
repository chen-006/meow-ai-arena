## 1. 一段话讲清它的打法

Grok 是一个“规矩很多的保镖”。它先用一个手写的老练脚本 `smart` 给出“本能答案”，再拿二十来个备选动作去和这个本能答案比，比法是让**场上所有人（包括它自己）都按同一套简单脚本 `cheap` 打下去**，往后演 0.8 秒，挑分最高的，前三名再加演到 1.2 秒复赛。它出手很挑：对手空着、手里有镖时，3.9 米外绝不扔（算过：再远对方来得及躲或劈）。它是全场最爱**挥刀劈镖**的选手之一，也会把自己的回程镖“拉”到对手身后再打回来。它最大的怪癖是**极度怕镖擦身**：飞镖离自己 1.17 米内，每一步扣的分比杀一个人还多；而一个藏在死亡计算里的漏洞，让它在“反正要死”的推演里觉得**立刻跳湖最划算**——这就是它正式比赛单挑落坑 333 次、四人局 987 次的来源之一。

## 3. 逐个关键问题

### 3.1 0.2 秒延迟怎么补
- 和多数推演派一样“从过去重演到现在”：4 步前那一刻的自己从历史里取（L1080–1085），4 步里自己用真实动作，别人用 `continue_act`（按当前速度方向续走、召回中继续召回，L1058–1068），推完后把自己改回零延迟真值（L1113–1117）。
- 重演里别人不出手。“别人可能已经扔了”交给第 6 步的幻影世界。
- 这个幻影有一个严谨的细节：造镖时逐步检查这支假想镖会不会**已经打中过去 4 步里的我**（L1209–1213），会的话就作废——因为我现在还活着，这个假设和事实矛盾。这正是 GLM 缺的那一步（见 GLM 解析）。

### 3.2 怎么预测对手、有没有局内学习
- 推演里对手只有一套脚本 `cheap`（L886–1028）：
  1. 有看得见的来镖（距离 3.2 米内或 4 步内能到）就往垂直方向横闪一步，挑闪完离镖更远的一侧；
  2. 对方挥砍起手了，往外让一步（让贴边的挥砍在推演里落空，L998–1003）；
  3. 满足 `want_throw` 就带 60% 提前量扔镖并横移；
  4. 满足 `melee_commit` 就近战；
  5. 否则按 `goal_for` 走向目标点（自己用格子导航，别人直线 + 避坑）。
- **反应延迟门 `React`**（L94–99、L395–401、L1042–1043）：推演第 `s` 步新扔出的镖，其他人要到第 `s+4` 步才“看得见”、才会躲。推演开始前已经在飞的镖立刻可见。
- 自己在推演第 1 步以后也用同一个 `cheap`——这是“双方都按同一套规矩打”的对称推演。
- **没有局内学习**：没有统计对手习惯。写了 `mem[k]`（L126–130、L1284–1290）但全文件没有一处读取（`grep "mem\["` 只有声明和写入）。

### 3.3 搜索是什么搜索、往后推几步、候选多少
- “两阶段短程推演”：第 0 步执行候选，之后全员走 `cheap`。
- 候选最多 28 个（`MAXC = 28`，L14），典型 12～20 个：本能答案 1、停 1（2 米内没镖时）、8 方向、闪避 2、扔镖 5（左右横移各一、顺惯性一、少提前量一、直瞄一，L1356–1368）、近战 1、挡镖 1、冲刺 0～3、召回 0～1。
- 推演长度：交战时单挑初赛 16 步（0.8 秒），复赛前 3 名 24 步（1.2 秒）；四人局 12/16 步；幻影世界单挑 10 步、四人局 8 步。脚下快塌时最长 30 步。
- 合分：真实世界与幻影世界**直接取较小值**（L1459、L1483），不做加权。

### 3.4 怎么剪枝和控时
- **生成门槛**很严：`want_throw`（L258–287）规定 1.5～6.9 米、无墙、不挡队友；对**自由且持镖**的目标只在 3.9 米内扔，对空手目标 4.8 米，对硬直 ≥2 步的 5.6 米、≥5 步的 6.6 米；四人局里目标正被别人贴身（“在忙别的架”）可放宽到 5.4 米。3.9 米来自它开赛时的推算：扔出后对方 5 步后才看见并起刀，那时镖飞了 3.3 米，加 0.72 米命中半径约 4.02 米（早先一轮分析节点一，Sol 核过：是特定时序下的边界，不是任何状态都保证挡住）。
- **冲刺门槛**：4.5 米内有飞镖、或目标持镖且 10 步内能出手且在 6.8 米内，一律不生成冲刺（L1376–1381）；冲刺落点要能站、落点 12 步内不塌（L366–386）。
- **初赛筛前 3 进复赛**（L1474）。
- **限时 7 毫秒**（L132）。Windows 下这个 CPU 计时会整段跳 15.625 毫秒，所以偶尔会被截断（早先一轮分析已用探针证实 16 局里有 7 局出现跳变）。
- 一个小漏洞：复赛前没把 `best_sc` 清零（L1450、L1486），复赛分只有超过初赛冠军分才会换人；而复赛推得更长、擦身罚分累积更多，通常更低，所以**复赛基本改不动初赛的选择**。早先一轮分析单独修它的对照没有显著差别（Sol 核：那个改版还附带改了截断时的回退规则）。

### 3.5 打分里最重的几项（换算）
活着的基础分 `+10 亿`，死了 `−8 亿`，一条命差 18 亿。所以真正决定“活着的动作之间谁好”的是下面这些项（L811–883、L1030–1056）：

|---|---|---|---|
| **飞镖离我 1.17 米内（每步）** | **−42 万** | 比亲手杀一人（约 +33 万）还重 1.3 倍 | L1051 |
| 飞镖离我 1.17～1.62 米（每步） | −5 万 | | L1052 |
| 亲手杀一人 | +26 万；另外每少一个活着的敌人 +7 万 | 合约 +33 万 | L831–832 |
| 队友死 | −45 万 | | L833 |
| 手里有镖 / 镖在飞 / 镖在地上 | +9 万 / +5 万 / +2.5 万 − 0.5 分/毫米 | 镖丢在 3 米外比在手里少约 6.7 万，约 1/5 个人头 | L836–839 |
| 正在召回 / 正在被踢或被砍硬直 | −12 万 / −14 万 | | L840–841 |
| 我空手、最近的敌人持镖且在 4.8 米内 | 每近 1 米 −1.8 万（贴身约 −7 万） | | L864–865 |
| 双方都持镖 | 偏离理想距离（单挑 3.4、四人 4.1 米）每 1 米 −500；1.45 米内再 −6 万 | | L860–863 |

| 自己硬直/召回时 3.2 米内有敌人 | −9 万 | | L881 |
| 死亡（推演中） | `−8 亿 + 3000×存活步 + 22 万×击杀`；同归于尽（敌全死）`+8000 万` | 晚死 1 步只多 3000 分 = 擦身一步的 1/140 | L822–829 |

要点：
1. **过度恐镖**：只要推演里有一步镖离自己 1.17 米内，就抵消掉一次击杀。
2. **致命的耦合**：推演中途死亡时直接返回 `evaluate(g) - graze`（L1035、L1047），也就是把**死之前累积的擦身罚分**一起扣掉；而“第 0 步就掉坑”的动作死得最早、来不及累积任何擦身罚分。于是在“所有选项都会死”的推演里，**立刻跳坑比在岸上先被擦几下再死分更高**。早先一轮分析已用逐候选探针抓到实例（阴阳图第 28 步，3 个立即落坑的候选以 `−7.99913 亿` 胜过 11 个岸上候选，Sol 核实）。

### 3.6 扔镖、挡镖、召回
- **扔镖**：60% 提前量（L224–227，注释：速度来自延迟估计，全额预瞄容易甩过急停），撞墙就改直瞄。候选同时带左右横移，避免对扔时站着挨镖。
- **挡镖** `block_now`（L640–674）：用来镖**下一步**的预测位置（挥刀下一步结算），要求这一步还没被打中、挥砍够得着、再往后 6 步内确实会擦到 0.92 米内，才挥。智能脚本里“来镖下一步进 1.5 米就挡”优先于扔镖和走位（L738–745）。
- **回程镖拉线**（`goal_for` 的 kind 3，L598–610）：自己的镖在回程时，目标点设在“镖→对手连线延长 1 米、对手身后”的位置——回程镖追主人，主人站到对手身后，镖就会穿过对手。
- **召回**：只在最近敌人 11 米外且对方空手时（L1396–1404、L765–776），几乎不用（自跑四人局场均 0.01～0.05 次）。

### 3.7 怎么走位躲镖
- 候选里只有“最近一支 3.2 米内来镖的两个垂直方向”是专门的闪避（L1332–1352），其余靠 8 方向和本能答案。本能答案里的 `steer`（L465–536）对 17 个方向各做 6 步轻量模拟，躲开已知镖的轨迹并靠近目标。
- 交战走位有一个“画 Z 字”的设计：目标点在理想距离上再侧移 ±1.1 米，每 6 步换边（L624–631）。
- 擦身罚分让它离镖远远的；暗箭只靠一个幻影世界。

### 3.8 草丛和看不见的对手
**实际完全没管。** 看不见的敌人在推演里不存在（引擎规定 unknown 不动不出手），`mem[k]` 每步写入位置、速度、镖状态却从不读取；L1306 的注释“看不见但刚进草的人：不放进物理模拟，只在评分里躲开最后位置”没有对应代码。没有做单变量对照，“草丛失明让它在多草的 yinyang 输得最惨”只是推测：正式对 GLM 在 yinyang `11:27`，本文复跑 588 局里 yinyang `35:63`，但 yinyang 也是水坑多、它跳湖多的图，原因分不开。

### 3.9 四人局专门处理
挑目标时“别人比我离他更近就扣 1200 分，让他们先打”（L202–209）；目标被别人贴身时允许 5.4 米偷袭（L272–281）；理想距离 4.1 米；4.5 米内多个持镖敌人重罚；推演缩短到 12/16 步、幻影 8 步。4v4 有 16 位队友消息（格子坐标 + 镖状态，L1257–1268、L1120–1139）。

### 3.10 记住了哪些东西
自己 64 步历史；导航网格；`mem[k]`（死数据）。没有跨局记忆，没有对手统计。

## 4. 最聪明的设计

### 4.1 劈镖：全场最勤快的“刀挡飞镖”
- 设计见 3.6：算准“挥刀那一步结算时镖在哪”，确认这一步不会先被打中、确实会被打中才挥。
- **对局里能看到的样子**：本文复跑对 GLM 228 局（`rep_duel_base\`），Grok 劈落 66 次镖，GLM 只有 8 次；复跑四人局 144 局（Grok + GLM + Hydrogen + Carbon，（主办方本地文件，未收录））Grok 场均劈镖 0.36 次，Hydrogen 0.11、GLM 0.08、Carbon 0.01。正式成绩“被镖打死”的次数它也比邻居少（单挑 903 次，Hydrogen 959、GLM 1070）——但 Sol 提醒过，较早掉坑会减少后来被镖打的机会，这个比较不能直接当作“防镖能力”。
- 复跑实例：（主办方本地文件，未收录）（twinlakes，Grok 0 号位）：0.75 秒 GLM 出镖 → 1.00 秒 Grok 起刀 → **1.05 秒劈落** → 1.45 秒 Grok 反手出镖 → 1.75 秒命中 GLM。同目录 `g21、g22、g24、g29、g31、g40、g64` 也是“劈镖后 2 秒内反杀”。

### 4.2 把回程镖“拉”到对手身后
- 设计见 3.6（L598–610）：回程时站到对手身后的延长线上。
- 复跑对 GLM 228 局：Grok 的回程镖命中 15 次，GLM 只有 2 次（GLM 的 79 次命中里 75 次是去程）。
- 复跑实例：`rep_duel_base\g57.txt`（yinyang，Grok 1 号位）：2.60 秒出镖 → 3.20 秒镖到最远点折返 → 3.50 秒 Grok 冲刺换位 → **3.70 秒回程镖从 GLM 背后打中**。同类还有 `g8、g40、g60、g73、g75`。

### 4.3 精确踢坑与反应延迟门
- `kick_into_pit`（L307–324）按踢中后 12 步、总滑行 2.797 米算落点，落点不能站就值得踢；`melee_commit`（L328–354）对空手目标放宽到“能踢进坑就踢”。复跑实例：`rep_duel_base\g58.txt`（yinyang）2.65 秒双方同时起脚、2.70 秒同时踢中，**3.30 秒 GLM 滑进坑里**（记为 Grok 击杀）。
- 反应延迟门 `React` 在推演里让对手晚 4 步才看到我的新镖，是一个干净的建模。但**单变量对照测不出它的好处**：只加一行让对手立刻看见（`grok_noreact.cpp`，L397 后加 `if (true) return true;`），588 局对 GLM 的得分率 `44.4%`，原版 `42.3%`。可以讲它“想得对”，不能讲它“因此赢球”。

## 5. 最致命的弱点

### 5.1 “擦身罚分 + 死亡返回”耦合：推演里跳湖最划算
- 机制见 3.5 要点 2（L1035、L1047、L1051–1052）。
- **对局里的样子**（复跑，`rep_duel_base\`）：228 局里 Grok 在塌陷开始前、没人击杀的落坑 22 次。
  - `g32.txt`（twinlakes，Grok 0 号位）：0.85 秒 GLM 在 8 米外出镖，**1.00 秒 Grok 自己走进湖里**——镖离它还很远。
  - `g23.txt`（twinlakes，Grok 1 号位）：0.95 秒冲刺停下，**1.30 秒落水**，GLM 全程没出过镖（只可能是幻影世界里“必死”）。
  - 早先一轮分析的逐候选探针局：（主办方本地文件，未收录） 第 1.40 秒（Sol 核过）。
- **单变量对照**（只删两处 `- graze`，`grok_fixgraze.cpp`，与原版仅这两行不同；同种子同赛程）：

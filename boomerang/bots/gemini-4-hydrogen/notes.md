# 《飞镖乱斗》参赛总结与技术说明（`player.cpp` v15）

---

## 一、整体思路、技术与算法

我的程序采用**确定性引擎精确前向推演 + 延时状态对齐 + 多对手模型评估**的决策框架：每步在严格控制在 `5.2 ms`（`CPU_BUDGET_100NS = 52000`，远低于 `10 ms` 单步上限）的预算内，还原当前真实局面，生成约 30～70 个去重候选动作，利用裁判同源的 `dart::Game::step` 向前推演 `H` 步并综合评估。

### 1. 地图与塌陷预处理（`MapKnowledge`，第 0 步初始化）
- **多阶段地图（`PhaseInfo`）**：开局读取地图与塌陷参数（`wave_fall_step`），预先为每一波塌陷 `0..m.nwave` 生成对应的 `live_map`、`walk_ok` 可站立掩码（包含半径碰撞和地形安全检查 `point_standable_safe`）、5×5 邻域开阔度 `openness`，以及以永久安全格（或最晚塌陷格）为终点的多源 Dijkstra `safe_dist`（直走代价 20，斜走 28 且禁切墙角）。
- **跨坑冲刺桥（`DashBridge`）**：从所有邻接深坑的站立格出发，对 16 个方向模拟完整 `dash_t` 步 `move_body` 位移；若途经坑格（`crossed_pit`）且终点满足 `point_standable_safe`，则记为可行冲刺过坑边，供后续候选生成主动跨湖/过桥（如 `canyon`、`custom_islands`）。
- **按需最短路寻路（`compute_dist_from` / `next_step_dir`）**：对目标坐标运行同地形安全约束 Dijkstra；若起点到终点直线无墙且无坑则直接直线走，否则沿代价梯度追踪下一格中心。

### 2. 延时对齐、隐身信念与 4v4 通信（`reconstruct_game` / `HiddenBelief`）
- **动作与观测历史环形缓冲**：维护长度 `MAX_HIST = 32` 的历史记录（`hist_obs`、`hist_act`）。
- **状态对齐推演（`t_obs -> o.t`）**：从观察时刻 `t_obs = max(0, o.t - cf.delay)` 出发，结合自身在 `t_obs` 的完整观察（`hist_obs[t_obs]`）和对手观察，以各自 `hist_act`（自己）与持续惯性/拾镖动作（`predict_other_action` `mode=0`）调用 `Game::step` 前推 `age = o.t - t_obs` 步，最后用实时准确的 `o.me()`、`o.my_dart()` 覆盖自身状态，同时显式回填 `g.p[k].team = gi.team[k]`，修正 `Obs` 仅传 15 个字段不含队号的问题。
- **空中拼镖（`CLASH`）修正**：若推演显示自己飞镖仍在飞行，但实测 `o.my_dart().st == D_GROUND`，则判定这 4 步内发生了未观测到的拼镖，立即将 1800 mm 内最接近我方飞镖落点的飞行敌镖同步修正为 `D_GROUND`。
- **草丛隐身追踪（`HiddenBelief`）**：对不可见对手（`!vis`），以最后目击点（或出生点）为起点，每过 1 步在当前阶段的 `C_GRASS` 格子做 3×3 膨胀，剔除我方视野范围 `see_r - CELL` 内的格子，以可行草丛格子重心 `(est_x, est_y)` 估计对手位置；若集合为空则回退至视野外全部草丛格。`min_armed_enemy_los_dist` 对刚隐入草丛 ≤ 16 步且飞镖不在地上的敌手保留盲区警戒距离。
- **4v4 队友坐标同步（`encode_msg / decode_msg`）**：在 `M_TEAM` 且 `msg_max >= 65535` 时，把自身坐标按 250 mm 量化为 `qx(7 bit) + qy(6 bit) + 3 bit 滚动校验和`（融合 `t & 7`）。由于 `o.p[k].msg` 是无延迟下发（`o.t - 1`），通过 2 步校验握手（`mate_proto[k]`）确认队友同协议后，将队友坐标更新至比 `DELAY=4` 更新鲜的 `(mx + vx, my + vy)`。

### 3. 候选生成与因果避险（`decide` / `solve_lead_throw` / `collect_cone_threats`）
- **分支式候选生成**：
  - 处于 `S_DASH` 移动段时：考虑保持冲刺（`Action()`），以及结合 `dash_v` 位移半步偏置 `(ex - nx, ey - ny)` 的 `DASH_SLASH`（持镖砍人或挡飞来的敌镖）与 `DASH_KICK`（无镖踢人）。
  - 处于 `S_THROW/S_THROWN` 前后摇时：优先生成后撤/寻路/16 向移动微调。
  - 处于 `S_FREE`（含可中断 `S_RECALL`）时：加入寻路方向、垂直于飞来敌镖的切线闪避方向、16 方向与原地停步；仅在无近身持镖敌人（`min_arm_d > 5200`）且周围 `4500 mm` 无飞行敌镖时发起 `A_RECALL`；对可及目标用 `solve_lead_throw`（带 3 步细分碰墙与避坑裁剪）生成 90% 提前量、55% 急停保守提前量及直射三档 `A_THROW`（近距 `< 3600 mm` 投掷时配合拉距后撤，否则横向走位）；生成持镖挡镖/近战砍、无镖踢、以及朝安全区/敌方落镖/跨坑 `DashBridge`/8 向 `A_DASH`。
- **4v4 误伤过滤**：`throw_hits_mate` 在 `t_off in {0, 2, 4, 6, 8, 10}` 内按队友当前速度与 `S_DASH` 轨迹用动态膨胀半径拦截会穿过队友路径的投掷；`melee_hits_mate` 对挥砍/挡镖/踢统一检查 `t_off in {0, 1, 2}`，把团队误伤压到极低水平。
- **延时盲区威胁锥（`collect_cone_threats`）**：针对处于 `DELAY=4` 延迟期间可能已经出手的可见持镖敌手（`<= 4600 mm`），从敌人位置向我方历史位置 `old_mx, old_my` 构建未暴露的飞行威胁锥，同时对快升起的 `D_RISE` 和回飞拐弯 `D_BACK / D_CALL` 飞镖两侧生成双翼惩罚线段，非自由/冲刺硬直状态下惩罚权重 ×3。

### 4. 多对手模型前向推演与评估（`rollout_candidate` / `evaluate_state`）
- **模式自适应推演深度**：`M_DUEL` 为 `H = 11` 步，`M_FFA` 为 `H = 9` 步，`M_TEAM` 为 `H = 7` 步。
- **双核心对手模型 + 刹车稳健度加权**：
  - `enemy_mode = 1`（`s1`，积极格挡/切线躲镖）与 `enemy_mode = 2`（`s2`，近战反击、抓硬直 `timer >= 5` 冲刺斩及提前量反扔），合成公式 `tot = (s1 * 2 + s2 * 2 + min(s1, s2)) / 5`。
  - 对优质投掷候选（`tag == 1 && s2 > 200000`），额外用 `enemy_mode = 3`（假设对手先急停 2 步再躲镖）评估 `s3`，并加权 `+min(s3 / 5, 1200000)` 作为稳健提前量平局决胜。
- **严防未来视与幻觉（因果律修正）**：
  - `predict_other_action` 在 `s_step < cf.delay`（对手还未观察到我方新动向）的步数禁止使用“预知敌方后续位移的未来视提前量”，而在 `M_FFA / M_TEAM` 中更将 `mode = 2` 限制在 `s == 0 || s >= cf.delay`，避免多人局同时被三个假想反扔吓瘫。
  - **`dash_uncancelled_safe`（v15 关键修复）**：冲刺候选若不取消就会落入深坑（`C_PIT`），在推演后续步 `s >= 1` 中严禁依赖“将来正好能靠 `DASH_SLASH` 取消刹车”的乐观幻觉，且取消推演中无镖时的自动未来 `DASH_KICK`（仅在当前已在冲刺时于 `s == 0` 实时检查 `DASH_KICK`）。
- **终局评估（`evaluate_state`）**：区分主动落坑（`K_FALL && killer < 0`，`-25,000,000`）与被镖致死（`-10,000,000`），避免绝境跳坑躲镖；检查非自由态结束时的脚下格子防硬直停在坑上（`-22,000,000`）；对空砍/空挡/空踢给予显著惩罚（`-24k / -30k / -50k`）；奖励把敌方踢进坑的轨迹（1v1 `+4,500,000`）；在 `M_FFA` 对多持镖敌人同时具有视线（`threats_los >= 2`）严格扣分，并在多人存活时提高冲刺冷却代价（`cd * 260`）以保存逃生冲刺。

## 二、强点、弱点与放弃的想法

### 强点
1. **极高的地形与规则安全性**：得益于全阶段 `MapKnowledge`、`dash_uncancelled_safe` 与主动落坑 `-25,000,000` 优先级分级，在标准图及未见过地形图上极少主动掉坑，对 `strong` 1v1 的 80 局测试实现 **0 落坑**。
2. **因果精确的多模型对抗**：`reconstruct_game` 精确补齐 `DELAY=4` 与 `CLASH` 落地，配合双模型最坏情况融合与急停 `mode 3` 决胜，飞镖命中率与近战挡/反打兼顾。
3. **极佳的计算效率与规则泛化性**：单步峰值 CPU 仅 `~1.0–1.9 ms`（零超时/零故障），且全部计算直接读取 `Config` 参数，实测在 `DELAY=0` 与关闭 `RECALL / BLOCK / DASH_SLASH` 的变体规则下也能无故障胜出。
4. **4v4 配合与低误伤**：双层队友位置动态外推拦截 + 无延迟 16-bit 报点协议，对强陪练混编队保持极高胜率。

### 弱点
1. **推演视野短于 `RECALL_PRE = 12`**：由于算力限制，`H = 9/11 < 12`，纯粹靠前向推演看不到“完成召回飞回手中”的收益，因此发起和维持 `A_RECALL` 仍需依赖外层启发式安全阈值（`min_arm_d > 5200` / `4800`）。
2. **`DELAY=4` 下超近身博弈仍有盲区**：若对手在最近 4 步内突然原地启动冲刺或变向，贴脸强踢/格挡的时机判断只能靠预测（这也是面对极激进版本如 `v1` 或混战互踢时仍有一定方差的原因）。
3. **四人混战（FFA）高阶博弈建模有限**：对多方互打中的“坐山观虎斗/劝架站位”主要靠 `threats_los >= 2` 与 `cd * 260` 启发式，尚未构建多方纳什/树搜索；在极窄跨岛图（如自制 `custom_collapse_ring` 四人混战）仍偶有缠斗落坑（24 局中 2 次）。
4. **草丛信念（`HiddenBelief`）无权重分布**：目前隐身追踪只维护二值可达网格重心，尚未对高频掩体边缘加权。

### 尝试过但放弃的想法（附原因）
1. **周期性蛇皮变向（`o.t / 5` 切偏置，v5）**：破坏移动惯性加分并导致临阵犹豫，1v1 对 `strong` 退化至 `31-28-1`，FFA 掉至 `2.23`（平均每局仅 `0.8` 次召回），遂回滚。
2. **把外推速度 `old_mx + old_mvx*4` 塞入 `collect_cone_threats`（v7）**：产生严重的幽灵躲避幻觉（把原本不会被瞄准的位置当成危险线乱跑），对 `strong` 降到 `30-29-1` 且丢失 `check` 热身赛，遂移除。
3. **对 `D_GROUND` 未持镖敌手提前计入威胁与全程 `near_dart_pen`（v6）**：导致手握空地飞镖却过分害怕，不敢在安全距离读条 `A_RECALL`，FFA 均分降至 `2.55`；v8 将其收缩为仅对 `S_DASH / S_KICK`（后加 `S_KICKED / S_SLASHED`）生效，FFA 立即回升至 `3.35`。
4. **持镖威慑区禁止冲刺 `-20000` 惩罚（v11）**：误伤了关键抢位与躲镖冲刺，FFA 跌至 `2.76` 且负于 `v10`（`16-19-5`），验证无效后放弃。
5. **在多人局所有中间延迟步启用全量 `mode 2` 反击（v13）**：`v13` 在 1v1 虽提升到 `30-23-7 vs v12`，但 FFA 同时对多名对手假设“立即偷步反扔”导致走位过度保守（FFA 从 `3.38` 跌到 `2.80`）；因此 `v14` 改为按 `M_DUEL` 与 `M_FFA/TEAM` 分流。
6. **推演内允许 `s >= 1` 自动 `DASH_KICK`（v14 及以前）**：回放 `ffa-.../g21.txt` 抓到典型 Bug——`t=128` 时角色面朝深坑冲刺，只因模拟里假设第 `s=3` 步能刚好踢中敌人刹车停在岸边，实际敌人在 `DELAY=4` 后走开，角色直接冲进坑里（`-1` 自杀）。`v15` 删除推演期未来自动 `DASH_KICK` 并对 `DASH_SLASH` 加入 `dash_uncancelled_safe` 校验后，1v1 对 `strong` 直接跃升到 **70.0%** 且 80 局 0 落坑。

## 四、对规则与引擎细节的核查发现

在对照阅读 `RULES.md`、`dart.hpp` 与回放日志的过程中，并未发现确定性引擎存在结算错误（`dart::Game::step` 完全可复现、逐位一致），但有几处**文字说明容易产生误解、选手实现时极易踩坑的细节**：

1. **`DASH_SLASH=1` 实际同时开放了"冲刺踢"（Dash-Kick）**
   - `dart.hpp` 的 `Config` 注释和 `RULES.md` 中将其简称为"冲刺斩（`DASH_SLASH`）"，直觉上容易以为只有手里有镖时才能在冲刺移动段提前出手近战。
   - 但 `dart.hpp` `start_action`（第 1258 行）写的是：`const bool slash = D.st == D_HAND; P.st = slash ? S_SLASH : S_KICK;`——即空手冲刺移动中给 `A_MELEE` 同样会打断冲刺并立即转入 `S_KICK`（踢人）和恢复落坑判定。我们不仅利用了这一特性补充在线踢人能力，也踩中过“推演靠未来冲刺踢刹车导致掉坑”的隐患。

2. **队友 `msg` 的“零延迟”与视觉延迟并存，且 `Obs` 不自动带 `team`**
   - `dart.hpp::observe()` 中，对手与队友的位置/状态/飞镖均取 `t - DELAY` 步的快照，但第 1184 行明确写了 `Q.msg = (mates(seat, k) || k == seat) ? p[k].msg : 0; // 消息不延迟`（拿到的是上一帧 `t - 1` 队友刚提交的消息）。选手若误以为消息也延迟 4 步，对齐就会错位；另外下发协议 `Obs` 的 15 个字段不包含 `team` 编号，用 `Obs` 自建 `dart::Game` 时若忘了从 `GameInfo::team[k]` 手动赋值，所有玩家 `team` 都会保持 `-1` 导致 4v4 队伤判定失效。

3. **草丛隐身状态下的飞镖情报部分暴露**
   - 当敌人在草丛中隐身（`vis == 0`）时，`dart.hpp::observe()` 第 1185-1192 行仍下发 `d[k].st`，并且只要 `d[k].st != D_HAND`（包含飞行中 `D_OUT/D_BACK/D_CALL`、落地 `D_GROUND` 以及正在蓄力召回 `D_RISE`），飞镖的精确坐标 `(x, y)` 和速度仍然可见（唯有握在手中 `D_HAND` 时坐标归零）。也就是说即便人物隐在草里，一旦其使用远程召回或接镖前，仍会暴露精确的镖位信息。

4. **地图文本格式与回放 `MAP` 编码不同**
   - 赛前工具的 `.txt` 地图使用字符 `.`（地）、`#`（墙）、`~`（坑）、`"`（草），而 `DART-REPLAY 2` 回放文件里的 `MAP` 矩阵使用数字 `0`（地）、`1`（墙）、`2`（坑）、`3`（草），编写回放分析或地形复现脚本时需注意映射一致。此外，`strong` 在复杂多墙多坑图（`custom_*` FFA）下偶尔触发超时故障（24 局内 `strong#3` 故障 5 次），提示线上面对高复杂度大图更应严格保持基于 `thread_cpu_100ns()` 的硬算力截断（我方保持 ≤ `1.854 ms`，全程 0 故障）。

# 飞镖乱斗 · opus 的程序说明

> 计时说明：比赛开始时本目录没有 `clock.json`（`python clock.py` 提示"没有找到计时信息"），我先按提示词的 75 分钟自己掌握时间；
> 后来主办方放入了 `clock.json`（07:55:15 开始，09:10:15 截止），之后以它为准。
> **交卷版是开发中的第 20 版**（`old/v20.cpp` 与 `player.cpp` 相同）：在第 8 版基础上只改了一个常数——
> 位置评估里"离自己地上的镖的距离"权重从 0.12 提高到 0.20（每米 200 分），让程序更积极地走过去捡镖、少站着召回。

## 1. 整体思路

程序是一个"**每步重新规划的推演搜索**"：每一步先把观察补偿到"现在"，生成几十个候选方案，用裁判同款引擎 `dart::Game`
把每个方案推演 16 步，再叠加几种"看不见的威胁"的风险扣分和进攻的命中概率，选分数最高的方案，只执行它的第一步动作。
下一步再从头算。整个程序是单个 `player.cpp`（约 1400 行），只用 `dart.hpp` 和标准库。

### 1.1 延迟补偿（`reconstruct`）
- 观察里别人是 4 步前的样子，自己是现在的。我记下自己每一步的状态和动作（`hp/hd/ha` 环形历史），
  拼出"第 t-4 步开始时的完整局面"（别人用观察，自己用历史），再用引擎推到现在：
  自己用当时真实给出的动作，别人按当时的速度方向继续走、不出手。
- 推完后把自己的状态和自己的镖换回真实的当前值（自己的东西是精确的）。
- 推演里对手被"打死"不当真（现实里他可能躲开了），保持存活。
- 这样已经在飞的镖、互推、撞墙、接镖在"现在"的局面里都和裁判一致，只有对手这 4 步的意图是猜的。

### 1.2 候选方案（`plans`）
- 移动：16 个方向 × 两种持续时间（3 步 / 9 步，之后站住），外加站着不动。
- 冲刺：8 个方向（冷却好、自由状态时），带一点固定代价。
- 扔镖：对每个可见对手，在多个瞄准方向里（情景"继续走/停"在镖到达时的位置、补偿后位置、观察位置，各再加 ±4.6°、±9.2° 偏移）
  选命中概率最高的一个，再配 4 种蓄势中的移动（左右横移、后退、站）。
- 挥砍 / 踢：贴近对手时朝他判定时刻的预测位置出手。
- 冲刺接近战：冲刺方向指向对手预测位置，在第 3/4/5 步接近战。要求"单纯冲刺本身也安全"——因为下一步重新规划时不一定会接近战，
  早期版本曾因此冲进 S 形深沟。
- 冲刺移动中：随时可以接近战（也当"刹车"用，避免冲刺终点落进坑）。
- 挡镖：对 4 米内飞来的镖朝它挥砍（引擎推演判断挡没挡到）。
- 召回：镖在地上时。

### 1.3 每个方案的打分
`分数 = 进攻收益 + 终点位置分 − 推演里死亡（−30000，越晚越轻）− 各种风险扣分`

1. **引擎推演**（`simPlan`）：H=16 步，对手按速度继续走。负责精确规则：自己会不会走进坑、撞上已知的镖、被推、冲刺越坑是否落地、挡镖是否成功、塌陷。
2. **真实飞镖的多情景风险**（`buildRealDarts` + `realRisk`）：观察里在飞的别人的镖、以及观察里正在蓄势（方向已知）的镖，
   用轻量模拟在**主人 10 种走位情景**下各推一遍（回程的镖追主人当前位置，主人走位不同路线就不同），按情景权重算被打中的概率，×20000 扣分。
   专门修好了"跑进对手回程镖路线"的死法（第一版对 strong 的主要死因）。挥砍方案会判断哪把镖落在格挡扇形里、之后不再算它。
   同时算出每个对手"按继续走的情景什么时候接住镖"（`armT`），给后面两项用：对手回程中途冲刺、接镖后接挥砍，是早期常见死法。
3. **假想来镖**（`buildThreats` + `threatRisk`）：对手手里有镖（或很快接住镖），假设他在我看不见的第 t-4..t+3 步任一步出手，
   瞄准"他那时看到的我"（我第 τ-4 步的位置），分不带提前量 / 全提前量 / 半提前量三种，算方案被打中的加权次数，×7000 扣分。
   **权重按对手的实际出手频率自适应**：统计每个对手"自由、有镖、在 7.5 米内"的步数和其中开始扔镖的次数，
   频率高的对手（例如见人就扔的 weak）威胁权重最多放大到 3 倍，最少 0.7 倍。
4. **假想近战**（`buildMelee` + `meleeRisk`）：对手可能在这几步直接挥砍/踢，或冲刺后在第 3/4/5 步接近战，
   按"他看到的我 + 提前量"瞄准，判定时我在不在扇形里。踢的话再模拟我被踢滑 12 步后停在哪：停在坑里就和被砍一样重，否则只扣一点。
   我在判定那一步处于锁定状态（硬直、召回、冲刺）时权重 ×3（对手能精确预判锁定中的我）。
5. **终点位置分**（`evalEnd`）：快塌的格子、坑边（被踢下去的风险）、离最终安全区的距离（越到后期越重）、手里有没有镖（空手 −250）、离自己地上的镖多远（每米 −200）、
   和对手的距离（双方有镖时不进 3.8 米，太远（>6 米）要靠近目标；我空手而他有镖时离 7.5 米以上；他空手我有镖时贴到 3.2 米左右压迫）；
   中间有墙时距离惩罚减轻。
6. **4v4 友伤**：推演里队友被我打死扣 25000；扔镖方向（含队友按速度外推的位置）1.5 米内有队友就不扔。

### 1.4 进攻：命中概率（`buildScen` / `throwProb` / `meleeProb`）
- 对每个对手，从 **4 步前的观察**出发（不是从补偿后的位置），生成 20 条行为情景：继续原速度、停、8 个方向各走；
  每种又分"不反应"和"看到我出手后（第 t+5 步起）横向躲开"两个版本。情景模拟考虑他当前的蓄势/硬直/冲刺/被踢滑行（锁定时动不了），也不会自己走进坑。
- 镖的去程是确定的（速度表 900、850、…，整条线只查一次墙），按相对运动判命中（含最远点停留 3 步），算加权命中率。
- 扔镖收益 = p × 9000 − (1−p) × 2600。挥砍同理；踢的收益主要来自"踢下坑"的概率（模拟滑行终点在不在坑里），
  并检查对方是否处于免踢状态（被踢硬直中、及硬直后一步）——早期版本会去踢正在硬直的人，必然踢空然后被扔中。

### 1.5 其他细节
- 所有数值从 `info().cfg` 读；出生点、地图、塌陷全从 `info()` 读，没有写死座位或地图。
- 安全区：开局 BFS 出"最后塌（或永不塌）的格子"的距离场，后期把人往里拉。
- CPU：1v1 单步最多约 2 ms，四人局约 2.5–2.8 ms，4v4 约 3.7 ms（预算 10 ms）。另有 6.5 ms 的 CPU 保险丝（`thread_cpu_100ns`），超过就停止评估剩下的方案。
- 平手用一个按座位播种的小随机数打破（xorshift），避免完全可预测。

## 2. 强项与弱项

**强项**
- 规则层面精确：所有动作的后果交给裁判同款引擎推演，不会自己冲进坑、冲刺不会落在坑里、挡镖时机由引擎判断。
- 躲镖：已知的镖（含回程镖在主人不同走位下的路线）基本不会再撞上；对看不见的出手按"他看到的我"建模。
- 自适应：针对"出手频繁"的对手提高警惕（对 weak 从 31:9 提升到 55:4）。
- 四人局表现好：对 3 个 strong 平均名次约 1.75、平均得分约 3.3（strong 们 1.9–2.3）。

**弱项**
- 冲刺斩（对手冲刺途中接挥砍）仍是主要死因之一：从对手按冲刺到判定只有 5～7 步，我看到时已来不及，只能靠风险模型提前保持距离。
- 自己处于硬直/召回/冲刺收势时被抓。
- 在更大、墙更多的图（我把两张 4v4 图改成 1v1 自测）上对 strong 只有五五开，召回次数偏多。正式的 1v1/四人图是 18×12 米，影响应小一些。
- 对手的 4 步隐藏期只用"继续原速度"外推来补偿推演局面；对急转弯的对手，补偿后的位置不准（命中率估计里用了多情景弥补）。

**试过但没用上的**（都在 160 局 1v1 + 80 局四人局上和基准比较过）
- `futureRisk/futureMelee`（第 t+4 步以后对手瞄准"方案里的我"出手，只在我锁定时计入）：开发中发现循环有 bug（第一次迭代就 break，实际从未生效）；
  修好后整体启用反而从 100:59 掉到 75:80；单独只开近战部分 95:61、只开飞镖部分 92:67，都不比不开好，所以保留了不生效的行为
  （代码还在，实际不起作用）。我猜原因是它让程序在任何会锁定的动作（扔、召回、冲刺）上都过于保守。
- 召回引导中的镖（RISE）建模为即将起飞的召回飞镖：83:77，比不加差。
- 整个冲刺都算"锁定"、冲刺代价 −350/−700、召回代价 −400：都在噪声范围内或更差。
- 冲刺中刹车代价 −3000（只在必死时刹车）：96:63，更差（刹车踢有时能救命/踢人下坑）。
- 风险权重 RISKW 4500 / 10000（现用 7000）、击杀价值 KILLV 7000 / 12000（现用 9000）、LOCKF 2 / 5（现用 3）：都不更好。
- 与对手保持距离的阈值整体放大或缩小：都更差。
- 踢的最低命中率 0.35 + 召回惯性（v9）：1v1 104:55 略好（噪声内），但四人局得分从 3.26 掉到 2.99；拆开测是"踢的门槛"伤害四人局
  （多人局里踢人下坑、打断别人很有价值），所以没采用。
- 草丛隐身奖励（终点在草丛且未暴露加 200/500 分）：1v1 和四人局都更差。
- 对手近战频率自适应（仿照出手频率）：1v1 持平，四人局 2.99，更差。

需要说明：这些参数是在同一组种子上挑出来的，有一定选择偏差；全新种子 900+ 上的 64% 胜率是更可信的估计。

正式计时检查 `python match.py check player.cpp`（交卷版 v20）：通过，单步最多 1.5–3 ms（随机器负载），第 0 步最多约 21–56 ms。

## 4. 规则疑问 / 可能的问题

- 没有发现引擎和规则文本不一致的地方。读代码确认了几处细节：
  - 冲刺移动最后一步 `dashing = 0`，照常判落坑；冲刺接近战后恢复落坑判定（所以"冲刺斩"方案里要求单纯冲刺也安全）。
  - 被踢免疫按"这一步开始时"的状态判断（`kick_protected`），硬直结束后那一步 free 且 timer=1 时也免踢。
  - 召回引导中给 ACT=4 不会重新计时，给任何移动立刻中断。
  - 出镖那一步镖不动、不判命中，也不参与镖撞镖；回程镖朝主人"这一步移动后"的位置飞。
- `Game(info(), obs)` 里看不见的对手是 `unknown`，推演中不移动也不会被打中；我只在假想威胁里用他最后出现的位置。
- 比赛开始时没有 `clock.json`，`clock.py` 无法显示时间（见开头）。
- 过失说明：开发中途我曾把几个对局结果的临时文本（以及一个调试用 .cpp）写到 Git Bash 的 `/tmp`（工作目录之外），
  发现后已删除我写的那些文件（没有动别的文件），之后只写本目录下的 `tmp/`。

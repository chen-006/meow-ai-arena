## 思路（为什么强）
底子是 `原型\bots\pro_core.hpp`，也就是主办方做游戏时写的强参考程序（README 计时表里那个），拼成单文件后针对今晚的新规则改过：
1. **补偿反应延迟**：记住自己每一步的状态和动作，把"4 步以前的世界"拼完整，用引擎自带的 `dart::Game` 从那里推演，对手按多种假设走（保持速度、往 4 个方向、在我还看不到的 4 步里已经出手、拿回镖后立刻扔）。
2. **每步给十几个候选走法 / 冲刺打分**：先看推演里会不会死，再看"对手完美预判朝我扔、我看到后再躲"有几种躲不开，然后才看位置。扔镖、挥砍、冲刺接近战都先推演"对手看到后往 9 个方向躲"的命中率（覆盖率）才出手，出手不能比最安全的走法明显更危险。
3. **针对新规则加的**：
   - 格挡：用推演把别人的镖推到"我现在挥砍、下一步判定"那一刻（包括观察里还在蓄势、其实已经出手的镖），挡得住又安全就挡；躲闪推演里把"原地等着格挡"也算一种躲法。
   - 认出会格挡的对手：看到某个对手在别人的镖身边挥砍过，之后对他扔镖时把"他站着挡得住"的那部分覆盖率打 6 折（对不挡的对手照常扔，不吃亏）。
   - 冲刺前摇：冲刺接近战、冲刺落点检查都按 `DASH_PRE + DASH_T + DASH_POST` 算；冲刺好不好由推演判断（新冲刺锁 8 步，推演自然会少用）。
4. **修掉参考程序原有的几个漏洞**（都是看对局回放找到的）：对手镖正飞回去或落在他身边时，原来当他"没镖"，会站着召回 / 空手冲上去踢而被近身扔死；现在 6.5 米内有"马上有镖"的对手就不开始召回，空手不去踢有镖、没在硬直的对手。
5. **计算量固定**：每步最多推演多少个 `Game::step` 是固定数（1v1 7000，四人局 60%，4v4 25%），不看时钟，所以结果确定（同一局复跑两次，回放逐行相同，已验证）。

## 已知弱点
- 对 s1 这类"冲刺贴脸 2～3 米扔镖、冲刺接近战"的打法只赢约 58%：输的局一半是 2～3 米内被扔中，另有被砍、被踢下坑。试过把"对手冲上来砍/踢"加进躲闪推演（`mel_w`），在误差内看不出好处，又费算力，默认关掉了。
- 推演里对手只有几种固定走法（保持、四个方向、完美预判扔镖），不会想到"假动作""绕到墙后"；草丛里看不见的人放在最后看到的位置。
- 四人局推演量只有 1v1 的六成、4v4 只有四分之一（受每步时间限制），多人混战里比 1v1 弱一些；4v4 只做了参考程序原有的避让队友，误伤仍有（4 人合计每局约 0.5～0.8 次）。
- 挡镖靠"看到对手在镖旁边挥砍过"来认人，一局开头对会挡的对手仍会照常远扔。

## match.py 的改法（`match_py.diff`，或直接用 `交付\match.py` 替换）
三处：
1. 文件开头的说明：
```
  weak            bots\\weak.exe（弱档陪练，只有可执行文件）
  mid             bots\\mid.exe（中档陪练，只有可执行文件）
  strong          bots\\strong.exe（强档陪练，只有可执行文件）
```
2. `BUILTIN`：
```python
BUILTIN = {'template': KIT / 'template.cpp', 'weak': KIT / 'bots' / 'weak.exe', 'mid': KIT / 'bots' / 'mid.exe',
           'strong': KIT / 'bots' / 'strong.exe'}  # 三档陪练只发可执行文件
```
3. `resolve_prog` 里内置名字那一段：
```python
    if low in BUILTIN:
        src = BUILTIN[low]
        if src.suffix.lower() == '.exe':
            if not src.is_file():
                raise build.BuildError(f'找不到陪练 {low}：{src}')
            res = (low, src.resolve())
        elif src.is_file():
            res = (low, build.compile_cpp(src))
        else:
            raise build.BuildError(f'找不到参考程序 {low}：{src}')
```
以及找不到程序时的提示加上 `strong`。`check`（对 weak）、`--fill`、`--fill-a/--fill-b`、`--vs` 都经过 `resolve_prog`，不用另改。

**已验证**：实验目录 `bots\` 里只放 `weak.exe`、`mid.exe`、`strong.exe`（没有 .cpp），跑通了 `check strong/mid/weak/template`、`duel strong weak`、`duel mid weak`、`ffa strong --fill mid`、`ffa strong mid weak template`、`team strong --vs mid --fill-b weak`、`team mid --vs weak`、`play strong mid --map yinyang --seed 7`。

合进选手包时：把三个 exe 放进 `选手包\bots\`，删掉 `bots\weak.cpp`、`mid.cpp`；`选手包\build\` 里缓存的 `weak-*.exe`、`mid-*.exe` 是从源码编出来的，也应一并删掉。**注意**：exe 是对着现在的 `dart.hpp` 编的，引擎或规则参数默认值再改，三个 exe 都要重编（strong 用 `交付\strong.cpp`，weak/mid 用现在的源码，命令 `python build.py 源文件 -o bots\名字.exe`）。

# Renderer

Renders a match replay (`DART-REPLAY 2`, format in [../workspace/回放格式.md](../workspace/回放格式.md)) into a 1080p, 30 fps mp4: ten themed floating-island arenas above a sea of clouds, voxel characters, three-bladed boomerangs, hit and collapse effects, a top info bar. All match footage in the video came from it.

## 1. Requirements

| Item | Version | Notes |
|---|---|---|
| Blender | 5.2.4 LTS (tested) | EEVEE, background mode `-b`, no add-ons. Put it on PATH or point `DART_BLENDER` at `blender.exe`. The render scripts run in Blender's own Python and only need its bundled numpy |
| Python | 3.10+, with `numpy`, `scipy`, `scikit-image`, `pillow` | Runs the controller, map preprocessing (terrain mesh, ground textures) and HUD. `render_game.py` uses the current interpreter; `出片.cmd` uses `python` on PATH or `DART_PYTHON` |
| ffmpeg | recent (7.x tested) | Encodes the mp4; must be on PATH |
| CJK font | default `C:\Windows\Fonts\NotoSansSC-VF.ttf` (variable Noto Sans SC) | HUD text; override with `DART_FONT` |

Tested on Windows 11 with an RTX 4060 laptop GPU. Intermediate files (terrain cache, frames, logs) go to `renderer/work/` (not committed); change with `DART_WORK`, `DART_CACHE`.

## 2. Render a game (one command)

```text
python renderer/render_game.py replays/g428.txt -o g428.mp4
```

Run from `boomerang/`. `render_game.py` picks the voxel character and HUD name for each seat from the player names in the replay, then calls `src/make_video.py`, passing on the other options: `-o out.mp4`, `--procs 3` (parallel Blender processes), `--samples 12` (EEVEE samples; the video's highlight reel used 6), `--frames a:b` (render a range for a preview), `--roster a,b,…` (characters by seat), `--theme name`, `--no-hud`, `--chars smooth` (early round-headed characters), `--keep` (keep frames). Re-running the same command resumes; finished frames are skipped. Measured: about 2.5 s/frame with one process at 6 samples (including scene setup and shader compilation); the highlight reel ran at about 0.29 s/frame with 3 processes at 1080p, roughly 3 minutes for a 20-second duel.

Character names for `--roster`: `astra sol fable opus gemini gemini_s grok glm deepseek kimi qwen mimo doubao`. In episode 11 Gemini 4 Carbon uses `gemini` and Gemini 4 Hydrogen the smaller `gemini_s`; their HUD names come from `DART_LABELS="gemini=Carbon,gemini_s=Hydrogen"` (set automatically by `render_game.py`).

## 3. Stills and exports

`出静帧.cmd [ffa team team2 closeup win collapse lineup themes maps one:<map>]` (or `python renderer/src/stills.py …`) renders key art, the character line-up and theme panoramas into `renderer/work/stills/`. `compare` and `compare_chars` need old stills and two external reference images that are not in the repo.

Export the voxel characters as reusable assets (this is how [characters/boomerang/](../../characters/boomerang/README.md) was made):

```text
blender -b --factory-startup -P renderer/src/export_voxchars.py -- <out dir> [astra,sol,...]
```

## 4. How it works

Replays have 20 steps per second and store only positions, headings and states. `pose.py` turns every character and boomerang into a pure function of (possibly fractional) game time; `timeline.py` maps each video frame to a game time (normally 2/3 step per frame, hit-stops, final-blow slow motion) and a camera. Because every frame can be computed independently, rendering splits into parallel segments and can resume anywhere. See the Chinese README for a per-file table and the ten map themes.

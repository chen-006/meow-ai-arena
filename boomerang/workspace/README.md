# 飞镖乱斗 · 选手包

## 1. 这是什么比赛

你写一个 C++ 程序，操控俯视角小场地里的一个角色。每人一把回旋镖：扔出去会飞回来，打中谁谁出局；也可以近身挥砍、空手踢人、冲刺越过坑。被打中或掉进坑里就出局，最后活下来的赢。场地过了 12 秒开始一圈圈塌陷，大家会被挤到一起。所有角色完全一样，赢在谁预判得准、躲得好、抓得住机会。

最要紧的一条：**你的程序看到的别人，是 0.2 秒（4 步）以前的样子**，自己是现在的。看到对手出手时，他的镖往往已经飞出来了，要靠预判。

海选有两项，各拟合一个实力值，两个实力值的平均就是个人实力值，个人榜按它排：

| 形式 | 人数 | 地图 | 怎么算分 |
|---|---|---|---|
| 1v1 | 2 | 18×12 米 | 胜 1 分、平 0.5 分 |
| 四人各自为战 | 4 | 18×12 米 | 第 1～4 名得 3、2、1、0 分，每击杀一人再加 1 分 |

实力值用 Bradley-Terry 模型拟合（和往期同一套算法，刻度同 Elo：差 400 分约等于 10 比 1 的胜负比）：1v1 用每一小局的胜负；四人局把每一小局里四个人的得分两两比较（高的算赢，一小局 6 组）。细则见 `RULES.md` 第 11 节。

每局最长 40 秒，正式比赛一共打几万局，座位轮换、两边各坐一次。正式地图里有一部分不在包里，但不会出现新的地图元素。4v4（8 人、24×15 米的图）是海选之后团队赛用的形式，海选不计分。规则全文在 `RULES.md`，请先读完。

## 2. 你要交什么

交卷文件是本目录的 **`player.cpp`**：单个 C++17 文件，`#include "dart.hpp"`，只用标准库。截止时刻它是什么内容就交什么；那一刻编译不过或者不存在，就用 `template.cpp` 上场。

最简单的程序长这样（`template.cpp` 是一个能跑的完整版本，从它改起）：

```cpp
#include "dart.hpp"
using namespace dart;
struct Bot {
    void init(const GameInfo& gi) {}          // 可选：开局调用一次
    Action decide(const Obs& o) {             // 每步（0.05 秒）调用一次，返回这一步的动作
        Action a;                             // 默认全 0：站着不动
        a.mx = 1000; a.my = 0;                // 往右跑
        return a;
    }
};
DART_MAIN(Bot)
```

- 观察：`o.me()` 是你自己（现在的），`o.p[k]` 是第 k 个座位的人、`o.d[k]` 是他的镖（别人的都是 4 步以前的），`o.t` 是第几步。`info()` 是本局固定的信息：参数 `info().cfg`、地图 `info().M()`、你的座位、队伍、出生点。
- 动作：`mx my` 移动方向；`act` 是 0 无、`A_THROW` 扔、`A_MELEE` 近战（有镖挥砍、没镖踢）、`A_DASH` 冲刺、`A_RECALL` 召回；`ax ay` 是动作方向；`msg` 是给队友的消息。
- 数值都从 `info().cfg` 读，不要写死。正式比赛全部用默认参数：召回、镖撞镖、冲刺中接近战、挥砍挡镖都开着；冲刺按下后先原地前摇 2 步、移动 4 步、再收势 2 步（`DASH_PRE`、`DASH_T`、`DASH_POST`，见 `RULES.md` 5.5）；被踢的人滑行途中不判落坑，只看被踢硬直最后一步停在哪里（`RULES.md` 5.4）。
- 调试信息写到标准错误（`std::cerr`）；标准输出只能写协议那一行，`dart.hpp` 会替你写。

## 3. 怎么编译和本地对战

需要 Python 3（`python` 命令）和 g++。命令都在本目录执行。改了程序直接重跑命令就行，`match.py` 会按内容自动重新编译。

```
# 1. 从模板开始，确认能编译（生成 player.exe）
copy template.cpp player.cpp        （bash 里用 cp）
python build.py player.cpp

# 2. 正式计时检查：1v1 两局（两边各坐一次）、四人局一局、4v4 一局，对手都是 weak。
#    报告胜负、超时、非法输出、崩溃，以及每步最多用了多少毫秒。交卷前务必跑一次。
python match.py check player.cpp

# 3. 1v1：和中档陪练 mid 打 40 局（公开的 1v1 图轮流用，每个种子两边各坐一次）
python match.py duel player.cpp mid --games 40

# 4. 四人局：你 + 3 个 mid，40 局（同一张图同一个种子打 4 局，座位轮转）
python match.py ffa player.cpp --fill mid --games 40

# 5. 和自己的旧版本比（旧版本另存一份就行）
python match.py duel player.cpp old\v3.cpp --games 80
python match.py ffa player.cpp old\v3.cpp mid mid --games 40

# 6. 打一局并存回放（程序按座位顺序写，第一个坐 0 号）
python match.py play player.cpp mid --map twinlakes --seed 7
python match.py play player.cpp mid mid mid --map yinyang --seed 7
```

- 程序可以写 `template`、`weak`（弱档陪练）、`mid`（中档陪练）、`strong`（强档陪练）、任何 `.cpp` 或 `.exe` 路径。三档陪练只给编译好的程序（`bots\weak.exe`、`bots\mid.exe`、`bots\strong.exe`），不给源码。它们是用来量进步的尺子：打赢强档也不代表够强，正式对手是其他选手认真写出来的程序，本地成绩只用来比较自己的版本。
- 结果有噪声：比较两个版本，同一组对手**至少 40 局**再下结论，几局的输赢说明不了什么。
- 地图：`--map 名字`（`maps\` 里的文件名，不带 .txt）或 `--map 路径.txt`，可以写多次；不写就把 `maps\` 里所有支持这种形式的图轮流用。也可以照 `RULES.md` 第 4.1 节自己画图测试，地图有错时裁判会说第几行哪里不对。
- 种子（`--seed`、`--seed-base`）只决定出生点最多 1 米的小抖动，对局本身没有随机。
- `duel`、`team` 的统计按程序列，每行的胜负是那个程序自己的；`match.py` 输出里的"故障"指超时、非法输出、崩溃。
- 4v4 也能本地打：`python match.py team player.cpp --vs mid --games 20`。
- `--cfg K=V` 可以临时改规则参数做实验（例如 `--cfg CLASH=0`），正式比赛不用。
- 本地对战和正式比赛的运行限制相同：内存上限 1 GB、不能开子进程（裁判强制），程序不得联网、不得读写文件（见 `RULES.md` 第 10 节）。

## 4. 怎么看回放

`check` 和 `play` 默认把回放存进 `replays\`，`duel`、`ffa`、`team` 加 `--replays` 才存。程序的标准错误也存在 `replays\` 下（每批对局一个 `stderr` 文件夹，文件名 `g<局号>_p<座位号>.txt`；加 `--no-stderr` 不存），每条命令的最后一行会告诉你具体在哪。

- 回放是 UTF-8 文本，每一步所有人和镖的状态、实际动作和事件（出手、命中、出局、撞镖、塌陷）都在里面，格式见 `回放格式.md`。想知道一局怎么输的，最直接的办法是写个小脚本读回放，找出你出局前几步双方的位置和动作；或者在程序里把自己的判断写进 `std::cerr`，对照标准错误的记录看。
- `viewer.html` 是给人看的网页查看器：浏览器打开，把回放文件拖进去（空格播放，← → 单步，勾"调试信息"显示更多数值）。`示例回放.txt` 是一局四人局（mid、weak、mid、weak）。

## 5. 时间和规矩

- **看时间**：`python clock.py` 显示开始、截止时刻和剩余分钟数。开始和截止时刻是主办方开赛时写进本目录 `clock.json` 的，不要改它（改了只会改变你看到的数字，收卷照常按时进行）。
- **每步用时**：每步 CPU 10 毫秒，第 0 步（含程序启动和 `init`）1000 毫秒；超时那一步按"不动"处理，累计 20 次程序被结束（详见 `RULES.md` 第 10 节）。看 `check` 输出里的"最多"一列，尤其是 4v4 那一局，留足余量。
- 不可以修改 `dart.hpp`、`arena.exe`、`build.py`、`maps\`、`RULES.md`、`clock.json`。正式比赛用主办方自己的副本编译和评测，你改了只会让本地结果和正式结果对不上。

## 6. 写程序时值得先知道的

### 反应延迟下怎么推演

`dart::Game` 是裁判用的同一份规则代码，可以从当前观察建一份对局往后推：`Game g(info(), o);`，然后 `g.step(acts)` 走一步（`acts` 是每人一个 `Action` 的数组），结果和裁判逐位一致。

但观察里别人是 4 步以前的样子，直接推演等于把别人的旧位置当成现在，会慢半拍。最简单的补偿是把别人按他当时的速度往前推 4 步：

```cpp
Game g(info(), o);
const i64 N = info().cfg.delay;
for (int k = 0; k < o.n; ++k) {
    if (k == o.seat || !g.p[k].alive || g.p[k].unknown) continue;
    g.p[k].x += g.p[k].vx * N;      // 假设他这 N 步一直按原来的速度走（不管墙和坑）
    g.p[k].y += g.p[k].vy * N;
    g.p[k].px = g.p[k].x; g.p[k].py = g.p[k].y;
}
// 之后照常 g.step(...)；别人的镖同样是旧的，要不要往前推、怎么推，自己决定
```

这只是最粗的办法：他这几步可能已经转向、冲刺、出手了，你看不到；被踢后的减速、冲刺末步降速、人和人互推也会让它偏离。另一个办法是记下自己每一步的状态和动作，拼出"4 步以前的完整局面"（别人用观察里的，自己用你当时的），从那里推到现在。怎样猜得更准、怎样防备"他在我看不到的这几步里已经出手了"，正是要比的东西。

看不见的对手（在草丛里）在推演里是 `unknown`，不移动、不出手、不会被打中；想防他，得自己估计他在哪、把他放回去。

### 工具函数（`dart.hpp` 末尾）

- `live_map(cfg, map, t)`：第 t 步的地图（塌掉的是坑）；`cell_fall_step`：某格哪一步塌。
- `cell_at_step`、`cell_of_point`、`standable`：只看圆心所在的地形，不保证身体不压墙。
- `wall_between`：两点之间有没有墙。
- `grid_dist`、`path_next`：格子上走路的最短路；不会冲刺越坑，不考虑身体半径；起点终点在同一格时直接返回成功、不检查地形。
- `dart_step_len`：镖这一步的速度上限；去程实际位移还要和剩余距离 `left` 取小。
- `is_mate`、`ilen`、`scale_to`、`iatan2` 等整数工具；`thread_cpu_100ns()`（见下）。
- 地图格子边长 0.5 米，用 `dart::CELL`、`cell_index`、`cell_center` 换算，不要写死；1000 仍然是每米的毫米数和方向单位。地图宽高的格数是 `info().M().nx`、`ny`，毫米是 `width()`、`height()`。出生点读 `info().spx[k]`、`spy[k]`，不要假定从四角出生或几个座位等价。

### 用时与按 CPU 收手

4v4 场上 8 个人，推演一步的计算量比 1v1 大好几倍。用推演的程序最好按实际用时自己收手。按墙上时钟（`steady_clock`）收手会把被系统调度出去的时间也算进来，机器忙时不可靠；可以用 `dart::thread_cpu_100ns()` 量本线程的 CPU 时间（Windows 上用 GetThreadTimes，失败时返回 -1）：

```cpp
// decide 开头记下：
const auto cpu_start = dart::thread_cpu_100ns();
// 每算完一批候选检查一次：
const auto cpu_now = dart::thread_cpu_100ns();
if (cpu_start < 0 || cpu_now < 0 || cpu_now - cpu_start >= 50000) {
    // 停止搜索，输出当前最好的动作；50000 个 100 纳秒约 5 毫秒
}
```

它只量本线程，裁判计的是整个进程（含启动、读写协议、步与步之间的计算），所以要留余量。交卷源码里不要直接包含 `windows.h`，源码检查会拒绝；用 `dart.hpp` 里的这个函数就够了。

机器同时跑很多局、或者有别的程序在忙时，测得的用时会偏大，同样的程序也可能做出不同的选择。比较用时请看 `check`（它固定只并行 2 局），或给 `duel` 等加 `--workers 1`。供参考，主办方在比赛用的机器上（无沙箱、有其他任务在跑）测过陪练每步的平均 / 最多毫秒数：

| 程序 / 同时跑几局 | 1v1 | 四人局 | 4v4 |
|---|---|---|---|
| mid / 1 | 0.06 / 0.94 | 0.03 / 0.90 | 0.05 / 0.93 |
| strong / 8 | 1.59 / 5.10 | 1.52 / 6.20 | 1.13 / 5.82 |

这是历史参考值，不是上限，你的程序要自己用 `check` 验收。

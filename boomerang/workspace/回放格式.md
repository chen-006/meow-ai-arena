# 回放格式（`DART-REPLAY 2`，规则第三版）

裁判 `arena.exe` 和实验台写的回放都是这个格式：UTF-8 文本，一行一条，字段用空格分隔，`|` 分隔每个角色 / 每把镖的字段组。
写给查看器 `viewer.html`、之后的 3D 渲染器、复盘脚本用。**只靠本文档就能还原任一步所有角色和镖的状态**，不需要读引擎代码。
**细格子回放仍用DART-REPLAY 2，MAP行扩展为 `MAP W H CELL毫米`，例如 `MAP 36 24 500`。读取旧回放时若没有第三个尺寸值，缺省CELL=1000；旧正方形MAP N仍为N×N个1000毫米格。人物/镖坐标、速度、事件坐标均仍是毫米，不随CELL缩放。引擎只模拟500毫米格；旧回放直接观看可由查看器兼容，需要重算旧地图时先每格拆2×2转换。**

规则含义见 `规则\RULES.md`；字段的权威定义是 `引擎\dart.hpp`（`replay_header` / `replay_state` / `replay_actions` / `replay_event` / `replay_end`）。

## 1. 单位与坐标

- 长度：1000 = 1 米。地图是 宽W×高H个边长CELL毫米的格子，格子 (x, y) 覆盖 `[x*CELL,(x+1)*CELL] × [y*CELL,(y+1)*CELL]`（点正好压在格线上时同时碰到两边的格子，规则见 RULES 第 3 节）。
- 坐标：x 向右、y 向下（和地图文字的列、行方向一致）。地图左上角是 (0, 0)。**3D 渲染时**把 y 当作地面上的另一个水平轴即可（例如世界坐标 X = x/1000，Z = y/1000，高度 Y 另算）。
- 时间：每秒 20 步，第 t 步 = t/20 秒。
- 角度（只有朝向 `face`）：0..35999，单位 0.01 度；0 = +x 方向，9000 = +y 方向（屏幕上往下）。
- 速度单位为毫米/步；人物字段是内部速度，镖的字段含义另见3.2。
- 角色是半径 `BODY_R` 的圆，镖是半径 `DART_R` 的圆（都在 CFG 行里）。场地外四周是虚空（掉下去 = 出局）。

## 2. 文件头

```text
DART-REPLAY 2
ENGINE dartfu-v3
CFG MODE=0 STEPS=800 DELAY=4 BODY_R=400 ...       全部规则参数 KEY=VALUE（顺序固定，含所有时长、半径、开关）
SEED 3                                             种子（只决定出生点的小抖动）
MODE 0 duel                                        形式：0 duel（1v1） 1 ffa（四人各自为战） 2 team（4v4）
MAPNAME floating                                   地图名
MAP 36 24 500                                          地图的宽 W（列数）和高 H（行数）；第三个数为格子毫米数；缺省1000，只有一个数则宽=高
~~~~                                               （示意）H 行，每行 W 个数字，第 1 行是 y=0；第 j 个字符是 x=j
00003310000020                                     0 地面  1 墙  2 坑  3 草丛（开局时；塌陷另算，见 WAVE）
...
WAVE                                               塌陷图：H 行，每行 W 个字符：0-9 a-z = 这一格在第几波塌（0 起），. = 永不塌
..0000....1111..                                   （坑格上写 .）
...
WAVES 5 240 270 300 330 360                        波数 R，然后第 0..R-1 波各自在第几步塌掉（示意）
PLAYERS 2
PLAYER 0 0 mid                                     座位号 队伍号 名字（名字里没有空白）
PLAYER 1 1 mid
LIMITS 10.000 1000.000                             每步 / 第 0 步的 CPU 预算（毫秒；实验台写的是名义值）
```

- `vis` 掩码（角色第 16 项）已经把草丛、视距 SEE_R、暴露时间、队友全都算进去了，直接用。
- **波**：每张地图自己设计塌陷顺序（WAVE 图）。第 w 波的格子在 WAVES 给的那一步**开始时**变成坑（那一步结算时站在上面的人落坑出局）；格子上原来的墙、草也一起消失。WAVE 图里是 `.` 的格子永远不塌。
- 预警：第 w 波在塌之前 `COL_WARN` 步开始预警（CFG 里有），只是显示用，规则上没有作用。
- 墙的高度、坑的深度规则里没有，渲染器自己定（墙挡人和镖，人不能跳过墙）。

## 3. 每一步

每一步依次写：`S` 行（这一步**开始时**的完整状态）、`A` 行（这一步各人实际执行的动作）、这一步发生的 `E` 事件行、`F` 故障行（只有裁判写，可能没有）。最后再写一个终局 `S` 行和 `END`。

```text
S t | 角色 0 的 18 项 | 角色 1 的 18 项 | ... | 镖 0 的 7 项 | 镖 1 的 7 项 | ... | 已塌波数 预警波
A t | MX MY ACT AX AY MSG | ...
E t 类型 a b c d
F t 座位 种类 说明
```

### 3.1 角色（每人 18 项，按座位号）

| # | 字段 | 含义 |
|---|---|---|
| 1 | alive | 1 = 在场，0 = 已出局 |
| 2 | x | 位置（圆心）|
| 3 | y | |
| 4 | vx | 结算后的内部速度（毫米/步），不是位置差；被踢已衰减，冲刺末步已降速，互推不计入 |
| 5 | vy | |
| 6 | face | 朝向角 0..35999。跑动时 = 跑的方向；出手时 = 出手方向；站着不动时保持 |
| 7 | st | 状态（下表）|
| 8 | timer | 当前状态还剩几步（含这一步）。dead 为0；free为1表示下一步整步免踢且可正常行动，其他free为0 |
| 9 | ax | 当前动作的方向（单位向量 × 1000）：扔 / 砍 / 踢 / 冲刺的方向。free 时 0 |
| 10 | ay | |
| 11 | cd | 冲刺冷却还剩几步（0 = 能冲）|
| 12 | expose | 还要强制暴露几步（出手后会暴露；见草丛）|
| 13 | kills | 到目前为止的击杀数（含误伤队友）|
| 14 | msg | 上一步给队友广播的消息（整数）|
| 15 | vis | 这一刻（真实画面，不是延迟后的）看得见他的座位的位掩码：第 k 位 = 1 表示 k 号看得见他。草丛里藏住的人，对手的位是 0；可以用来把"藏在草里"画成半透明 |
| 16 | dead_t | 在第几步出局（-1 = 还在场）|
| 17 | cause | 出局方式：0 无 1 被飞镖打中 2 被挥砍 3 落坑（含被踢下去、塌陷、自己走下去）|
| 18 | killer | 凶手座位号；-1 = 没有（自己落坑、塌陷）。被踢下坑算踢的人 |

回放里的一切都是**真实状态**。程序收到的观察里别人是 DELAY 步以前的样子（反应延迟），那只影响程序怎么决策，不进回放。

状态 `st`：

| 值 | 名字 | 画面上是什么 | 时长（CFG） |
|---|---|---|---|
| 0 | free | 站立 / 跑（看速度）| — |
| 1 | throw | 扔镖蓄势（举镖），方向 ax ay | THROW_PRE |
| 2 | thrown | 出镖后的收势 | THROW_POST |
| 3 | slash | 挥砍起手 | SLASH_PRE |
| 4 | slashed | 挥砍收势（砍中或挥空）| SLASH_POST（挥空时 SLASH_MISS，若 ≥ 0）|
| 5 | kick | 踢起手（空手时的近战）| KICK_PRE |
| 6 | kicked | 踢完收势 | KICK_POST |
| 7 | dash | 冲刺：先 DASH_PRE 步前摇（原地，不能控制移动），再 DASH_T 步高速直线移动（方向 ax ay），最后 DASH_POST 步收势（不能控制移动）。timer 说的是下一步：timer > DASH_T + DASH_POST 前摇，DASH_POST < timer ≤ DASH_T + DASH_POST 冲刺移动，timer ≤ DASH_POST 收势（刚结算完的那一步属于 timer + 1 所在的段）| DASH_PRE + DASH_T + DASH_POST |
| 8 | stun | 被踢中、向后滑行的硬直（滑行途中不判落坑，只在最后一步判，见 RULES 5.4）| KICK_STUN |
| 9 | recall | 原地站定召回镖 | RECALL_PRE |
| 10 | dead | 出局（位置 = 出局时的位置；落坑的人在坑里）| — |

阶段进度：`已过步数 = 总时长 − timer`，总时长取上表 CFG 里对应的值，用来做动画插值。冲刺移动除最后一步外不判落坑（前摇、收势照常判），可以越过窄缺口，画成"贴地冲过去"。被踢硬直（st = 8）同理：滑行途中经过坑、场外不判，只在硬直最后一步（S 行里 timer = 1 的下一步）判，所以回放里会看到被踢的人从坑上滑过去、停在地上；冲刺中被踢，当步人在坑上方也不会掉。被踢后停在坑上出局时，FALL 事件和 DEATH 都记给踢的人。
**挥砍 / 踢的判定**发生在起手的最后一步（timer = 1 的那一步）结算时；对应的 `SWING` 事件同一步写出。

### 3.2 镖（每把 7 项，按主人座位号；每人恰好一把）

| # | 字段 | 含义 |
|---|---|---|
| 1 | st | 0 hand（在主人手里）1 out（去程）2 back（回程，追着主人飞）3 ground（落在地上）4 rise（主人正在召回，镖还在地上，可画成发光 / 抖动）5 gone（主人出局后消失）6 call（召回飞行，追着主人飞）|
| 2 | x | 位置（在手里时 = 主人位置）|
| 3 | y | |
| 4 | vx | 去程：飞行方向（单位向量 × 1000，整个去程不变）；回程 / 召回飞行：上一步的位移；其他 0 |
| 5 | vy | |
| 6 | left | 去程：还要飞多远才折返（毫米）；rise：召回还剩几步；其他 0 |
| 7 | age | 这一程（去程 / 回程 / 召回飞行）已经过了几步；其他 0 |

镖的速度不是匀速的（CFG：DART_V、DART_DEC、DART_VMIN、DART_HANG、RET_V0、RET_ACC、RET_V、RECALL_V）：去程每步比上一步慢 DART_DEC（最低 DART_VMIN），到最远点后停 DART_HANG 步（回程状态、位移 0），然后回程从 RET_V0 起每步快 RET_ACC（最高 RET_V）；召回飞行同样从 RET_V0 加速到 RECALL_V。画面直接用相邻两步的位置插值即可。
镖的朝向：飞行中用这一步的运动方向（去程 = vx vy；回程用相邻两步的位置差）；停在最远点、刚折返时位移为 0，用上一步的反方向。镖本身在飞行中旋转只是画面效果，规则里没有。
落在坑上（含塌陷区）的镖不会消失，可以被召回。
接住的那一步：`S t+1` 里镖已经是 hand、位置 = 主人位置；它这一步实际飞到哪里没有记录（要画"飞进手里"的动画，就从 `S t` 的位置插值到主人位置）。

### 3.3 塌陷（最后 2 项）

`已塌波数`：第 0..已塌波数-1 波已经是坑。`预警波`：正在预警的波号，-1 = 没有。两项都能从 WAVES 和 t 算出来，只是方便。

### 3.4 动作行 A

每人 6 个整数（裁判收下的动作；超时 / 非法 / 程序已结束都写 `0 0 0 0 0 0`。已出局的人的程序照常收到局面，它回的动作照写，但不起任何作用）：
`MX MY` 移动方向，`ACT` 0 无 1 扔 2 近战 3 冲刺 4 召回，`AX AY` 动作方向，`MSG` 消息。
注意"写了动作"不等于"动作生效"：例如硬直中给的 ACT 会被忽略。生效与否看下一个 S 行的状态或 E 行。

### 3.5 事件行 E

`E t 类型 a b c d`（不用的字段为 0）。t = 发生在第几步的结算里（状态变化体现在 `S t+1`）。

| 类型 | a | b | c | d | 含义 |
|---|---|---|---|---|---|
| THROW | 座位 | ax | ay | | 开始扔镖蓄势 |
| RELEASE | 座位 | x | y | | 镖出手（这一步镖在主人位置，下一步开始飞）|
| TURN | 主人 | x | y | | 去程到最远处，折返 |
| CATCH | 主人 | 这一趟打中几人 | 回程累计转角 | | 接住自己的镖 |
| DROP | 主人 | x | y | | 镖撞墙落地 |
| CLASH | 主人 | 撞上的那把镖的主人 | x | y | 镖撞镖（CLASH=1）：两把在飞的镖相撞，这把镖落在 (x, y)，下一步起是 ground（主人正好在 0.6 米内的话同一步就捡起来了：同一步还有一条 PICK，S t+1 里是 hand）。每把撞落的镖写一条：两把相撞就是两条（a、b 互换），两个落点挨得很近（两把镖最接近的那一刻各自的位置）；一把镖同一步和几把相撞时只写一条，b = 最早撞上的那把的主人（三把连环相撞会是三条）|
| PICK | 主人 | | | | 走过去捡起镖 |
| RECALL | 主人 | 镖 x | 镖 y | | 开始召回（主人站定）|
| CANCEL | 主人 | | | | 召回被打断（移动、出手或被踢），镖留在地上 |
| CALL | 主人 | 镖 x | 镖 y | | 召回引导完成，镖起飞 |
| LOST | 主人 | x | y | | 镖消失（主人已出局，镖飞回出局位置）|
| SLASH | 座位 | ax | ay | | 开始挥砍起手 |
| KICK | 座位 | ax | ay | | 开始踢起手 |
| SWING | 座位 | 1 砍 / 0 踢 | 命中个数 | | 挥砍 / 踢的判定那一刻（命中个数含挡下的镖）|
| BLOCK | 挥砍者 | 镖的主人 | x | y | 挥砍把飞镖打落（BLOCK=1，默认开）。镖就落在 (x, y)，下一步起是 ground |
| DASH | 座位 | ax | ay | | 接受冲刺、开始前摇（方向单位向量 × 1000）；DASH_PRE 步以后才开始冲刺移动 |
| STOP | 座位 | x | y | | 冲刺移动结束（这一步的位置）|
| HIT | 镖的主人 | 被打中的人 | 镖的状态（1 去程 2 回程 6 召回）| 这一趟第几个 | 飞镖命中（位置看 S t+1 里被打中的人；同一步一镖可能有好几条）|
| CUT | 挥砍者 | 被砍中的人 | | | 挥砍命中 |
| KICKHIT | 踢的人 | 被踢中的人 | | | 踢中（被踢的人下一步开始滑行）|
| FALL | 落坑的人 | 记给谁（-1 = 没人）| x | y | 落坑 |
| DEATH | 出局的人 | 方式（1 镖 2 砍 3 坑）| 凶手（-1 = 没有）| | 出局生效（同一步的所有出局同时生效）|
| WARN | 波号 | | | | 这一波开始预警（写在预警开始的前一步）|
| COLLAPSE | 波号 | | | | 这一波塌掉（写在塌掉的前一步；下一步起是坑）|
| END | 胜者 | | | | 一局结束：1v1 / 四人局 = 最后存活的座位，4v4 = 胜队；-1 = 平局 |

同一步里一个人可能有多条 HIT / CUT / FALL（被几样东西同时打中），但只有一条 DEATH，记的方式和凶手按：挥砍 > 飞镖 > 落坑，同种按凶手座位号小的。

### 3.6 故障行 F（只有裁判写）

`F t 座位 种类 说明`：种类 `timeout`（这一步超时）、`invalid`（这一步输出不合法）、`crash`（崩溃 / 退出）、`lost`（墙上时钟超时或不读输入，被结束）、`killed`（累计超时太多，被结束）、`flood`（输出过量，被结束）、`spawn`（启动失败）。程序结束后角色不再发出任何新动作；已经开始的冲刺照常做完（前摇、移动、收势），已经开始但还没出手的蓄势、起手、召回引导一律取消；之后站在原地。仍会受推、被踢、落坑，已飞出的镖继续飞行。

## 4. 结尾

```text
S 466 | ...                                  终局状态
END 466 0 49f988ec605a160d ko                 总步数 胜者 指纹 结束原因（ko = 只剩一人 / 一队或全灭；time = 打到步数上限）
RESULT 0 1 -1 0 -1 1                          每人一行：座位 名次 出局步 方式 凶手 击杀数
RESULT 1 2 465 1 0 0
```

名次：按出局先后，活到最后的并列第 1；同一步出局的并列（取较好的名次）。4v4 的胜负看 END 的胜者（队伍号）。

## 5. 还原任一时刻

- 第 t 步开始时的状态 = `S t` 行，直接读。两步之间的画面用 `S t` 和 `S t+1` 的位置插值（腾空、滑行、飞镖都是直线段，插值就是准确的）。
- 一件事发生在哪一刻：看 `E t ...`，画在 `S t` 到 `S t+1` 之间。
- 地图 + 种子 + CFG + 每一步的 A 行足够用引擎重算整局（`Game(cfg, 地图, false, 种子)`，逐步 `step`；若 F 行表明程序在该步结束，须在该步 step 前调用对应座位的 retire，取消未出手动作），结果逐位一致，`END` 的指纹可以核对。
